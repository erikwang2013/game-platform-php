## 1. ডিফেন্স-ইন-ডেপথ প্যানোরামা

সিস্টেমটি ৭-লেয়ার ডিফেন্স-ইন-ডেপথ মডেল ব্যবহার করে, বাইরে থেকে ভেতরে স্তরে স্তরে দূষিত রিকোয়েস্ট ফিল্টার করে, নিশ্চিত করে যে কোনো এক স্তর ব্যর্থ হলেও পরবর্তী প্রতিরক্ষা লাইন থাকে।

সম্পূর্ণ মিডলওয়্যার চেইন নিম্নলিখিত ক্রমে কার্যকর হয় (`config/middleware.php` দেখুন):

```
请求 → Cors → SecurityFilter → RateLimit → [路由组中间件: AdminAuth → AdminPermission → OperationLog] → Controller
```

| স্তর | মিডলওয়্যার/মেকানিজম | সুরক্ষা লক্ষ্য |
|----|--------|---------|
| 1 | SecurityFilter | XSS / SQL ইনজেকশন / পাথ ট্রাভার্সাল / কমান্ড ইনজেকশন / CSRF অ্যাটাক ব্লক |
| 2 | Cors | ক্রস-অরিজিন নিরাপত্তা + রেসপন্স সিকিউরিটি হেডার ইনজেকশন |
| 3 | RateLimit | Redis স্লাইডিং উইন্ডো রেট লিমিট, ব্রুট-ফোর্স রোধ |
| 4 | AdminAuth | JWT অথেনটিকেশন + ব্ল্যাকলিস্ট লগআউট |
| 5 | AdminPermission | RBAC method.path গ্রানুলারিটি অথোরাইজেশন |
| 6 | OperationLog | অপারেশন অডিট + সোর্স ট্র্যাকিং |
| 7 | ডেটা এনক্রিপশন | Hashids ID অবফাসকেশন + Encryptable DB এনক্রিপশন + EncryptionService ট্রান্সপোর্ট এনক্রিপশন |

ফ্রন্টএন্ডের তিন স্তরে (Flutter) আলাদা ইনপুট ভ্যালিডেশন রয়েছে, ব্যাকএন্ড কোনো ট্রাস্ট করে না, প্রতিটি স্তর স্বাধীনভাবে রক্ষা করে।

## 2. অ্যাটাক ডিটেকশন ইঞ্জিন

### 2.0 HTTP মেথড সীমা

SecurityFilter সব অ্যাটাক ডিটেকশনের আগে প্রথমে HTTP মেথড ভেরিফাই করে, শুধুমাত্র নিম্নলিখিত স্ট্যান্ডার্ড মেথড অনুমোদিত:

```
GET, POST, PUT, DELETE, OPTIONS, HEAD
```

নন-স্ট্যান্ডার্ড মেথড (যেমন TRACE, CONNECT, PATCH, কাস্টম মেথড ইত্যাদি) সরাসরি **405 Method Not Allowed** ফেরত দেয়, রেসপন্স বডি খালি HTML, পরবর্তী অ্যাটাক ডিটেকশন বা ব্যবসায়িক লজিকে প্রবেশ করে না।

এটি ডিফেন্স-ইন-ডেপথের প্রথম প্রতিরক্ষা লাইন, কার্যকরভাবে রোধ করে:
- TRACE ক্রস-সাইট ট্র্যাকিং অ্যাটাক (XST)
- CONNECT টানেল প্রক্সি অপব্যবহার
- নন-স্ট্যান্ডার্ড WebDAV মেথড প্রোবিং
- অটোমেটেড স্ক্যানারের HTTP মেথড এনুমারেশন

### 2.1 XSS ক্রস-সাইট স্ক্রিপ্টিং

সব রেজেক্স `SecurityFilter::PATTERNS['XSS']` থেকে আসে, কেস-ইনসেনসিটিভ ম্যাচ।

| ডিটেকশন প্যাটার্ন | রেজেক্স | রক্ষা করা অ্যাটাক |
|----------|------|-----------|
| স্ক্রিপ্ট ট্যাগ | `<\s*\/?\s*s\s*c\s*r\s*i\s*p\s*t\b` | `<script>`, `<script >`, `< script>` ইত্যাদি স্পেস ভ্যারিয়েন্ট |
| ইভেন্ট অ্যাট্রিবিউট | `\bon\w+\s*=\s*[\"\']?\s*(?:javascript\|vbscript):` | `onclick="javascript:..."` ইত্যাদি ইনলাইন ইভেন্ট |
| JS সিউডো-প্রোটোকল | `(?:javascript\|vbscript)\s*:\s*(?:[^\s]*\s*)?(?:eval\|alert\|prompt\|confirm\|document\.cookie\|location\s*=)` | `javascript:eval(...)`, `javascript:alert(1)` ইত্যাদি |
| Data URI XSS | `data\s*:\s*text\s*\/\s*html\s*(?:;base64)?\s*,` | `data:text/html,<script>`, `data:text/html;base64,...` ইত্যাদি |
| টেমপ্লেট ইনজেকশন | `\{\{.*?\}\}` | `{{constructor}}`, `{{7*7}}` ইত্যাদি সার্ভার-সাইড/Angular/Vue টেমপ্লেট ইনজেকশন |

### 2.2 SQL ইনজেকশন

| ডিটেকশন প্যাটার্ন | রেজেক্স | রক্ষা করা অ্যাটাক |
|----------|------|-----------|
| UNION জয়েন্ট কোয়েরি | `\bUNION\s+(?:ALL\s+)?SELECT\b` | `UNION SELECT`, `UNION ALL SELECT` ডেটা ডাম্প |
| OR চির-সত্য ইনজেকশন | `(?:[\"\']\s*OR\s+[\"\']?\s*\d+\s*=\s*\d+\|[\"\']\s*OR\s+[\"\']?1[\"\']?\s*=\s*[\"\']?1)` | `' OR 1=1--`, `" OR '1'='1'` |
| টেবিল স্ট্রাকচার ধ্বংস | `\b(?:DROP\|ALTER\|TRUNCATE)\s+(?:TABLE\|DATABASE\|INDEX\|VIEW)\b` | `DROP TABLE users`, `TRUNCATE TABLE logs` |
| স্টোরড প্রসিডিউর কল | `\b(?:xp_cmdshell\|sp_executesql\|sp_addsrvrolemember)\b` | MSSQL এক্সটেন্ডেড স্টোরড প্রসিডিউর কমান্ড এক্সিকিউশন |
| মেটাডেটা প্রোবিং | `\b(?:INFORMATION_SCHEMA\|sys\.(?:tables\|columns\|databases)\|pg_class\|sqlite_master\|mysql\.(?:user\|db))\b` | MySQL/PG/SQLite/MSSQL ডেটাবেস স্ট্রাকচার প্রোবিং |
| কমেন্ট বাইপাস | `(?:[\"\'])\s*(?:--\|#)\s*[\"\']?\s*(?:OR\|AND\|SELECT\|INSERT\|UPDATE\|DELETE\|DROP)` | `'-- OR SELECT`, `'# AND UPDATE` কমেন্ট বাইপাস |

### 2.3 পাথ ট্রাভার্সাল

| ডিটেকশন প্যাটার্ন | রেজেক্স | রক্ষা করা অ্যাটাক |
|----------|------|-----------|
| ডিরেক্টরি ব্যাকট্র্যাকিং | `\.\.[\/\\\\]{2,}` | `../`, `..\`, `....//` মাল্টি-লেভেল ডিরেক্টরি ব্যাকট্র্যাকিং |
| সংবেদনশীল ফাইল প্রোবিং | `\/(?:etc\/(?:passwd\|shadow\|hosts)\|proc\/self\|boot\.ini\|win\.ini\|WEB-INF\|\.env\|\.git\/)` | `/etc/passwd`, `/proc/self/environ`, `.env`, `.git/HEAD` ইত্যাদি |
| নাল-বাইট ট্রানকেশন | `%00` | `../../../etc/passwd%00.jpg` এক্সটেনশন ভ্যালিডেশন বাইপাস |

### 2.4 কমান্ড ইনজেকশন

| ডিটেকশন প্যাটার্ন | রেজেক্স | রক্ষা করা অ্যাটাক |
|----------|------|-----------|
| পাইপ/সেমিকোলন কমান্ড | `[;\|&]\s*(?:ls\|cat\|rm\|wget\|curl\|nc\|bash\|sh\|cmd\|powershell\|python\|perl)\b` | `;cat /etc/passwd`, `\|bash` |
| ব্যাকটিক সাবস্টিটিউশন | `` `[^`]*\b(?:cat\|ls\|id\|whoami\|pwd\|rm\|wget\|curl)\b[^`]*` `` | `` `cat /etc/passwd` `` |
| $() সাবস্টিটিউশন | `\$\(\s*(?:cat\|ls\|id\|whoami\|rm\|wget\|curl)\b` | `$(whoami)`, `$(cat flag)` |
| রিমোট ডাউনলোড পাইপ | `(?:wget\|curl)\s+.*(?:\b-o\b\|\b-O\b\|pipe\|bash\|python).*\bhttps?:\/\/` | `wget URL -O - \| bash`, `curl URL \| python` |

### 2.5 CSRF ক্রস-সাইট রিকোয়েস্ট ফোরজারি

ভেরিফিকেশন লজিক `SecurityFilter::checkCsrf()`-এ বাস্তবায়িত:

```php
// 仅 POST/PUT/DELETE 触发校验
// Origin 头和 Referer 均为空 → 放行（非浏览器客户端）
// Origin 非空 → 解析 Origin 域名与 Host 比对
```

তুলনার নিয়ম:
- Host-এর `www.` প্রিফিক্স বাদ দিয়ে Origin-এর ডোমেইনের সাথে সঠিক তুলনা
- Host যদি Origin-এর প্যারেন্ট ডোমেইন হয় (যেমন `Origin: app.example.com`, `Host: example.com` — `str_contains($originHost, '.' . $hostOnly)` ট্রিগার), ছাড় দেওয়া হয়
- সঠিক ম্যাচও নয়, সাবডোমেইনও নয় → 403 ফেরত, CSRF অ্যাটাক হিসেবে নির্ধারিত

লক্ষ্য করুন: নন-ব্রাউজার ক্লায়েন্ট (যেমন Origin/Referer ছাড়া curl) সরাসরি ছাড় পায়, CSRF সুরক্ষা শুধুমাত্র ব্রাউজার পরিবেশে কার্যকর।

### 2.6 দূষিত ফাইল আপলোড

| ডিটেকশন প্যাটার্ন | রেজেক্স | রক্ষা করা অ্যাটাক |
|----------|------|-----------|
| ডাবল এক্সটেনশন ছদ্মবেশ | `\.(?:php\d?\|phtml\|phar\|cgi\|pl\|py\|jsp\|asp)x?\.(?:png\|jpg\|gif\|pdf)` | `shell.php.png`, `shell.phar.jpg` হোয়াইটলিস্ট বাইপাস |
| PHP এক্সটেনশন | `\.php\s*$/m` | রিকোয়েস্ট প্যারামিটারে সরাসরি `.php` পাথ |

## 3. অ্যাটাক এসকেলেশন ও IP ব্ল্যাকলিস্ট

SecurityFilter-এ বিল্ট-ইন অ্যাটাক এসকেলেশন মেকানিজম আছে, একই IP-এর অব্যাহত স্ক্যান অ্যাটাক রোধ করে।

### এসকেলেশন ফ্লো

```
第 1 次扫描命中 → Redis INCR security_escalate:{ip} = 1, TTL=60s
第 2 次扫描命中 → INCR → 2
...
第 5 次扫描命中 → INCR → 5
    → 触发封禁: SETEX security_ban:{ip} 900 1
    → 清除计数器 DEL security_escalate:{ip}
    → 写入安全日志: [SECURITY] IP banned 15min
```

### ব্লক থাকা অবস্থায় আচরণ

প্রতিটি রিকোয়েস্ট SecurityFilter-এ প্রবেশের সময় প্রথমে `isBanned()` চেক করে:

```php
if (Redis::get("security_ban:{$ip}")) {
    return response('<h1>403 Forbidden</h1>', 403);
}
```

ব্লক করা IP-এর ১৫ মিনিটের মধ্যে সব রিকোয়েস্ট (বৈধ রিকোয়েস্ট সহ) সরাসরি 403 ফেরত পায়, পরবর্তী ব্যবসায়িক লজিক সম্পূর্ণ এড়িয়ে যায়।

### কনফিগ কনস্ট্যান্ট

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| ESCALATE_LIMIT | 5 | ৬০ সেকেন্ড উইন্ডোতে ট্রিগার থ্রেশহোল্ড |
| ESCALATE_WINDOW | 60 | কাউন্টার উইন্ডো (সেকেন্ড) |
| BAN_DURATION | 900 | ব্ল্যাকলিস্ট সময়কাল (সেকেন্ড), অর্থাৎ ১৫ মিনিট |

### নিরাপত্তা লগ

ফাইল অবস্থান: `runtime/logs/security.log`

লগ ফরম্যাট উদাহরণ:
```
2026-05-20 14:32:11 [SECURITY] XSS attack blocked | IP: 192.168.1.100 | Path: /admin/v1/user | Field: body.username | Source: body | Payload: <script>alert(1)</script>
2026-05-20 14:32:15 [SECURITY] IP banned 15min | IP: 192.168.1.100 | Triggers: 5
```

### রিকোয়েস্ট বডি সাইজ সীমা

`Content-Length > 10MB` হলে সরাসরি 413 Payload Too Large ফেরত, DoS বিশাল রিকোয়েস্ট বডি অ্যাটাক রোধ।

### Content-Type ভেরিফিকেশন

POST/PUT রিকোয়েস্টে **অবশ্যই** `Content-Type` `application/json` বা `application/x-www-form-urlencoded` ঘোষণা করতে হবে, না হলে 415 Unsupported Media Type ফেরত। ফাইল আপলোড রিকোয়েস্ট (file ফিল্ডসহ) এই চেক এড়িয়ে যায়।

## 4. রেসপন্স সিকিউরিটি হেডার

সব হেডার `Cors` মিডলওয়্যারে ইনজেক্ট হয়, `$response->withHeaders()` দিয়ে প্রতিটি রেসপন্সে যুক্ত হয়।

| হেডার | মান | কাজ |
|----|-----|------|
| Access-Control-Allow-Origin | `*` | যেকোনো উৎসের ক্রস-অরিজিন অনুমোদন (ইন্টারনেট প্রশাসনিক প্যানেল পরিস্থিতি) |
| Access-Control-Allow-Methods | `GET,POST,PUT,DELETE,OPTIONS` | অনুমোদিত মেথড সেট |
| Access-Control-Allow-Headers | `Authorization,Content-Type` | অনুমোদিত কাস্টম হেডার |
| Access-Control-Max-Age | `86400` | প্রিফ্লাইট রিকোয়েস্ট ক্যাশ ২৪ ঘণ্টা |
| X-Content-Type-Options | `nosniff` | ব্রাউজার MIME স্নিফিং নিষিদ্ধ |
| X-Frame-Options | `DENY` | সব iframe এমবেড নিষিদ্ধ, ক্লিকজ্যাকিং রোধ |
| X-XSS-Protection | `1; mode=block` | ব্রাউজার বিল্ট-ইন XSS ফিল্টার সক্রিয় ও পেজ রেন্ডার ব্লক |
| Referrer-Policy | `strict-origin-when-cross-origin` | একই অরিজিনে সম্পূর্ণ URL, ক্রস-অরিজিনে শুধু ডোমেইন |
| Permissions-Policy | `camera=(), microphone=(), geolocation=()` | পুরো সাইটে ক্যামেরা/মাইক্রোফোন/জিওলোকেশন API নিষিদ্ধ |

OPTIONS প্রিফ্লাইট রিকোয়েস্ট সরাসরি 204 খালি রেসপন্স ফেরত দেয়, পরবর্তী মিডলওয়্যার চেইনে প্রবেশ করে না।

### 4.2 Content-Security-Policy (CSP)

অন্যান্য সিকিউরিটি হেডারের সাথে Cors মিডলওয়্যারে ইনজেক্ট হয়, ডিপ-ডিফেন্স প্রদান করে, ব্রাউজার লোড ও এক্সিকিউট করতে পারা রিসোর্সের উৎস সীমাবদ্ধ করে।

| হেডার | মান | কাজ |
|----|-----|------|
| Content-Security-Policy | `default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'` | স্ক্রিপ্ট/স্টাইল/ইমেজ/কানেকশন/ফ্রেম/ফর্ম ইত্যাদি রিসোর্সের উৎস সীমাবদ্ধ |
| X-Permitted-Cross-Domain-Policies | `none` | Adobe Flash/PDF ইত্যাদি ক্রস-ডোমেইন পলিসি ফাইল লোড নিষিদ্ধ |

CSP পলিসির মূল পয়েন্ট:
- `default-src 'self'`: ডিফল্টে শুধুমাত্র সম-অরিজিন রিসোর্স
- `script-src 'self' 'unsafe-inline' 'unsafe-eval'`: সম-অরিজিন স্ক্রিপ্ট + ইনলাইন স্ক্রিপ্ট (Flutter Web-এর জন্য প্রয়োজন) + eval (Flutter Web ডিবাগের জন্য প্রয়োজন)
- `frame-ancestors 'none'`: যেকোনো পেজে iframe এমবেড নিষিদ্ধ, X-Frame-Options: DENY-এর সাথে ডাবল সুরক্ষা
- `base-uri 'self'`: `<base>` ট্যাগ শুধুমাত্র সম-অরিজিন নির্দেশ করতে পারে
- `form-action 'self'`: ফর্ম শুধুমাত্র সম-অরিজিনে সাবমিট করতে পারে

## 5. রেট লিমিট কৌশল

### অ্যালগরিদম

Redis Sorted Set স্লাইডিং উইন্ডো + Lua অ্যাটমিক স্ক্রিপ্ট, মূল অপারেশন:

```lua
-- 1. 清理窗口外的旧记录
redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, windowStart)
-- 2. 检查当前窗口计数
local count = redis.call('ZCARD', KEYS[1])
-- 3. 超限则返回 {0, count}，未超限则 ZADD 并返回 {1, count+1}
if count >= limit then return {0, count} end
redis.call('ZADD', KEYS[1], now, now . '.' . random)  -- 随机后缀避免同毫秒覆盖
redis.call('EXPIRE', KEYS[1], window + 10)
```

Lua স্ক্রিপ্ট Redis সার্ভারে সিঙ্গেল-থ্রেডে কার্যকর হয়, **প্রাকৃতিকভাবে অ্যাটমিক**, TOCTOU (Time-of-check to Time-of-use) রেস কন্ডিশন দূর করে।

### রেট লিমিট কনফিগ

| রুট | সীমা | উইন্ডো | পরিস্থিতি |
|------|------|------|------|
| ডিফল্ট (সব রুট) | ৬০ বার/মিনিট | 60s | সাধারণ API |
| `/api/v1/auth/login` | ১০ বার/মিনিট | 60s | লগইন (ব্রুট-ফোর্স রোধ) |
| `/api/v1/auth/register` | ৫ বার/মিনিট | 60s | রেজিস্ট্রেশন (বাল্ক রেজিস্ট্রেশন রোধ) |

### রেসপন্স হেডার

রেট লিমিট ট্রিগার হলে HTTP 429 ও JSON body ফেরত:
```json
{"code": 429, "message": "请求过于频繁，请稍后再试", "data": []}
```

সব রেসপন্স (স্বাভাবিক রেসপন্স সহ) নিম্নলিখিত হেডার বহন করে:

| হেডার | বিবরণ |
|----|------|
| X-RateLimit-Limit | বর্তমান উইন্ডোতে সর্বোচ্চ রিকোয়েস্ট সংখ্যা |
| X-RateLimit-Remaining | বর্তমান উইন্ডোতে অবশিষ্ট রিকোয়েস্ট সংখ্যা |
| X-RateLimit-Reset | উইন্ডো রিসেটের Unix টাইমস্ট্যাম্প |
| Retry-After | শুধুমাত্র রেট লিমিটের সময়, অপেক্ষার সেকেন্ড নির্দেশ করে |

### ডিগ্রেডেশন কৌশল

Redis অস্বাভাবিক হলে (সংযোগ টাইমআউট, অনুপলব্ধ ইত্যাদি) **fail-closed**:

```php
try {
    $result = Redis::eval($lua, ...);
} catch (\Throwable $e) {
    // Redis down: 限流不可用即拒绝，避免安全防线失效（登录/支付回调限流为空转）
    return json(['code' => 503, 'message' => '服务暂不可用，请稍后再试', 'data' => []])
        ->withStatus(503)->withHeaders(['Retry-After' => '5']);
}
```

রেট লিমিট লগইন ব্রুট-ফোর্স রোধ ও পেমেন্ট কলব্যাক রিপ্লে রোধের প্রথম নিরাপত্তা লাইন, Redis ব্যর্থ হলে রিকোয়েস্ট প্রত্যাখ্যান (503) করাই সঠিক, ছাড় দেওয়া হয় না।

### 5.4 অ্যাকাউন্ট লক মেকানিজম

লগইন ইন্টারফেস রেট লিমিটের উপর ভিত্তি করে অতিরিক্ত **অ্যাকাউন্ট লক** মেকানিজম যোগ করেছে, নির্দিষ্ট ইউজারের বিরুদ্ধে টার্গেটেড ব্রুট-ফোর্স রোধ করে।

**লক ফ্লো**:

```
登录失败 → Redis INCR account_lockout:{userId} TTL=900s
连续 5 次失败 → Redis SETEX account_locked:{userId} 900 1
            → 返回 429 "账号已被锁定，请15分钟后再试"
            → 清除计数器 DEL account_lockout:{userId}
```

**লক থাকা অবস্থায় আচরণ**:

লক থাকা অবস্থায় সব লগইন রিকোয়েস্ট সরাসরি 429 ফেরত পায়, পাসওয়ার্ড ভেরিফিকেশন হয় না, ব্রুট-ফোর্স চেষ্টা সম্পূর্ণ ব্লক হয়।

**কনফিগ কনস্ট্যান্ট**:

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| MAX_LOGIN_ATTEMPTS | 5 | সর্বোচ্চ টানা ব্যর্থ সংখ্যা |
| LOCKOUT_DURATION | 900 | লক সময়কাল (সেকেন্ড), অর্থাৎ ১৫ মিনিট |

লক্ষ্য করুন: অ্যাকাউন্ট লক `userId` ভিত্তিক, IP নয়, তাই আক্রমণকারী IP পরিবর্তন করে লক বাইপাস করতে পারে না। IP রেট লিমিটের (১০ বার/মিনিট) সাথে মিলে ডাবল সুরক্ষা:
- IP স্তর: ১০ বার/মিনিট রেট লিমিট ডিস্ট্রিবিউটেড ব্রুট-ফোর্স রোধ
- অ্যাকাউন্ট স্তর: ৫ বার ব্যর্থ লক টার্গেটেড ব্রুট-ফোর্স রোধ

## 6. অথেনটিকেশন ও অথোরাইজেশন

### 6.1 JWT অথেনটিকেশন

AdminAuth মিডলওয়্যারে বাস্তবায়িত, অথেনটিকেশন প্রয়োজন এমন রাউট গ্রুপে মাউন্ট করা।

**প্যারামিটার কনফিগ** (`config/plugin/erikwang2013/jwt/jwt`, `.env` থেকে ইনজেক্ট):

| প্যারামিটার | মান | বিবরণ |
|------|-----|------|
| অ্যালগরিদম | HS256 | HMAC-SHA256 সিমেট্রিক সিগনেচার |
| কী | `JWT_SECRET_KEY` | এনভায়রনমেন্ট ভেরিয়েবল ইনজেকশন, অনুপস্থিত বা ডিফল্ট মান থাকলে **স্টার্টআপ প্রত্যাখ্যান** (fail-closed) |
| access_token TTL | 7200s (2h) | `JWT_TTL` |
| refresh_token TTL | 1209600s (14d) | `JWT_REFRESH_TTL` |
| ইস্যুয়ার | `open-admin` | `JWT_ISSUER` |
| অডিয়েন্স | `open-admin` | `JWT_AUDIENCE` |

**Token এক্সট্রাকশন**: `Authorization: Bearer <token>` হেডার থেকে, `Bearer ` প্রিফিক্স স্ট্রিপ করে আসল JWT পাওয়া যায়।

**অথেনটিকেশন ফ্লো**:
1. খালি token → সরাসরি 401 `{"code": 401, "message": "未登录"}`
2. Redis ব্ল্যাকলিস্ট `jwt_blacklist:{md5(token)}` চেক → হিট → 401 `Token已失效，请重新登录`
3. JWT decode → ব্যর্থ (মেয়াদোত্তীর্ণ/সিগনেচার ম্যাচ না) → 401 `Token已过期或无效`
4. সফল → `$request->adminId` ও `$request->adminUsername` ইনজেক্ট

**ব্ল্যাকলিস্ট মেকানিজম**: ইউজার লগআউট করলে `md5(token)` Redis-এ লেখা হয়, TTL JWT-এর অবশিষ্ট মেয়াদে সেট হয়। Redis ব্যর্থ হলে ব্ল্যাকলিস্ট চেক এড়িয়ে যায় (fail-open), এই সময়ে লগআউট করা Token স্বল্প সময় ব্যবহারযোগ্য, কিন্তু JWT-এর স্বল্প মেয়াদ (2h) বটম-লাইন সুরক্ষা দেয়।

**Token রিফ্রেশ**: `POST /api/v1/auth/refresh` আসল refresh token ভেরিফাই করে (`token_type=refresh` ও মেয়াদোত্তীর্ণ নয়/ব্ল্যাকলিস্টে নয়) তারপরই ঘোরায় ও ইস্যু করে, এবং `sub` অবশ্যই বৈধ ইউজার ID হতে হবে — **sub=null সহ refresh token আর ইস্যু হয় না**, রিফ্রেশ ব্যর্থ হলে সরাসরি 401।

### 6.2 কনকারেন্ট সেশন সীমা

Token লিকেজের পর মাল্টি-ডিভাইস অপব্যবহার রোধ করতে, সিস্টেম একই ইউজারের একসাথে ধারণ করা বৈধ Token সংখ্যা সীমাবদ্ধ করে।

**সীমা লজিক**:

```
登录成功 → 签发新 Token
         → 查询当前用户有效 Token 数量: Redis SCARD user_tokens:{userId}
         → 若数量 >= 3（MAX_CONCURRENT_SESSIONS）:
            → 按创建时间升序排列，移除最旧的 Token:
              Redis SREM user_tokens:{userId} <oldest_token_id>
              Redis SETEX jwt_blacklist:{md5(oldest_token)} TTL remaining
         → 将新 Token 加入集合: Redis SADD user_tokens:{userId} <new_token_id>
            Redis SET user_token:{token_id} {userId} EX {TTL}
```

**কনফিগ কনস্ট্যান্ট**:

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| MAX_CONCURRENT_SESSIONS | 3 | একই ইউজারের সর্বোচ্চ কনকারেন্ট Token সংখ্যা |

**লগ আউট হওয়ার পরিস্থিতি**: ইউজার ৪র্থ ডিভাইসে লগইন করলে, ১ম ডিভাইসের Token বাধ্যতামূলকভাবে ব্ল্যাকলিস্টে যায়, পরবর্তী রিকোয়েস্টে 401 "Token已失效，请重新登录" ফেরত।

লগআউটের সময় বর্তমান Token সেট থেকে সরানো হয়। Token প্রাকৃতিকভাবে মেয়াদোত্তীর্ণ হলে Redis key স্বয়ংক্রিয়ভাবে অকার্যকর হয়, সেটের সদস্যও কমে যায়।

### 6.3 RBAC পারমিশন মডেল

AdminPermission মিডলওয়্যারে বাস্তবায়িত।

**ডেটা মডেল**: User -> Role -> Permission তিন-স্তরের সম্পর্ক

- `game_admin_user` (ইউজার টেবিল)
- `game_admin_user_role` (ইউজার-রোল সম্পর্ক টেবিল)
- `game_admin_role` (রোল টেবিল)
- `game_admin_role_permission` (রোল-পারমিশন সম্পর্ক টেবিল)
- `game_admin_permission` (পারমিশন টেবিল)

**পারমিশন টাইপ**:
| type | অর্থ | উদাহরণ |
|------|------|------|
| 1 | মেনু পারমিশন | বাম নেভিগেশনের দৃশ্যমানতা নিয়ন্ত্রণ |
| 2 | বাটন পারমিশন | পেজের ভেতরের অপারেশন বাটন নিয়ন্ত্রণ (তৈরি/সম্পাদনা/ডিলিট) |
| 3 | API পারমিশন | ব্যাকএন্ড ইন্টারফেস কল নিয়ন্ত্রণ |

API পারমিশন আইডেন্টিফায়ার ফরম্যাট: `{method}.{path}`

উদাহরণ:
- `post.admin/user` — ইউজার তৈরি
- `put.admin/user` — ইউজার সম্পাদনা
- `delete.admin/user` — ইউজার ডিলিট
- `get.admin/user` — ইউজার তালিকা দেখা

**অথোরাইজেশন ফ্লো**:
1. `$request->adminId` খালি (লগইন নেই) → সরাসরি 401 `{"code": 401, "message": "未登录"}`, ছাড় নেই
2. ইউজার → রোল (স্ট্যাটাস `status=0` ডিসেবল রোল বাদ) → পারমিশন তালিকা
3. সুপার অ্যাডমিন (`slug = '*'`) → সরাসরি ছাড়
4. `strtolower(method) . '.' . trim(path, '/')` তৈরি → পারমিশন তালিকার সাথে তুলনা
5. ম্যাচ ব্যর্থ → 403 `{"code": 403, "message": "无权限访问"}`

**দ্বিতীয় নিশ্চিতকরণ**: BaseController `confirmPassword()` মেথড প্রদান করে, সংবেদনশীল অপারেশনে (ইউজার ডিলিট, ডেটা এক্সপোর্ট ইত্যাদি) Controller লেয়ারে বর্তমান পাসওয়ার্ড ইনপুট বাধ্যতামূলক, সেশন হাইজ্যাকের পর অননুমোদিত অপারেশন রোধ।

### 6.4 পেমেন্ট কলব্যাক ভেরিফিকেশন (fail-closed)

`POST /api/v1/payment/callback` (Stripe/PayPal টপ-আপ কলব্যাক) ভেরিফিকেশন **fail-closed**, যেকোনো কনফিগ অনুপস্থিত বা ভেরিফিকেশন অস্বাভাবিক হলে কলব্যাক প্রত্যাখ্যান:

| পরিস্থিতি | আচরণ |
|------|------|
| Stripe-এ `STRIPE_WEBHOOK_SECRET` কনফিগ নেই | প্রত্যাখ্যান (403), সিগনেচারবিহীন কলব্যাক আর গ্রহণ হয় না |
| Stripe সিগনেচার অনুপস্থিত / ভেরিফিকেশন ব্যর্থ | প্রত্যাখ্যান (403) |
| Stripe টাইমস্ট্যাম্প `t=` অনুপস্থিত বা সার্ভার সময়ের পার্থক্য **> ±৫ মিনিট** | প্রত্যাখ্যান (403), রিপ্লে রোধ |
| PayPal-এ `PAYPAL_WEBHOOK_ID` কনফিগ নেই | প্রত্যাখ্যান (403) |
| PayPal রিভার্স-চেক অস্বাভাবিক / SUCCESS নয় | প্রত্যাখ্যান (403) |
| ঐচ্ছিক `CALLBACK_TRUSTED_IPS` কনফিগের পর সোর্স IP হোয়াইটলিস্টে নেই | প্রত্যাখ্যান (403) |
| কলব্যাক provider অর্ডারের পেমেন্ট মেথডের সাথে মেলে না / পেমেন্ট মেথড নেই | প্রত্যাখ্যান (403) |

কলব্যাক জমা (স্ট্যাটাস আপডেট + ব্যালেন্স + লেনদেন রেকর্ড) একই ডেটাবেস ট্রানজেকশনে সম্পন্ন, যেকোনো ধাপ ব্যর্থ হলে পুরোটা রোলব্যাক, আধা-জমা রোধ।

## 7. অডিট লগ

### 7.1 অপারেশন লগ

OperationLog মিডলওয়্যার POST / PUT / DELETE রিকোয়েস্টে স্বয়ংক্রিয়ভাবে অপারেশন লগ রেকর্ড করে। GET রিকোয়েস্ট রেকর্ড হয় না।

**রেকর্ড করা ফিল্ড**:

| ফিল্ড | সোর্স | বিবরণ |
|------|------|------|
| id | SnowflakeService::generate() | গ্লোবাল ইউনিক ID |
| user_id | `$request->adminId` | অপারেটর ID, লগইন না থাকলে 0 |
| action | `$request->method()` | method-এর সমান |
| method | `$request->method()` | POST / PUT / DELETE |
| path | `$request->path()` | রিকোয়েস্ট পাথ |
| ip | `$request->getRealIp()` | ক্লায়েন্ট প্রকৃত IP |
| source | detectSource() | ক্লায়েন্ট সোর্স প্ল্যাটফর্ম |
| input | রিকোয়েস্ট body (মাস্ক করা JSON) | অপারেশনে জমা দেওয়া ডেটা |
| created_at | `date('Y-m-d H:i:s')` | অপারেশন সময় |

**সংবেদনশীল ফিল্ড ফিল্টার**: রিকোয়েস্ট বডি রিকার্সিভভাবে ট্রাভার্স করা হয়, নিম্নলিখিত ফিল্ডের মান `***` দিয়ে প্রতিস্থাপিত হয়:

`password`, `old_password`, `new_password`, `new_password_confirmation`, `token`, `secret`, `access_token`, `refresh_token`

**সোর্স ডিটেকশন** (`detectSource()`): অগ্রাধিকার অনুযায়ী:

1. প্রথমে `X-Client-Platform` কাস্টম হেডার পড়া হয় (নেটিভ ক্লায়েন্ট স্পষ্টভাবে ঘোষণা করে)
2. না হলে User-Agent স্ট্রিং থেকে অনুমান (`detectSource()` মেথড ডিটেকশন ক্রম):

| প্ল্যাটফর্ম | UA কীওয়ার্ড |
|------|----------|
| iPadOS | `iPad` |
| macOS | `Macintosh`, `Mac OS` |
| Windows | `Windows` |
| Linux | `Linux` |
| iOS | `iPhone`, `iOS`, `CFNetwork` |
| Android | `Android` |
| HarmonyOS | `HarmonyOS`, `OpenHarmony` |
| Web | ফলব্যাক ডিফল্ট মান |

**ফল্ট টলারেন্স**: লগ লেখার অস্বাভাবিকতা ব্যবসায়িক রিকোয়েস্ট ব্লক করে না (`catch (\Throwable)` নীরবে গ্রাস)।

### 7.2 নিরাপত্তা লগ

**ফাইল অবস্থান**: `runtime/logs/security.log`

**রেকর্ড করা বিষয়বস্তু**:
- অ্যাটাক ব্লক লগ: অ্যাটাক ক্যাটাগরি, IP, পাথ, ফিল্ড, সোর্স, payload খণ্ড (প্রথম ২০০ অক্ষর)
- IP ব্লক নোটিফিকেশন: ব্লক করা IP, ট্রিগার সংখ্যা

লগ পারমিশন `FILE_APPEND | LOCK_EX`, কনকারেন্ট নিরাপদ লেখা নিশ্চিত।

## 8. ডেটা সুরক্ষা

সিস্টেম তিন-স্তরের ডেটা সুরক্ষা কৌশল ব্যবহার করে, ডেটা প্রবাহের তিনটি পর্যায়ের সাথে মিলে।

### 8.1 ট্রান্সপোর্ট লেয়ার — EncryptionService

`EncryptionService` `erikwang2013/encryption` প্যাকেজ ব্যবহার করে, API রিকোয়েস্ট/রেসপন্সের সংবেদনশীল ফিল্ড এনক্রিপশন/ডিক্রিপশন করে।

**প্রযুক্তিগত বিবরণ**:
- অ্যালগরিদম: `aes-256-cbc-hmac` (নিজস্ব HMAC সিগনেচার টেম্পার রোধ)
- কী: `ENCRYPTION_KEY` এনভায়রনমেন্ট ভেরিয়েবল, স্বয়ংক্রিয়ভাবে ৩২ বাইটে অ্যালাইন হয়
- ব্যবহৃত: ক্লায়েন্ট ও API-এর মধ্যে ফোন নম্বর, আইডি কার্ড নম্বর ইত্যাদি ফিল্ড ট্রান্সমিট

**মাস্কিং টুল মেথড**:
- `maskPhone('13812341234')` → `138****1234`
- `maskEmail('abc@example.com')` → `a***@example.com` (ইউজারনেম ২ অক্ষরের বেশি হলে) বা `a**@example.com`

### 8.2 স্টোরেজ লেয়ার — Encryptable Cast

`AdminUser` মডেল `Erikwang2013\Encryptable\Encryptable` Eloquent cast ব্যবহার করে, সংশ্লিষ্ট ফিল্ড:

- `email` → Encryptable cast, স্বয়ংক্রিয় এনক্রিপশন/ডিক্রিপশন
- `phone` → Encryptable cast, স্বয়ংক্রিয় এনক্রিপশন/ডিক্রিপশন
- `id_card` → Encryptable cast, স্বয়ংক্রিয় এনক্রিপশন/ডিক্রিপশন

ডেটাবেসে লেখার সময় স্বয়ংক্রিয়ভাবে সাইফারটেক্সটে এনক্রিপ্ট হয়, পড়ার সময় স্বয়ংক্রিয়ভাবে প্লেইনটেক্সটে ডিক্রিপ্ট হয়। ডেটাবেস স্টোরেজ কলাম টাইপ `VARCHAR(500)`, সাইফারটেক্সট base64 আকারে সংরক্ষিত।

**কী সিস্টেম**: ট্রান্সপোর্ট লেয়ার এনক্রিপশন (`ENCRYPTION_KEY`) থেকে আলাদা `ENCRYPTABLE_KEY` ব্যবহার করে, একটি কী লিক হলে অন্য স্তর অকার্যকর হয় না।

কী রোটেশন: `ENCRYPTION_PREVIOUS_KEYS` এনভায়রনমেন্ট ভেরিয়েবল ঐতিহাসিক কী তালিকা সাপোর্ট করে (কমা-বিভক্ত), পুরনো ডেটা পড়ার সময় ঐতিহাসিক কী দিয়ে ডিক্রিপ্ট চেষ্টা হয়, লেখার সময় বর্তমান কী দিয়ে পুনরায় এনক্রিপ্ট হয়।

### 8.3 ডিসপ্লে লেয়ার — ID অবফাসকেশন ও মাস্কিং

**Hashids ID অবফাসকেশন**: `HashidsService` `erikwang2013/hashids` প্যাকেজ ব্যবহার করে।

- বাহ্যিক API-তে ফেরত দেওয়া ডেটাবেস BIGINT ID hash স্ট্রিংয়ে এনকোড হয় (যেমন `xK3mN9qR2pL7wV8b`)
- ক্লায়েন্ট রিকোয়েস্টে hash স্ট্রিং পাঠায়, ব্যাকএন্ড স্বয়ংক্রিয়ভাবে আসল ID ডিকোড করে
- সল্ট `HASHIDS_SALT` এনভায়রনমেন্ট ভেরিয়েবল ইনজেকশন, সল্ট ভিন্ন হলে এনকোড/ডিকোড ফলাফল সম্পূর্ণ ভিন্ন
- hash ন্যূনতম দৈর্ঘ্য ১৬ অক্ষর, ৬২ অক্ষরের আলফানিউমেরিক ক্যারেক্টার সেট
- BaseController `encodeId()`, `decodeId()`, `encodeIds()` সুবিধাজনক মেথড প্রদান করে

**এক্সপোর্ট মাস্কিং**: Excel/PDF এক্সপোর্টের সময় (ExportController), সংবেদনশীল ফিল্ড ইউনিফর্মলি মাস্ক:
- ফোন নম্বর: `138****1234`
- ইমেইল: `a***@example.com`
- আইডি কার্ড: সম্পূর্ণ ঢেকে `********`

## 10. security.txt (RFC 9116)

সিস্টেম `/.well-known/security.txt`-এ RFC 9116 স্ট্যান্ডার্ড অনুযায়ী নিরাপত্তা যোগাযোগ তথ্য এন্ডপয়েন্ট প্রদান করে, নিরাপত্তা গবেষকরা দুর্বলতা পেলে দ্রুত রিপোর্ট চ্যানেল খুঁজে পায়।

**অ্যাক্সেস পদ্ধতি**:

```
GET /.well-known/security.txt
```

**রেসপন্স বিষয়বস্তু**:

```text
Contact: mailto:security@erik.xyz
Expires: 2027-05-20T00:00:00.000Z
Preferred-Languages: zh, en
Canonical: https://erik.xyz/.well-known/security.txt
Policy: https://erik.xyz/security-policy
```

**ফিল্ড বিবরণ**:

| ফিল্ড | বিবরণ |
|------|------|
| Contact | নিরাপত্তা দুর্বলতা রিপোর্টের যোগাযোগ মাধ্যম |
| Expires | ফাইলের মেয়াদোত্তীর্ণ সময়, নিয়মিত আপডেট প্রয়োজন |
| Preferred-Languages | পছন্দের যোগাযোগ ভাষা |
| Canonical | এই ফাইলের ক্যানোনিকাল URL |
| Policy | নিরাপত্তা নীতি/দুর্বলতা প্রকাশ নীতির লিংক |

এই এন্ডপয়েন্ট রেট লিমিট, অথেনটিকেশন ইত্যাদি মিডলওয়্যারের সীমাবদ্ধতার বাইরে, যে কেউ সরাসরি অ্যাক্সেস করতে পারে।

## 11. Nginx নিরাপত্তা কনফিগারেশন

প্রজেক্ট প্রোডাকশন পরিবেশে Nginx রিভার্স প্রক্সির নিরাপত্তা হার্ডেনিং রেফারেন্স কনফিগ হিসেবে `docs/nginx-security.conf` প্রদান করে।

**অন্তর্ভুক্ত নিরাপত্তা ব্যবস্থা**:

| কনফিগ আইটেম | কাজ |
|--------|------|
| `server_tokens off` | Nginx ভার্সন নম্বর লুকানো |
| `client_max_body_size 10m` | রিকোয়েস্ট বডি সাইজ সীমা, SecurityFilter-এর সাথে সমন্বয় |
| `limit_req_zone` | Nginx স্তরে রিকোয়েস্ট ফ্রিকোয়েন্সি সীমা |
| `limit_conn_zone` | কনকারেন্ট সংযোগ সংখ্যা সীমা |
| `add_header` নিরাপত্তা হেডার | Nginx স্তরে X-XSS-Protection ইত্যাদি নিরাপত্তা হেডার যুক্ত |
| `if ($request_method)` | Nginx স্তরে নন-স্ট্যান্ডার্ড HTTP মেথড প্রত্যাখ্যান |
| SSL/TLS কনফিগ | আধুনিক TLS 1.2/1.3 কনফিগ, দুর্বল সাইফার স্যুট নিষিদ্ধ |
| ব্যাকএন্ড হেডার লুকানো | `proxy_hide_header` দিয়ে webman ভার্সন ইত্যাদি সংবেদনশীল হেডার সরানো |

**ব্যবহার পদ্ধতি**: `docs/nginx-security.conf`-এর কনফিগ আপনার Nginx server ব্লকে মার্জ করুন, প্রকৃত ডোমেইন ও সার্টিফিকেট পাথ অনুযায়ী সামঞ্জস্য করুন।

| কমান্ড ইনজেকশন | `;ls`, `` `whoami` ``, `$(cat ...)` | SecurityFilter (৪ ধরনের প্যাটার্ন) |

### 12.2 জানা সীমাবদ্ধতা

| সীমাবদ্ধতা | প্রভাব এলাকা | প্রশমন ব্যবস্থা |
|------|---------|---------|
| CSRF সুরক্ষা শুধুমাত্র ব্রাউজারে কার্যকর | নন-ব্রাউজার ক্লায়েন্ট (curl, Postman, মোবাইল App) Origin/Referer চেক বাইপাস করতে পারে | নন-ব্রাউজার ক্লায়েন্ট প্রাকৃতিকভাবে CSRF অ্যাটাকে অরক্ষিত; Cookie-র বদলে JWT অথেনটিকেশনের উপর নির্ভর |
| Redis অনুপলব্ধ হলে রেট লিমিট fail-closed (503), ব্ল্যাকলিস্ট চেক fail-open | রেট লিমিটের সময় কিছু রিকোয়েস্ট প্রত্যাখ্যান; লগআউট করা Token স্বল্প সময় ব্যবহারযোগ্য | Redis উপলব্ধতা মনিটরিং অ্যালার্ট; JWT স্বল্প মেয়াদ ফলব্যাক হিসেবে |
| আলাদা WAF ইঞ্জিন নেই | SecurityFilter `@preg_match` রেজেক্স ম্যাচ, ডেডিকেটেড WAF রুল ইঞ্জিন নয় | প্রোডাকশনে Nginx ModSecurity বা Cloudflare WAF প্রিফিক্স করার পরামর্শ |
| JWT স্টেটলেস, সক্রিয়ভাবে অকার্যকর করা যায় না | Token মেয়াদোত্তীর্ণ হওয়ার আগে সার্ভার থেকে সক্রিয়ভাবে রিভোক করা যায় না (ব্ল্যাকলিস্ট ছাড়া) | ব্ল্যাকলিস্ট + স্বল্প 2h TTL ঝুঁকি উইন্ডো কমায় |
| IP ব্ল্যাকলিস্ট শুধুমাত্র মেমরিতে | Redis রিস্টার্টে ব্ল্যাকলিস্ট হারিয়ে যায় | Ban সময়কাল মাত্র ১৫ মিনিট, প্রভাব সীমিত |
| অ্যাডমিন এন্ডপয়েন্টে বিশেষ রেট লিমিট নেই | প্রশাসনিক ইন্টারফেস সাধারণ ইন্টারফেসের সাথে 60/মিনিট ডিফল্ট সীমা ভাগ করে | অ্যাডমিন অপারেশন ফ্রিকোয়েন্সি প্রাকৃতিকভাবে কম, আপাতত আলাদা করার দরকার নেই |
| `@preg_match` এরর দমন | ম্যালফর্মড রেজেক্স ইনপুটে নীরবে অকার্যকর | `preg_last_error()` দিয়ে মনিটরিং যোগ করা যায়, বর্তমানে বাস্তবায়িত নয় |
