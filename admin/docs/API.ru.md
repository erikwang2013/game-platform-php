## 1. Обзор

Открытая административная панель (open-admin) построена на webman v2 и предоставляет RESTful JSON API. Все интерфейсы панели требуют JWT-аутентификации и RBAC-проверки прав, публичные интерфейсы маршрутизируются через заголовок версии API к версионированным контроллерам.

- **Базовый URL**: `http://localhost:8787`
- **Версия API**: задается заголовком `API-Version: v1` (при отсутствии по умолчанию v1)

> **Обзор эндпоинтов**: аутентификация(5) | дашборд(1) | пользователи(7) | роли(4) | права(4) | настройки(4) | журнал(1) | личный кабинет(3) | импорт/экспорт(3) | загрузка(1) | эксплуатация(4: health/metrics/docs/security.txt) | всего 37 эндпоинтов
- **Аутентификация**: `Authorization: Bearer <token>` (JWT)
- **Формат ответа**: `{ "code": 0, "message": "success", "data": {...} }`
- **Документация**: `GET /api/docs` возвращает спецификацию OpenAPI 3.0 JSON

### Требования к запросам

- Разрешены только методы `GET` / `POST` / `PUT` / `DELETE` / `OPTIONS` / `HEAD`; использование других HTTP-методов (например, TRACE, CONNECT, PATCH) вернет 405
- Все запросы `POST` / `PUT` должны иметь `Content-Type: application/json` (кроме загрузки файлов), иначе возвращается 415
- Размер тела запроса не должен превышать 10MB, иначе возвращается 413
- Фильтр безопасности сканирует все входные данные запросов на XSS, SQL-инъекции, обход пути, инъекции команд; при срабатывании возвращается 403
- 5 неудачных входов подряд вызывают блокировку аккаунта (15 минут), запросы входа в этот период возвращают 429
- Один пользователь может одновременно владеть не более чем 3 действительными токенами, при превышении самый старый автоматически попадает в черный список

## 2. Коды ошибок

| code | Значение | Сценарий срабатывания |
|------|------|---------|
| 0 | Успех | |
| 400 | Ошибка параметров запроса | Некорректный формат запроса |
| 401 | Не авторизован | Токен отсутствует / истек / в черном списке |
| 403 | Нет прав / блокировка безопасности | Недостаточно прав RBAC / срабатывание SecurityFilter |
| 404 | Ресурс не найден | Цель запроса/обновления/удаления не существует |
| 405 | Метод не разрешен | Разрешены только GET/POST/PUT/DELETE/OPTIONS/HEAD, нестандартные методы отклоняются |
| 413 | Слишком большое тело запроса | Content-Length превышает 10MB |
| 415 | Неподдерживаемый тип медиа | Content-Type запроса POST/PUT не JSON и не загрузка файла |
| 422 | Ошибка проверки параметров | Отсутствуют обязательные поля, некорректный формат, не пройдена бизнес-проверка |
| 429 | Слишком частые запросы | Срабатывание RateLimit / блокировка аккаунта (5 неудачных входов — блокировка 15 минут) |
| 500 | Внутренняя ошибка сервера | |

## 3. Публичные эндпоинты

Все публичные эндпоинты смонтированы в группе `/api`, промежуточное ПО `ApiVersion` распределяет их по версионированным контроллерам в соответствии с заголовком `API-Version` (например, `app\api\v1\controller\AuthController`).

### 3.1 Health check

```
GET /health
```

- **Аутентификация**: не требуется
- **Ограничение частоты**: нет

**Пример ответа**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "app": "open-admin",
    "version": "1.1",
    "php": "8.3.0",
    "database": "ok",
    "redis": "ok",
    "elasticsearch": "ok",
    "timestamp": 1716249600
  }
}
```

Значения `database`, `redis`, `elasticsearch`: `"ok"` | `"unavailable"`. `elasticsearch` возвращает `"unavailable"` при недоступности ES, если состояние кластера не green/yellow — возвращается фактическое значение status (например, `"red"`).

### 3.2 Документация API

```
GET /api/docs
```

- **Аутентификация**: не требуется
- **Ограничение частоты**: глобальное по умолчанию (60 раз/мин)
- **Ответ**: спецификация OpenAPI 3.0.3 JSON со всеми определениями эндпоинтов, параметров и Schema

### 3.3 Генерация клик-капчи

```
POST /api/captcha/generate
```

- **Аутентификация**: не требуется
- **Заголовок**: `API-Version: v1` (обязателен)
- **Ограничение частоты**: глобальное по умолчанию (60 раз/мин)

**Тело запроса**:
```json
{
  "difficulty": "medium"
}
```

| Поле | Тип | Обязательно | Описание |
|------|------|------|------|
| difficulty | string | нет | `easy` / `medium` / `hard`, по умолчанию `medium` |

**Пример ответа**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "key": "abc123def456",
    "image": "iVBORw0KGgoAAAANSUhEUgAA...",
    "extra": {
      "targets": [
        { "order": 1, "text": "请点击 A" },
        { "order": 2, "text": "请点击 B" }
      ]
    }
  }
}
```

| Поле | Тип | Описание |
|------|------|------|
| key | string | Идентификатор капчи, передается обратно при проверке |
| image | string | Изображение PNG в base64 |
| extra.targets[].order | int | Порядок кликов |
| extra.targets[].text | string | Подсказка о цели клика |

### 3.4 Проверка клик-капчи

```
POST /api/captcha/verify
```

- **Аутентификация**: не требуется
- **Заголовок**: `API-Version: v1` (обязателен)
- **Ограничение частоты**: глобальное по умолчанию (60 раз/мин)

**Тело запроса**:
```json
{
  "key": "abc123def456",
  "clicks": [
    { "x": 120, "y": 85 },
    { "x": 310, "y": 42 }
  ]
}
```

| Поле | Тип | Обязательно | Описание |
|------|------|------|------|
| key | string | да | Ключ капчи, возвращенный generate |
| clicks | array{object} | да | Массив координат кликов, каждый элемент содержит `x` (int) и `y` (int) |

**Пример ответа**:
```json
{
  "code": 0,
  "message": "验证通过",
  "data": { "valid": true }
}
```

При неудачной проверке `code` равен 422, `message` — `"验证失败，请重试"`, `data.valid` — `false`.

### 3.5 Вход

```
POST /api/auth/login
```

- **Аутентификация**: не требуется
- **Заголовок**: `API-Version: v1` (обязателен)
- **Ограничение частоты**: 10 раз/мин (по IP + пути)

**Тело запроса**:
```json
{
  "username": "admin",
  "password": "123456",
  "captcha_key": "abc123def456",
  "clicks": [
    { "x": 120, "y": 85 },
    { "x": 310, "y": 42 }
  ]
}
```

| Поле | Тип | Обязательно | Правило проверки | Описание |
|------|------|------|---------|------|
| username | string | да | min:3, max:50 | Имя пользователя |
| password | string | да | min:6, max:32 | Пароль |
| captcha_key | string | да | | Ключ капчи |
| clicks | array{object} | да | min:2 | Массив координат кликов |

**Пример ответа**:
```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 7200,
    "user": {
      "id": "a1b2c3d4",
      "username": "admin",
      "real_name": "管理员"
    }
  }
}
```

| Поле | Тип | Описание |
|------|------|------|
| access_token | string | JWT-токен доступа |
| refresh_token | string | JWT-токен обновления |
| expires_in | int | Срок действия токена доступа (секунды), по умолчанию 7200 |
| user.id | string | ID пользователя в hashid |
| user.username | string | Имя пользователя |
| user.real_name | string | Реальное имя |

**Возможные ошибки**:
- 422: ошибка проверки параметров (отсутствуют обязательные поля, некорректный формат)
- 422: неверная капча, попробуйте еще раз
- 401: неверное имя пользователя или пароль
- 403: аккаунт отключен
- 429: аккаунт заблокирован, попробуйте через 15 минут (срабатывает после 5 неудачных входов подряд)

- **Заголовок**: `API-Version: v1` (обязателен)
- **Ограничение частоты**: 5 раз/мин (по IP + пути)

**Тело запроса**:
```json
{
  "username": "newuser",
  "password": "123456",
```

| Поле | Тип | Обязательно | Правило проверки | Описание |

| password | string | да | min:6, max:32 | Пароль (хранится в виде bcrypt-хэша) |
| real_name | string | да | max:50 | Реальное имя |
| captcha_key | string | да | | Ключ капчи |
| clicks | array{object} | да | min:2 | Массив координат кликов |

**Пример ответа**:
```json
{
  "code": 0,
  "message": "注册成功",

      "id": "e5f6g7h8",

```

После успешной регистрации сразу возвращаются JWT-токены, статус пользователя по умолчанию — включен (status=1).

### 3.7 Обновление токена

```
POST /api/auth/refresh
```

- **Аутентификация**: не требуется
- **Заголовок**: `API-Version: v1` (обязателен)
- **Ограничение частоты**: глобальное по умолчанию (60 раз/мин)

**Тело запроса**:
```json
{
  "refresh_token": "eyJhbGciOiJIUzI1NiIs..."
}
```

| Поле | Тип | Обязательно | Описание |
|------|------|------|------|
| refresh_token | string | да | refresh_token, полученный при входе/регистрации |

**Пример ответа**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 7200
  }
}
```

При успешном обновлении возвращаются новые access_token и refresh_token, старые автоматически теряют силу. При обновлении также обновляются время последнего входа и IP пользователя.

**Возможные ошибки**:
- 422: отсутствует токен обновления
- 401: токен обновления недействителен или истек

### 3.8 Метрики Prometheus

- **Аутентификация**: не требуется

## 5. Управление пользователями

Все `id`, возвращаемые интерфейсами управления пользователями, — строки в hashid. Поле пароля исключено из ответов. Телефон и email в списковых интерфейсах деидентифицируются, в интерфейсах деталей возвращаются в открытом виде (зашифрованные поля БД автоматически дешифруются trait'ом Encryptable).

### 5.1 Список пользователей

```
GET /admin/user
```

- **Аутентификация**: JWT + RBAC

**Параметры запроса**:

| Параметр | Тип | Обязательно | По умолчанию | Описание |
|------|------|------|------|------|

| limit | int | нет | 15 | Записей на странице |
| keyword | string | нет | | Поисковый ключ, сопоставляется с именем пользователя и реальным именем |
| status | int | нет | | Фильтр по статусу, 0=отключен, 1=включен |

**Пример ответа**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [
      {
        "id": "a1b2c3d4",
        "username": "admin",
        "real_name": "管理员",

        "email": "a***@example.com",

        "last_login_at": "2026-05-21 10:30:00",

```

| Поле | Тип | Описание |
|------|------|------|

| username | string | Имя пользователя |
| real_name | string | Реальное имя |

В интерфейсе деталей `phone` и `email` возвращаются в открытом виде (в БД хранятся зашифрованными, cast Encryptable дешифрует автоматически), без деидентификации. `password` и `id_card` никогда не включаются в ответ.

- 404: пользователь не существует

- 422: длина нового пароля 6-32 символа

### 10.3 Выход

```
POST /admin/profile/logout
```

- **Аутентификация**: JWT

**Тело запроса**: нет (нет requestBody, токен читается из заголовка Authorization)

**Пример ответа**:
```json
{
  "code": 0,
  "message": "已登出",
  "data": []
}
```

Логика выхода: декодировать JWT, получить оставшийся срок действия (exp - now), записать md5-хэш токена в черный список Redis `jwt_blacklist:{md5}` с TTL = оставшийся срок. Токены из черного списка перехватываются в промежуточном ПО `AdminAuth` и возвращают 401.

При отсутствии токена возвращается 401. Если токен истек/недействителен (исключение при декодировании), выход все равно считается успешным.

## 16. Процесс аутентификации

Полная последовательность аутентификации:

```
1. Клиент запрашивает POST /api/captcha/generate
   (заголовок: API-Version: v1)
    ↓
   Сервер возвращает: key + изображение base64 + подсказки целей кликов
   
2. Пользователь кликает по целям на изображении, клиент собирает координаты кликов
   
3. Клиент запрашивает POST /api/auth/login
   (заголовки: API-Version: v1, Content-Type: application/json)
   Тело запроса: { username, password, captcha_key, clicks: [{x,y}, ...] }
    ↓
   Сервер:
   a. Проверка параметров → 422
   b. Проверка капчи → 422
   c. Проверка учетных данных → 401
   d. Проверка статуса аккаунта → 403
   e. Выпуск JWT (access + refresh) → 200
   f. Обновление last_login_at / last_login_ip
    ↓
   Клиент сохраняет: access_token, refresh_token, expires_in

4. Последующие запросы несут JWT
   Заголовок: Authorization: Bearer <access_token>
    ↓
   Промежуточное ПО AdminAuth:
   a. Извлечение Bearer-токена
   b. Проверка черного списка (Redis jwt_blacklist:{md5}) → 401
   c. Декодирование JWT, проверка срока → 401
   d. Установка $request->adminId = поле sub
    ↓
   Промежуточное ПО AdminPermission:
   a. Не авторизован (adminId пуст) → 401
   b. Определение идентификатора права для маршрута ресурса
   c. Запрос ролей пользователя → прав ролей, сопоставление
   d. Нет прав → 403
    ↓
   Контроллер обрабатывает запрос
    ↓
   Ответ + заголовки X-RateLimit-*

5. Обновление перед истечением Access Token
   Клиент запрашивает POST /api/auth/refresh
   Тело запроса: { refresh_token: "..." }
    ↓
   Сервер декодирует refresh_token → выпускает новые access + refresh
    ↓
   Клиент обновляет локальные токены

6. Выход
   Клиент запрашивает POST /admin/profile/logout
   Заголовок: Authorization: Bearer <access_token>
    ↓
   Сервер:
   a. Декодирует JWT, получает оставшийся TTL
   b. Записывает в черный список Redis: jwt_blacklist:{md5(token)} = 1, TTL = оставшийся срок
   c. Возвращает успех
```

### Структура JWT

- **access_token**: `{ sub: <user_id>, username: "<name>" }`, TTL по умолчанию 7200 секунд (управляется конфигурацией JWT `default_expire`)
- **refresh_token**: `{ sub: <user_id>, token_type: "refresh" }`, TTL по умолчанию 1209600 секунд (управляется конфигурацией JWT `refresh_expire`, т.е. 14 дней)

### Управление безопасностью

- Пароли хранятся в виде хэша `PASSWORD_BCRYPT`
- Чувствительные поля (phone, email, id_card) прозрачно шифруются/дешифруются на уровне БД через `erikwang2013/encryptable`
- ID на уровне API передаются зашифрованными через `erikwang2013/hashids`, исключая раскрытие последовательности исходных snowflake ID
- SecurityFilter глобально сканирует XSS, SQL-инъекции, обход пути, инъекции команд; временный черный список для одного IP 5 раз/60 сек на 15 минут
- Чувствительные операции (удаление пользователей, ролей, прав, настроек) требуют повторного подтверждения паролем текущего вошедшего пользователя
- Ограничение параллельных сессий: не более 3 действительных токенов на пользователя, при входе с 4-го устройства самый старый токен принудительно попадает в черный список
- Блокировка аккаунта: 5 неудачных входов подряд — блокировка на 15 минут, в этот период возвращается 429

| type | string | `fiat` (фиатная валюта) / `crypto` (криптовалюта) |
| provider | string | Провайдер шлюза: `stripe` / `paypal` / `nowpayments` / `coinbase` / `skrill` / `neteller` / `paysafecard` / `paytm` / `mercadopago` / `astropay` / `paypay` / `kakaopay` / `gcash` |
| status | int | 1=включен, 0=отключен |
| sort | int | Порядок сортировки (по возрастанию) |
| countries | array{string} | Массив видимых кодов стран (пустой массив = виден глобально) |
| currency | string | Валюта (например, USD/USDT), пусто = без ограничений |
| min_amount / max_amount | string | Диапазон сумм (строка сохраняет точность), 0 = без лимита |
| config | string? | JSON конфигурации оплаты (зашифрован; null, если не задан) |

### 17.2 Включение/отключение способа оплаты

```
POST /admin/payment/method/toggle
```

**Тело запроса**:
```json
{
  "id": "a1b2c3d4",
  "status": 1
}
```

| Поле | Тип | Обязательно | Описание |
|------|------|------|------|
| id | string | Да | ID способа оплаты (hashid) |
| status | int | Да | 0=отключен, 1=включен |

**Возможные ошибки**:
- 422: ошибка валидации (id/status отсутствует или status не 0/1)
- 404: способ оплаты не найден

### 17.3 Создание способа оплаты

```
POST /admin/payment/method/create
```

**Тело запроса**:
```json
{
  "name": "Криптовалюта USDT",
  "type": "crypto",
  "provider": "nowpayments",
  "status": 1,
  "sort": 2,
  "countries": [],
  "currency": "USDT",
  "min_amount": "10",
  "max_amount": "10000",
  "config": "{\"api_key\":\"...\"}"
}
```

| Поле | Тип | Обязательно | Валидация | Описание |
|------|------|------|---------|------|
| name | string | Да | max:50 | Название способа оплаты |
| type | string | Да | in:fiat,crypto | Тип: фиат/крипто |
| provider | string | Да | in:stripe,paypal,nowpayments,coinbase,skrill,neteller,paysafecard,paytm,mercadopago,astropay,paypay,kakaopay,gcash | Белый список провайдеров шлюза |
| status | int | Да | in:0,1 | Статус |
| sort | int | Нет | integer,min:0 | Порядок сортировки, по умолчанию 0 |
| countries | array{string} | Нет | max:2 | Коды видимых стран, пусто = глобально |
| currency | string | Нет | max:10 | Валюта, по умолчанию пусто |
| min_amount / max_amount | string | Нет | numeric,min:0 | Диапазон сумм, по умолчанию "0" |
| config | string | Нет | | JSON конфигурации оплаты (зашифрован); пустая строка сохраняется как NULL |

**Пример ответа**:
```json
{
  "code": 0,
  "message": "создано успешно",
  "data": { "id": "e5f6g7h8" }
}
```

**Возможные ошибки**:
- 422: ошибка валидации

### 17.4 Обновление способа оплаты

```
PUT /admin/payment/method/{hashid}
```

- **Параметр пути**: `{hashid}` — ID способа оплаты в кодировке hashid
- **Тело запроса**: как при создании (17.3), все поля необязательны, обновляются только переданные поля

**Возможные ошибки**:
- 404: способ оплаты не найден
- 422: ошибка валидации

### 17.5 Удаление способа оплаты

```
DELETE /admin/payment/method/{hashid}
```

- **Параметр пути**: `{hashid}` — ID способа оплаты в кодировке hashid

**Возможные ошибки**:
- 404: способ оплаты не найден
- 422: существуют ожидающие платежные заказы (status=pending), удаление невозможно
