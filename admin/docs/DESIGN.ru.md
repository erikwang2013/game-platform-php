## 2. Архитектура бэкенда

### 2.1 Многоуровневое проектирование

| Уровень | Каталог | Ответственность |
|---|------|------|
| Маршруты | `config/route.php` | Маппинг URL на контроллеры, привязка промежуточного ПО, версионированные маршруты |
| Промежуточное ПО | `app/middleware/` | Блокировка атак (SecurityFilter), ограничение частоты (RateLimit), аутентификация (JWT), авторизация (RBAC), версия API (ApiVersion) |
| Контроллеры | 30 шт.: Dashboard/User/Role/Permission/Config/Log/Profile/Export/Import/Upload/Health/Docs/Metrics/Analytics/Game/Payment/Withdraw... (панель) + Captcha/Auth (API v1) | Проверка параметров запроса, вызов бизнес-логики, форматирование ответа |
| Бизнес-сервисы | `common/service/` | Аналитика данных: GameDashboardService (обзор/рейтинги/тренды), DepositLogService (выручка/конверсия), ProbabilityService (совместные/условные вероятности, построитель SQL); при сбое БД — пустые данные вместо ошибки |
| Модели данных | `app/model/` | ORM-маппинг, связи, шифрование/дешифрование полей |
| Общие утилиты | `app/common/` | Сервисы Hashids, Snowflake, Encryption |

### 2.2 Жизненный цикл запроса

```
客户端请求
  │
  ▼
webman HTTP Server (workerman)
  │
  ▼
Route 匹配
  │
  ▼
中间件链:
  SecurityFilter ──────► HTTP方法检查 → 405 (仅允许 GET/POST/PUT/DELETE/OPTIONS/HEAD)
  │                     XSS/SQL注入/路径遍历/命令注入/CSRF 攻击拦截 (403)
  ▼
  RateLimit ───────────► Redis 滑动窗口限流
  │ (失败返回 429 + Retry-After 头)
  ▼
  ApiVersion ─────────► API-Version 头校验，注入 $request->apiVersion
  │ (失败返回 400)
  ▼
  AdminAuth ──────────► JWT 验证，注入 $request->adminId
  │ (失败返回 401)
  ▼
  AdminPermission ────► RBAC 权限校验（Redis 60s 缓存）
  │ (失败返回 403)
  ▼
  OperationLog ───────► 操作日志记录 (POST/PUT/DELETE)，自动检测来源端
  │
  ▼
Controller::method()
  │
  ├─► 参数验证 (validator)
  ├─► 敏感操作确认 (confirmPassword)
  ├─► decodeId() — hashid → BIGINT
  ├─► Model 操作 (自动 encryptable 加解密)
  ├─► encodeId() — BIGINT → hashid
  └─► Response JSON
```

### 2.3 Жизненный цикл ID

```
生成 (Snowflake) → 存储 (MySQL BIGINT) → 传输 (Hashids 编码) → 外部 (hash 字符串)
                                                                    │
                            HashidsService::decode() ←──────────────┘
```

### 2.4 Система шифрования данных

```
传输层 (encryption)     — AES-256-CBC，独立密钥
存储层 (encryptable)    — AES-128-ECB，独立密钥，Model $casts 自动处理
展示层 (mask)           — 手机号: 138****1234，邮箱: a***@example.com
```

### 3.3 Стандарты первичных ключей

- Тип: `BIGINT UNSIGNED NOT NULL`
- Свойство: **не автоинкрементный**, генерируется алгоритмом Snowflake на уровне приложения
- Преимущества: глобально уникален, дружествен к распределенным системам, трендовое возрастание удобно для индексов, не раскрывает объем бизнеса
- Конфигурация: datacenter_id(0-31) + worker_id(0-31), поддержка параллельной работы 1024 узлов


### 4.2 Стратегия версий API

Версия API задается заголовком запроса, **не отражается в пути URL**:

```http
API-Version: v1
```

| Механизм | Описание |
|------|------|
| Версия по умолчанию | При отсутствии заголовка `API-Version` по умолчанию `v1` |
| Проверка | Промежуточное ПО `ApiVersion` проверяет, неподдерживаемая версия возвращает 400 |
| Маршрутизация | Вспомогательная функция `v()` динамически разрешает класс контроллера по версии |
| Каталог | Контроллеры организованы по версиям: `app/api/{version}/controller/` |

Пример расширения — добавление API v2:
1. Создать `app/api/v2/controller/AuthController.php`
2. В промежуточном ПО `ApiVersion` добавить `'v2'` в константу `SUPPORTED`
3. Определения маршрутов менять не нужно

```bash
# Использование v1
curl -H "API-Version: v1" /api/auth/login

# Использование v2
curl -H "API-Version: v2" /api/auth/login

# Без заголовка — по умолчанию v1
curl /api/auth/login
```

### 4.3 Стратегия ограничения частоты

Алгоритм скользящего окна на Redis Sorted Set, атомарное выполнение через Lua-скрипты:

| Интерфейс | Лимит |
|------|------|
| По умолчанию | 60 раз/мин/IP/маршрут |
| POST /api/auth/login | 10 раз/мин |
| POST /api/auth/register | 5 раз/мин |

При превышении возвращается 429, заголовки ответа содержат X-RateLimit-Limit / Remaining / Reset / Retry-After.

### 4.4 Единый ответ

```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

| code | Значение | Сценарий срабатывания |
|------|------|---------|
| 0 | Успех | Нормальный ответ |
| 400 | Ошибка параметров | Некорректный формат запроса |
| 401 | Не авторизован | Токен отсутствует/истек/недействителен |
| 403 | Нет прав | Роль пользователя не содержит требуемого права |
| 404 | Не найдено | Ресурс не найден |
| 422 | Ошибка проверки | Параметры формы не соответствуют правилам / неудача подтверждения пароля |
| 500 | Ошибка сервера | Непредвиденное исключение |

### 4.5 Процесс аутентификации (с клик-капчей)

```
客户端                               服务端
  │                                    │
  │  ① POST /api/captcha/generate     │ captcha_create('click')
  │◄── {key, image(base64), targets}  │
  │                                    │
  │  ② 用户点击图中文字位置              │
  │                                    │
  │  ③ POST /api/auth/login           │
  │     {username, password,          │
  │      captcha_key, clicks}         │
  │────────────────────────────────►  │
  │                                    │ ① captcha_verify()
  │                                    │ ② password_verify()
  │                                    │ ③ jwt()->create()
  │◄── {access_token, refresh_token}  │
  │                                    │
  │  ④ GET /admin/dashboard           │
  │     Authorization: Bearer xxx     │
  │────────────────────────────────►  │ AdminAuth → AdminPermission
  │◄── 200 {dashboard data}           │
```

### 4.6 Модель прав (RBAC)

```
  用户 ──┬── 角色 ──┬── 权限
  User     Role      Permission
                 │
                 ├── type=1: 菜单 (控制侧边栏可见)
                 ├── type=2: 按钮 (控制页面内操作)
                 └── type=3: API  (控制接口访问)

  权限标识格式: {method}.{path}
  例: get.admin/user  post.admin/user  delete.admin/user
  超级管理员标识: * (跳过所有权限检查)
```

### 4.7 Повторное подтверждение чувствительных операций

Чувствительные операции (удаление пользователей, ролей, прав и т.п.) требуют передачи пароля текущего пользователя в теле запроса для повторной проверки личности:

```
客户端                           服务端
  │                                │
  │  DELETE /admin/user/{hashid}  │
  │  { password: "******" }       │
  │────────────────────────────►  │
  │                                │ confirmPassword(adminId, password)
  │                                │ → 密码错误返回 422
  │                                │ → 密码正确继续执行
  │◄── 200 { code: 0 }           │
```

Фронтенд перед выполнением операции удаления показывает диалог подтверждения, собирает пароль пользователя и отправляет запрос.

### 4.8 Управление способами оплаты

Модуль управления способами оплаты (`PaymentController` + Flutter `payment_page.dart`) предоставляет 5 эндпоинтов, все требуют аутентификации JWT + RBAC:

| Метод | Путь | Описание |
|------|------|------|
| GET | /admin/payment/method/list | Список (по возрастанию sort) |
| POST | /admin/payment/method/toggle | Включить/отключить |
| POST | /admin/payment/method/create | Создать |
| PUT | /admin/payment/method/{hashid} | Обновить (только переданные поля) |
| DELETE | /admin/payment/method/{hashid} | Удалить (422 при наличии ожидающих заказов) |

- **Белый список provider**: `stripe` / `nowpayments` / `coinbase`
- **Поля**: name / type (fiat|crypto) / provider / status / sort / countries[] (видимость по странам, пусто = глобально) / currency / min_amount / max_amount / config (JSON, хранится зашифрованным)
- **Защита удаления**: удаление возвращает 422, пока существуют заказы со статусом pending
- **Фронтенд**: Flutter `payment_page.dart` — список + диалог создания/редактирования + переключатель включения/отключения

## 6. Проектирование безопасности

### 6.1 Эшелонированная оборона

| Уровень | Мера |
|------|------|
| Ограничение методов | Белый список HTTP-методов SecurityFilter, разрешены только GET/POST/PUT/DELETE/OPTIONS/HEAD, нестандартные методы возвращают 405 |
| Блокировка атак | Промежуточное ПО SecurityFilter, обнаружение и блокировка XSS/SQL-инъекций/обхода пути/инъекций команд/CSRF |
| Человеко-машинная проверка | Клик-капча, обязательная при входе/регистрации |
| Блокировка аккаунта | 5 неудачных входов подряд — блокировка на 15 минут, в этот период возвращается 429 |
| Ограничение сессий | Не более 3 параллельных токенов на пользователя, при превышении самый старый автоматически в черный список |
| Ограничение частоты | Промежуточное ПО RateLimit, скользящее окно Redis, атомарность через Lua |
| CSP | Заголовок Content-Security-Policy ограничивает источники ресурсов, защита от XSS и инъекций данных |
| Подтверждение операций | Чувствительные операции (например, удаление) требуют ввода пароля текущего пользователя |
| Передача | HTTPS + JWT Bearer Token |
| ID интерфейсов | Шифрование Hashids, внешне невозможно вычислить реальный ID |
| Тело запроса | Шифрование чувствительных полей AES-256-CBC |
| База данных | BIGINT первичные ключи (без раскрытия автоинкремента) |
| База данных | Шифрованное хранение чувствительных полей AES-128-ECB |
| Аутентификация | JWT HS256, срок 2ч + refresh token |
| Авторизация | RBAC, контроль прав с гранулярностью method.path |
| Аудит | OperationLog записывает все операции (включая автоматическое определение источника source) |

### 6.2 Управление ключами

```
JWT_SECRET          → 环境变量注入，64位随机字符串
HASHIDS_SALT        → 唯一盐值，泄漏后需全局更换
ENCRYPTION_KEY      → API 传输加密密钥，32字节
ENCRYPTABLE_KEY     → DB 存储加密密钥，与传输密钥独立
SCOUT_HOSTS         → ES 地址，内网部署
```

## 7. Проектирование экспорта

### 7.1 Экспорт Excel

```
请求: POST /admin/export/excel { table, columns, conditions, title }
  → fetchExportData() 查询数据 (limit 10000)
  → 脱敏敏感字段
  → PhpSpreadsheet 构建（蓝底白字表头 + 冻结首行 + 自动筛选）

```

```
请求: POST /admin/export/pdf { type: table|dashboard, title, data }

  → Dompdf 渲染 A4 横向
  → 写入 runtime/tmp/ → download 响应
```

## 8. Архитектура развертывания

### 8.1 Рекомендуемая топология

```
Nginx (:443 HTTPS) → webman worker × N (:8787) → MySQL + ES + Redis
                    静态文件: Flutter Web build/
```

### 8.2 Docker Compose (рекомендуется для продакшена)

`docker-compose.yml` в корне проекта оркестрирует все сервисы указанной топологии:

| Сервис | Образ/сборка | Порт | Описание |
|------|----------|------|------|
| `nginx` | nginx:alpine | 80, 443 | Обратный прокси + статические файлы + Gzip |
| `app` | сборка из локального `Dockerfile` | 8787 | PHP 8.3 + OPcache + webman |
| `mysql` | mysql:8.0 | 3306 | Основная БД, персистентность томов данных |
| `redis` | redis:7-alpine | 6379 | Кэш / ограничение частоты / капча |
| `elasticsearch` | elasticsearch:8.x | 9200 | Полнотекстовый поиск |

Перед запуском замените ключи `JWT_SECRET`, `HASHIDS_SALT`, `ENCRYPTION_KEY` и др. в `docker-compose.yml` на случайные строки.

```bash
cp .env.docker .env
docker-compose up -d
```

### 8.3 CI/CD

Непрерывная интеграция GitHub Actions определена в `.github/workflows/ci.yml`:
- Проверка синтаксиса PHP (`php -l`)
- Модульные тесты PHPUnit
- Статический анализ Flutter (`flutter analyze`)

### 8.4 Резервное копирование базы данных

`database/backup/backup.sh` — резервное копирование mysqldump + gzip, автоочистка старых копий старше 30 дней.
`database/backup/restore.sh` — интерактивный выбор и восстановление копии.

### 8.5 Мониторинг

Эндпоинт `GET /metrics` (`MetricsController`) в текстовом формате Prometheus раскрывает 5 метрик gauge: общее число HTTP-запросов, число активных пользователей, статус соединений с БД/Redis, потребление памяти.
