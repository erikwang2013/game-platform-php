## البدء السريع

### 1. تثبيت التبعيات

```bash
composer install
```

### 2. تكوين متغيرات البيئة

انسخ متغيرات البيئة وعدّلها (اختياري، عند عدم التكوين تُستخدم القيم الافتراضية في `config/*.php`):

```bash
cp .env.example .env
```

عناصر التكوين الأساسية:

| متغير البيئة | الوصف | القيمة الافتراضية |
|---------|------|--------|
| `JWT_SECRET` | مفتاح توقيع JWT | `open-admin-jwt-secret-change-in-production` |
| `HASHIDS_SALT` | ملح Hashids | `open-admin-hashids-salt-2026` |
| `ENCRYPTION_KEY` | مفتاح تشفير API | قيمة افتراضية بـ 32 بايت |
| `SNOWFLAKE_DATACENTER_ID` | معرّف مركز البيانات (0-31) | `1` |
| `SNOWFLAKE_WORKER_ID` | معرّف العقدة العاملة (0-31) | `1` |
| `SCOUT_HOSTS` | عنوان ES | `http://localhost:9200` |

**في بيئة الإنتاج، يجب تعديل جميع المفاتيح إلى سلاسل عشوائية.**

### 3. تهيئة قاعدة البيانات

نفّذ ملفات SQL في `install/` بالترتيب:

```bash
mysql -u root -p < install/install.sql
```

### 4. تشغيل الخدمة

```bash
php start.php start
```

يستمع افتراضيًا على `http://0.0.0.0:8787`.

### 5. تشغيل الواجهة الأمامية (اختياري)

**لوحة إدارة Flutter (الويب):**

```bash
cd apps/flutter
flutter pub get
flutter run -d chrome    # الويب (نمط لوحة إدارة PC)
```

**عميل HarmonyOS (الهاتف):**

افتح دليل `apps/harmonyos/` باستخدام DevEco Studio، واربط جهازًا حقيقيًا أو محاكيًا للتشغيل.

### 6. النشر بخطوة واحدة عبر Docker Compose (موصى به للإنتاج)

يوفر المشروع حلاً كاملاً لتنظيم Docker، يتضمن 5 خدمات: Nginx وPHP (تطبيق webman) وMySQL وRedis وElasticsearch.

```bash
# 1. تكوين متغيرات بيئة Docker
cp .env.docker .env

# 2. تشغيل جميع الخدمات
docker-compose up -d

# 3. تهيئة قاعدة البيانات (نفّذ داخل حاوية app)
docker-compose exec app mysql -h mysql -u root -p < install/install.sql

# 4. الوصول
# http://localhost:8787  (webman)
# http://localhost:8080  (وكيل Nginx العكسي)
```

- `Dockerfile`: PHP 8.3 + OPcache + Composer، مبني على `php:8.3-cli`
- `docker-compose.yml`: تنظيم 5 خدمات، عزل الشبكة، استمرارية البيانات عبر أحجام
- `.env.docker`: متغيرات بيئة مخصصة لبيئة Docker


## مواصفات قاعدة البيانات

- **بادئة الجداول**: `erik_`
- **المفتاح الأساسي**: المفتاح الأساسي لكل الجداول هو `id BIGINT UNSIGNED NOT NULL`، **مُعطّل AUTO_INCREMENT**
- **توليد المعرفات**: معرفات المفتاح الأساسي يولّدها `SnowflakeService::generate()` على طبقة التطبيق، فريدة موزّعة
- **الحقول الإلزامية**: يجب أن يتضمن كل جدول `id`, `created_at`, `updated_at`
- **الحذف الناعم**: الجداول التي تتطلب حذفًا ناعمًا تُضيف `deleted_at DATETIME DEFAULT NULL`
- **الحقول الحساسة**: أرقام الهواتف والبريد الإلكتروني وأرقام الهوية وغيرها تُشفّر/تُفك تشفيرها تلقائيًا عبر إضافة `encryptable`، ويُخزَّن النص المشفر في الحقل `VARCHAR(500)`

## مواصفات API

### تنسيق الاستجابة الموحد

```json
{
    "code": 0,
    "message": "success",
    "data": {}
}
```

### رموز أخطاء الأعمال

| رمز الخطأ | المعنى | الوصف |
|-------|------|------|
| `0` | نجاح | |
| `400` | خطأ في معاملات الطلب | |
| `401` | غير مسجّل دخول (رمز غير صالح أو منتهٍ) | |
| `403` | لا صلاحية / اعتراض أمني | فشل تحقق RBAC / كشف هجوم SecurityFilter |
| `404` | المورد غير موجود | |
| `422` | فشل التحقق من المعاملات | |
| `413` | حجم الطلب كبير جدًا | فعّله SecurityFilter، يتجاوز 10MB |
| `405` | طريقة الطلب غير مسموح بها | فعّله SecurityFilter، يُسمح فقط بـ GET/POST/PUT/DELETE/OPTIONS/HEAD |
| `415` | نوع الوسائط غير مدعوم | فعّله SecurityFilter، Content-Type ليس JSON |
| `429` | عدد الطلبات كبير جدًا | فعّله RateLimit / قفل الحساب (5 محاولات فاشلة تقفل 15 دقيقة) |
| `500` | خطأ داخلي في الخادم | |

### معالجة المعرفات

- **المعرفات في الطلبات/الاستجابات**: تُشفّر إلى سلاسل عبر hashids، دون كشف معرفات قاعدة البيانات الحقيقية
- **مسار الواجهة**: `GET /admin/user/{hashid}` — `{id}` في المسار هو سلسلة hashid
- **التخزين في قاعدة البيانات**: القيمة الأصلية BIGINT، يولّدها snowflake

### إصدار API

يُتحكم بإصدار API عبر ترويسة الطلب، **ولا يظهر في URL**:

```http
API-Version: v1
```

- عند عدم حمل رقم الإصدار، يُستخدم `v1` افتراضيًا
- الإصدارات غير المدعومة تُرجع `400 Bad Request`
- عند إضافة إصدار جديد، يكفي إنشاء دليل `app/api/{version}/controller/` وتسجيل الإصدار الجديد في الوسيطة

### الحد من المعدل

بناءً على خوارزمية النافذة المنزلقة في Redis، الافتراضي 60 مرة/دقيقة/IP/مسار. الواجهات الحساسة أكثر صرامة:
- تسجيل الدخول: 10 مرات/دقيقة
- التسجيل: 5 مرات/دقيقة

تتضمن ترويسات الاستجابة `X-RateLimit-Limit` و`X-RateLimit-Remaining` و`X-RateLimit-Reset`. عند تجاوز الحد يُرجع 429 مع `Retry-After`.

### بنية الوسيطات

الوسيطات العامة تسري على جميع الطلبات، وتُنفَّذ بالترتيب:

```
Cors (معالجة مسبقة للعمل عبر الأصول + ترويسات استجابة)
  → SecurityFilter (تقييد طرق HTTP/حجم الطلب/التحقق من Content-Type/اعتراض XSS/حقن SQL/اجتياز المسار/حقن الأوامر/CSRF)
  → RateLimit (الحد من المعدل بنافذة منزلقة في Redis + قفل الحساب: 5 محاولات فاشلة تقفل 15 دقيقة)
  → ApiVersion (التحقق من إصدار API، مجموعة مسارات /api)
  → AdminAuth (مصادقة JWT + قائمة سوداء، مجموعة مسارات /admin)
  → AdminPermission (تحقق RBAC، مجموعة مسارات /admin)
  → OperationLog (تسجيل تلقائي لـ POST/PUT/DELETE، بما فيه كشف المصدر، مجموعة مسارات /admin)
```

`/health` و`/api/docs` نقطتا نهاية عامتان، تمران عبر `Cors → SecurityFilter → RateLimit` فقط.

تحسينات أمنية:
- **قفل الحساب**: بعد 5 محاولات تسجيل دخول فاشلة متتالية، يُقفل الحساب تلقائيًا لمدة 15 دقيقة، وترجع محاولات الدخول خلالها 429
- **تقييد الجلسات المتزامنة**: 3 رموز صالحة كحد أقصى لكل مستخدم، وعند التجاوز يُضاف أقدم رمز تلقائيًا إلى القائمة السوداء
- **security.txt**: يوفر `GET /.well-known/security.txt` معلومات الاتصال الأمنية القياسية RFC 9116
- **إعدادات أمان Nginx**: راجع `docs/nginx-security.conf` للحصول على مثال كامل لتحصين الوكيل العكسي

### المصادقة

يتطلب تسجيل الدخول والتسجيل اجتياز **رمز التحقق بالنقر** أولاً:

1. يطلب العميل `POST /api/captcha/generate` للحصول على صورة رمز التحقق (base64 PNG) وقائمة أهداف النص
2. ينقر المستخدم على مواضع النص المطابقة في الصورة بالترتيب، ويُجمع إحداثيات النقرات `[{x, y}, ...]`
3. عند تسجيل الدخول، يُرسل `captcha_key` و`clicks` معًا، ويتحقق الخادم من رمز التحقق أولاً ثم من بيانات الاعتماد

```http
POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "******",
  "captcha_key": "abc123...",
  "clicks": [{"x": 120, "y": 85}, {"x": 210, "y": 140}, {"x": 95, "y": 170}]
}
```

تتطلب الواجهات اللاحقة للوحة الإدارة مصادقة JWT:

```http
Authorization: Bearer <token>
```

بعد نجاح تسجيل الدخول، يُرجع access_token بصلاحية ساعتين؛ ويُرجع أيضًا refresh_token بصلاحية 14 يومًا.

عند تسجيل الخروج، يُضاف الرمز إلى القائمة السوداء في Redis ولا يمكن إعادة استخدامه خلال فترة صلاحيته. POST /admin/profile/logout

### التأكيد الثانوي للعمليات الحساسة

تتطلب العمليات الحساسة مثل حذف المستخدمين والأدوار والصلاحيات تمرير `password` للمستخدم المسجل دخوله حاليًا في جسم الطلب للتأكيد الثانوي على الهوية:

```http
DELETE /admin/user/{id}
Content-Type: application/json
Authorization: Bearer <token>

{ "password": "******" }
```

### الواجهات العامة

| الطريقة | المسار | الوصف |
|-----|------|------|

## ملاحظات الواجهة الأمامية

### لوحة إدارة Flutter (نمط PC)

- **التخطيط**: شريط جانبي (قابل للطي 64px/240px) + شريط علوي + منطقة محتوى، متجاوب عند ثلاث نقاط توقف (هاتف/لوحي/مكتبي)
- **الصفحات**: تسجيل الدخول، لوحة المعلومات، إدارة المستخدمين، صلاحيات الأدوار، إعدادات النظام، سجلات العمليات، المركز الشخصي
- **إدارة الحالة**: GetX (`ApiService` مفرد + `AuthService` لاستمرار الرمز)
- **لوحة المعلومات**: بطاقات إحصائية، مخطط خطي للاتجاه (fl_chart)، مخطط دائري، أحدث سجلات العمليات
- **التصدير**: تصدير Excel/PDF، يتضمن PDF معلومات حقوق نشر غير قابلة للإزالة
- **العمليات الجماعية**: حذف جماعي متعدد التحديد، تفعيل/تعطيل جماعي
- **السمة**: Material 3 بسمتين فاتحة/داكنة

### هاتف HarmonyOS

- **الصفحات**: تسجيل الدخول، لوحة المعلومات، قائمة/تفاصيل المستخدمين، المركز الشخصي
- **المصادقة**: JWT Bearer + تحديث تلقائي دون إحساس عند 401، ومع فشل التحديث إعادة توجيه تلقائية لصفحة تسجيل الدخول
- **التخزين**: إدارة الرمز عبر AppStorage

## معايير التطوير

- لا تُسبق مراجع الدوال/الفئات العامة بـ `\`، استخدم الاستيراد عبر `use` بشكل موحد
- يجب أن يتضمن رأس كل ملف PHP إعلان حقوق النشر
- يجب أن تتضمن جميع ملفات التكوين تعليقات توضيحية بالصينية
- يجب أن تولَّد المفاتيح الأساسية لقاعدة البيانات عبر snowflake على طبقة التطبيق، ويُحظَر التزايد الذاتي
- يجب تمرير جميع المعرفات في معاملات واستجابات طبقة API عبر تشفير/فك تشفير hashids
- تستخدم وسيطة AdminPermission التخزين المؤقت في Redis لصلاحيات المستخدم (TTL=60s)، لإزالة عنق زجاجة استعلامات N+1

## النشر

### Docker Compose (موصى به)

يوفر دليل جذر المشروع `docker-compose.yml`، ينظم 5 خدمات:

| الخدمة | الصورة | المنفذ |
|------|------|------|
| `nginx` | nginx:alpine | 80, 443 |
| `app` | بناء محلي عبر `Dockerfile` | 8787 |
| `mysql` | mysql:8.0 | 3306 |
| `redis` | redis:7-alpine | 6379 |
| `elasticsearch` | elasticsearch:8.x | 9200 |

تُبنى صورة PHP عبر `Dockerfile`، الصورة الأساسية `php:8.3-cli`، مع تفعيل OPcache.

```bash
cp .env.docker .env
docker-compose up -d
```

### CI/CD

خط أنابيب التكامل المستمر في GitHub Actions: `.github/workflows/ci.yml`

- فحص صياغة PHP (`php -l`)
- اختبارات PHPUnit الوحدوية
- التحليل الساكن لـ Flutter (`flutter analyze`)

### النسخ الاحتياطي لقاعدة البيانات

دليل `database/backup/`:

- `backup.sh` — نسخ احتياطي عبر mysqldump + gzip، تنظيف تلقائي للنسخ الأقدم من 30 يومًا
- `restore.sh` — استعادة تفاعلية، تعرض النسخ الاحتياطية المتاحة للاختيار

### إعدادات أمان Nginx

يرجى الرجوع إلى `docs/nginx-security.conf` في النشر الإنتاجي لتكوين تحصين الوكيل العكسي.
