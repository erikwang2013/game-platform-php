## 2. V1 范围

**做完算上线的：** 四关可通关、三种消除、技能与破坏王障碍、H5 可从大厅打开。钱包可关（特性开关 `xxl.entry_bet`）。

**明确砍掉或后置：** 100 物种同时在盘上、农具当棋子、物理引擎、GLTF、观战、局内排行、水洼主线关、克制者吃完留场、每步服务端校验。

## 4. 分期与依赖

```
P0 同种三消 ─────────┐
P1 选关与丰收 ───────┼─ P2 生态与驱赶 ─ P3 障碍农具 ─ P4 象+钱包 ─ P5 抛光
渲染沙盘（可与 P0 并行）┘
```

- P0 不依赖 PHP。`?debug=1` 本地玩。
- P1 不依赖钱包。
- P2 依赖 P0 的匹配扫描扩展，不改操作方式。
- P3 依赖格子 overlay。
- P4 依赖平台已有 `POST /api/game/launch` 与 `SelfProvider`；游戏侧加 ticket、bet、settle。
- P5 无功能依赖，可随时插入低端开关。

## 5. 工作包（按人）

**A 领域（无界面）**  
图鉴 JSON → 棋盘快照 → 匹配（同种/生态/象）→ 重力 → 关卡胜负 → 分数。Vitest 先于画面。

**B 表现**  
场景、相机、10 套模板里先做 3 套（谷穗/水果/鸡），Raycaster，交换与消除缓动。HUD 用 DOM。

**C 关卡内容**  
四关 JSON：刷新池、目标、步数/时限、技能白名单、开局障碍。

**D 平台**  
launch URL 参数、余额展示、bet/settle、失败退费策略、play-log 事件。

建议顺序：A 的 P0 测试红绿 → B 接快照 → C 丰收 → A 生态测试 → C 其余三关 → D。

---

## 6. 平台侧要动的（P4 才做）

接口契约见 **[api.md](api.md)**。平台侧改动点：

| 项 | 现状 | 规划动作 |
|----|------|----------|
| 游戏记录 | `GameController::launch` 已写 session | 后台加一条 type=self、api_endpoint 指向本 H5 |
| 钱包 | `SelfProvider::bet/settle` 已有 | 游戏按 round_id 调用；设单 round 派奖上限 |
| 特性开关 | `FeatureFlag` 已有 | `xxl.eco_chain` `xxl.elephant` `xxl.skills` `xxl.entry_bet` |
| 静态托管 | Nginx 已分发 | `/games/xiaoxiaole/` 指向构建产物 |
| 大厅打开 | Flutter `launchUrl` | endpoint 拼 `session_id` |

P0–P3 **不必改 PHP**。

## 7. 风险

| 风险 | 影响 | 对策 |
|------|------|------|
| 生态规则玩家看不懂 | 驱赶关过不去 | 教学第三条；可消预览放到 P5 |
| 刷新种类仍偏多 | 无子可消 | 单关硬顶 8 种 |
| 象过强 | 狂欢瞬空 | 目标只计象规则；盘上锁死 1 只 |
| 客户端改分骗奖 | 钱包 | P4 派奖上限；录像校验后置 |
| 低端机掉帧 | 体验 | dpr 上限 2；粒子可关 |
