## 0. পরিকল্পনার সাপেক্ষে আর্কিটেকচার সিদ্ধান্ত

পরিকল্পনা হলো গেমপ্লে দৃষ্টিভঙ্গি; নিচের সিদ্ধান্তগুলো "খেলার যোগ্য, টেস্টযোগ্য, ওয়ালেট যুক্তযোগ্য" এর দ্বন্দ্ব সমাধান করে।

| ID | সিদ্ধান্ত | কারণ |
|----|------|------|
| D1 | **ডেক্স ≠ একই বোর্ডের棋子**। ১০০+ প্রজাতি ডেক্স ও চেহারা; এক লেভেলের রিফ্রেশ পুলে শুধু **৫–৮টি প্রজাতি** | 8×8-এ একসাথে কয়েক ডজন প্রজাতি থাকলে প্রায় মিল হয় না |
| D2 | ম্যাচিং দুই স্তর: **একই প্রজাতি `speciesId` অনুযায়ী, ইকোসিস্টেম `role` + কন্ট্রোল টেবিল অনুযায়ী** | পরিকল্পনায় একসাথে "তিনটি আপেল" ও "মুরগি+পোকা+পোকা" দরকার |
| D3 | একই লাইনে নিয়মের অগ্রাধিকার: **হাতি > ইকোসিস্টেম > একই প্রজাতি**; পরস্পর-বর্জনীয়, ডাবল স্কোর নেই | এক লাইনে দুবার স্কোর এড়াতে |
| D4 | **কৃষি-যন্ত্র বোর্ডে আসে না**, শুধু HUD স্কিল স্লটে; পাথর/জলাশয়/গাছ বাধা, অদলবদল করা যায় না | পরিকল্পনার ৫ম ধারা棋子 লাইব্রেরির সাথে সংঘর্ষে, স্কিল+বাধা-ই মান্য |
| D5 | **ডোমেইন লজিকে Three.js-এর শূন্য নির্ভরতা**, শুদ্ধ ফাংশন + স্ন্যাপশট; প্রেজেন্টেশন স্তর শুধু ইভেন্ট সাবস্ক্রাইব করে | নিয়ম ইউনিট-টেস্ট, রিপ্লে ও ভবিষ্যতে সার্ভার ভেরিফিকেশনযোগ্য |
| D6 | শুরুর `session_id` থেকে **ডিটারমিনিস্টিক RNG seed**; ড্রপ/রিফ্রেশ সব এই RNG দিয়ে | একই seed-এ পুনরায় দেখার সুযোগ; অ্যান্টি-চিটের পথ খোলা |
| D7 | ফিজিক্স ইঞ্জিন নেই। মুভ/জাম্প/মিল ইজিং দিয়ে, Cannon/Rapier আনা হয় না | পরিকল্পনায় "সিমুলেটেড অ্যানিমেশন" লেখা আছে; গ্রিড গেমে ফিজিক্সের লাভ নেই |
| D8 | ক্যামেরা **অর্থোগোনাল 2.5D ফিক্সড পজিশন**, অরবিট কন্ট্রোল বন্ধ | পরিকল্পনার সাথে সামঞ্জস্য, ভুল অপারেশন ও মাথা ঘোরা এড়ায় |
| D9 | প্রজাতি **দলভিত্তিক জিওমেট্রি টেমপ্লেট + রং/এক্সেসরি** ভাগ করে, প্রতিটি ফসলের জন্য আলাদা মডেল নেই | ব্যান্ডউইথ ও সময়সীমা; ভিজ্যুয়াল পার্থক্য রঙ + একটি চেনার চিহ্নে |
| D10 | লেভেল এন্ট্রিতে `SelfProvider::bet`, জয়ে `settle`, মাঝপথে ব্যর্থ হলে এন্ট্রি ফি ফেরত নেই; প্রথম ধাপ না নিলে `refund` | প্ল্যাটফর্ম ওয়ালেট ও round ইডেমপোটেন্সির সাথে সামঞ্জস্য |

## 1. সিস্টেম কনটেক্সট

```
Flutter / HarmonyOS / PC Web
        │  POST /api/game/launch { game_id }
        ▼
service/ (webman :8788)
  GameController::launch  → session_id + seed + api_endpoint
  SelfProvider            → bet / settle / refund / getBalance
  GamePlayLog + EventBus  → game.played / 成就 / VIP
        │  api_endpoint?session_id=&token= খুলুন
        ▼
game/xiaoxiaole/  (স্ট্যাটিক রিসোর্স, Nginx)
  Vite + TypeScript + Three.js
  ডোমেইন ইঞ্জিন ──ইভেন্ট──► রেন্ডার / HUD
  PlatformAdapter ──HMAC/JWT──► /api/provider/*
```

গেমটি **স্ট্যাটিক ফ্রন্টএন্ড**, কর্তৃত্বমূলক সেশন ও অর্থ `service/`-এ। ক্লায়েন্ট বোর্ড স্টেট ধরে রাখে; সার্ভার ব্যালেন্স ও round ইডেমপোটেন্সি ধরে রাখে। প্রথম পর্বে প্রতি ধাপ সার্ভার ভেরিফিকেশন নেই, তবে ডোমেইন স্তর অবশ্যই ডিটারমিনিস্টিক, যাতে দ্বিতীয় পর্বে `seed + অপারেশন সিকোয়েন্স` সার্ভারে পাঠিয়ে পুনরায় হিসাব করা যায়।

## 2. ক্লায়েন্ট স্তরবিন্যাস

উপর থেকে নিচে, ক্রস-লেয়ার রিভার্স নির্ভরতা নিষিদ্ধ (`render` কে `domain` import করতে পারবে না)।

```
app/          অ্যাসেম্বলি, স্টেট মেশিন, লেভেল লাইফসাইকেল
hud/          HTML Overlay: স্কোর, ধাপ, লক্ষ্য, স্কিল, ফলাফল
platform/     launch প্যারামিটার, ওয়ালেট, play-log, ফিচার সুইচ
render/       Three.js: দৃশ্য, বোর্ড,棋子 গ্রিড, ইনপুট, VFX
runtime/      কমান্ড বাস, অ্যানিমেশন কিউ, রিপ্লে
domain/       বোর্ড, ম্যাচিং, কন্ট্রোল, গ্র্যাভিটি, স্কোর, ক্যাটালগ, লেভেল নিয়ম
config/       কন্ট্রোল টেবিল, রিফ্রেশ ওয়েট, জিওমেট্রি রেসিপি, লেভেল JSON
```

**মূল লুপ (`requestAnimationFrame`-এ নিয়ম হিসাব নয়)**: ইনপুট → কমান্ড → ডোমেইন সিঙ্ক সেটেলমেন্ট (একবার swap-এ সব চেইন হিসাব করে, ইভেন্ট তালিকা তৈরি হয়) → রানটাইম ইভেন্ট অনুযায়ী অ্যানিমেশন কিউ চালায় → অ্যানিমেশন শেষ হলেই পরের ইনপুট গ্রহণ।

এতে "লজিক এক ফ্রেম, প্রেজেন্টেশন বহু ফ্রেম", combo ক্লিকের সাথে স্টেট টানাটানি করে না।

## 4. ডোমেইন মডেল

### 4.1棋子 সংজ্ঞা (ডেক্স)

```
PieceDef
  id            speciesId        যেমন wheat, hen, elephant
  faction       Faction         crop | veg | fruit | flora | insect | poultry | livestock | tree | tool | obstacle | apex
  role          Role            plant | prey | predator_mid | predator_high | apex | obstacle | skill
  tags[]                         crop, edible_by_poultry, tree_seedling, bone …
  rarity        common | rare | legendary
  template      GeometryTemplate জিওমেট্রি টেমপ্লেটের নাম
  tint          RGB              টেমপ্লেটের মধ্যে রঙ
  accessory     optional         ঠোঁট, পাপড়ি, শুঁড় ইত্যাদি আলাদা করার অংশ
```

পরিকল্পনার ফসল/শাকসবজি/ফল/ফুল-ঘাস/পোকা/হাঁস-মুরগি/গবাদি/গাছ সব ডেক্সে যায়; **tool ঘরে তৈরি হয় না**। হাতি `rarity = legendary`, `role = apex`।

### 4.2 ঘর ও বোর্ড

```
Cell
  q, r                কলাম, সারি (0–7)
  height              ভূ-আকৃতির ওঠানামা (শুধু রেন্ডার, নিয়মে অংশ নেয় না)
  occupant           PieceInstance | null
  overlay            none | fertilizer | puddle | stone(hp) | tree(hp)
  locked             bool          হাতির উৎসব লেভেল: হাতিকে সরানো যাবে না

PieceInstance
  uid, speciesId, def
  special            none | fertilizer_token
```

- **পাথর / গাছ**: ঘর দখল করে, অদলবদল বা ভেঙে পড়া যায় না। HP লেভেলে।
- **জলাশয়**: ঘরের উপর জমা, গ্র্যাভিটি দিয়ে সেই ঘর ভেদ করা ব্লক করে (উপরের棋子 জলাশয়ের এক ঘর উপরে থামে)।
- **সার**: ইকোসিস্টেম মিলের পর ওই ঘরে থাকে; পরের বার ওই ঘরের অংশগ্রহণে মিলের স্কোর ×2, তারপর অদৃশ্য।

### 4.3 রিফ্রেশ পুল (লেভেল)

```
SpawnPool
  speciesIds[]       5–8 টি
  weights[]          species-এর সাথে সারিবদ্ধ
  maxApex            ডিফল্ট 1
  apexUnlock         combo >= 5 হলে সিস্টেম তৈরি করে, "অদলবদল দিয়ে তৈরি" নিষিদ্ধ
```

লেভেল শুধু নিজের পুল থেকে `rng` দিয়ে棋子 টানে। ডেক্স যত বড়ই হোক, বোর্ডের এনট্রপি নিয়ন্ত্রণযোগ্য।

## 5. মূল নিয়ম ইঞ্জিন (ফিচার ডিজাইন)

### 5.1 অপারেশন

1.棋子 A ক্লিক → সিলেক্ট (জাম্প + আউটলাইন)।
2. সংলগ্ন অর্থোগোনাল ঘর B ক্লিক → অদলবদলের চেষ্টা (তির্যক নিষিদ্ধ)।
3. অসংলগ্ন / খালি ক্লিক → পুনঃনির্বাচন বা বাতিল।
4. অদলবদলের পর **কোনো বৈধ ম্যাচ না থাকলে**, ফেরত অ্যানিমেশন, ধাপ খরচ হয় না।
5. ম্যাচ থাকলে ১ ধাপ খরচ, সেটেলমেন্টে যায়।

বাধা ঘরকে অদলবদল লক্ষ্য হিসেবে বাছা যায় না। লক করা ঘর (লেভেল নিয়ম) একইভাবে।

### 5.2 লাইন স্ক্যান

প্রতিটি swap-এর পরের বোর্ডে:

- অনুভূমিক, উল্লম্ব ধারাবাহিক ঘর, দৈর্ঘ্য ≥ 3 হলে একটি **run**।
- একটি run-এ শুধু একটি নিয়ম প্রয়োগ হয় (D3)।
- একাধিক run ছেদ করতে পারে (ক্লাসিক L/T আকৃতি), ছেদ ঘর শুধু একবার মিল হয়।

### 5.3 একই প্রজাতির মিল

run-এর ভেতরে `speciesId` সব একই, এবং বাধা নয়, হাতির বিশেষাধিকার আলাদাভাবে সামলানো হয়।

- ৩-মিল: বেস স্কোর।
- ৪-মিল: অতিরিক্ত স্কোর, এবং কেন্দ্র ঘরে **সার** পড়ে (ইকোসিস্টেম সারের সাথে একই overlay)।
- ৫-মিল: অতিরিক্ত স্কোর, স্কিল স্লট +১ চার্জ (৫.৭ দেখুন)।

### 5.4 ইকোসিস্টেম মিল (কন্ট্রোল চেইন)

বিচার: **ঠিক ১টি কন্ট্রোলার + বাকিগুলো সব ওই কন্ট্রোলারের শিকার** (৩ ঘর মানে ১+২)। শিকার একই প্রজাতির হতে হবে না।

| কন্ট্রোলার | শিকার ম্যাচিং |
|--------|----------|
| মুরগি, হাঁস, হংস | faction ∈ {flora, veg, fruit, insect}；**crop (শস্য) নয়** |
| কুকুর | faction = poultry (মুরগি/হাঁস/হংস/কবুতর ইত্যাদি) |
| শূকর | faction ∈ {tree, flora, veg, fruit, insect, crop}；**কুকুর নয়** |
| গরু, ঘোড়া | faction ∈ {flora, crop} বা tag `tree_seedling`; পোকা ও মাংস নয় |
| হাতি | ৫.৫ দেখুন, এই টেবিলে নয় |

ফলাফল:

- পুরো রান মিলে যায়, শিকার অ্যানিমেশন চলে (কন্ট্রোলার আগে "খায়", তারপর শিকারের সাথে একসাথে মাঠ ছাড়ে, বা কন্ট্রোলার থাকে——**প্রথম পর্বে পুরো রান একসাথে মাঠ ছাড়ে**, অবশিষ্ট কন্ট্রোলার ড্রপ ভারসাম্য নষ্ট না করতে; অভিজ্ঞতা দুর্বল মনে হলে দ্বিতীয় পর্বে "কন্ট্রোলার থাকা" সুইচ)।
- বেস ইকোসিস্টেম স্কোর একই-প্রজাতির চেয়ে বেশি।
- কন্ট্রোলারের মূল ঘরে **সার** তৈরি হয়।
- `ecoChainStreak += 1`; একই চেইনে একাধিক ইকোসিস্টেম মিল streak কাউন্ট নোড একবারই বাড়ায় (পুরো resolve শেষে +1, যাতে একবার ড্রপে স্কিল ভরে না যায়)।

**মুরগি শস্য খায় না**: ফসল ও মুরগি এক বোর্ডে থাকতে পারে, কিন্তু ইকোসিস্টেম run তৈরি হয় না; ফসল শুধু একই-প্রজাতি মিলে।

### 5.5 হাতি

- গোটা বোর্ডে সর্বোচ্চ ১টি; রিফ্রেশ ওয়েট খুব কম; শুধু `combo >= 5` পুরস্কারে তৈরি, বা লেভেল `initialPieces`-এ দেওয়া।
- run-এ ১টি হাতি + যেকোনো ২টি অ-কৃষি-যন্ত্র, অ-বাধা棋子 → এই ৩ ঘর খালি (বিভিন্ন দল হতে পারে)।
- হাতি **কৃষি-যন্ত্র মিলাতে পারে না** (কৃষি-যন্ত্র বোর্ডে নেই, স্বাভাবিকভাবেই পূরণ হয়) এবং বাধাও নয় (বাধা run-এ আসে না)।
- 「হাতির উৎসব」লেভেল: শুরুতে ১টি, `locked = true`, মূল ঘর থেকে সরানো যায় না; শিকারকে হাতির পাশে এনে run তৈরি হয়।

### 5.6 চেইন, গ্র্যাভিটি, রিফ্রেশ

```
resolve:
  runs ডিটেক্ট
  none হলে → idle
  স্কোর, overlays, hp প্রয়োগ (সংলগ্ন বাধায়)
  Clear ইমিট
  gravity: প্রতিটি কলাম নিচ থেকে উপর দিকে কমপ্যাক্ট, stone/tree ঘন বাধা এড়িয়ে; puddle ভেদ ব্লক
  refill: কলামের উপর থেকে SpawnPool অনুযায়ী棋子 পূরণ (maxApex সীমা মান্য)
  combo++
  detect-এ ফিরে যান
```

সংলগ্ন মিল বাধার HP কাটে: পাথর প্রতিবার সংলগ্ন একই-প্রজাতি/ইকোসিস্টেম -1, HP=0 হলে ভাঙে; গাছ ডিফল্ট শুধু **কোদাল** বা লেভেলের 「তিন শূকরের রেঞ্জ আর্চ」 বা শূকর ইকোসিস্টেম (শিকার-এ গাছ) দিয়ে HP কাটে। ডেস্ট্রয়ার লেভেলে গাছের HP=5।

বালতি স্কিল: এক ঘর জলাশয় বাছুন → overlay মুছে, ওই কলামে সাথে সাথে একবার gravity।

### 5.7 স্কিল স্লট (কৃষি-যন্ত্র)

| স্কিল | আনলক | প্রভাব |
|------|------|------|
| কাস্তে | পরপর ৩ বার resolve-এ ইকোসিস্টেম | এক সারি বা কলাম বেছে, ওই লাইনের সব **plant রোল** (crop/veg/fruit/flora) মুছে, ধাপ খরচ হয় না, চার্জ খরচ হয় |
| কোদাল | একই, বা লেভেল প্রি-সেট | পাথর/গাছ ক্লিক, সরাসরি HP=0 বা -3 (লেভেল কনফিগ) |
| বালতি | লেভেল প্রি-সেট বা চার্জ | এক ঘর জলাশয় নিষ্কাশন |

চার্জ নিয়ম: `ecoResolveCount` ৩ হলে → স্লট +১, কাউন্ট শূন্য। স্লট সর্বোচ্চ ২। কাস্তে/কোদাল/বালতি কোনগুলো আসবে লেভেল `allowedSkills[]` ঠিক করে।

### 5.8 স্কোরিং

```
same_3     = 10 * n * combo * fertilizerMul
eco        = 25 * n * combo * fertilizerMul
elephant   = 40 * n * combo
skill_clear= 8  * n
obstacle   = 20 * brokenCount
```

`combo` ১ থেকে শুরু, প্রতিটি চেইন +১, প্লেয়ারের পরের ম্যানুয়াল swap-এ রিসেট। সার শুধু "ওই ঘর মিল হওয়ার সেই একবার"-এ কাজ করে।

## 9. প্ল্যাটফর্ম ইন্টিগ্রেশন

সম্পূর্ণ ইন্টারফেস চুক্তি (launch / balance / bet / settle / refund / play-log / ফিচার সুইচ) দেখুন **[api.md](api.bn.md)**। মূল পয়েন্ট:

- লঞ্চ: `POST /api/game/launch` → `session_id, api_endpoint, type=self`, `api_endpoint?session_id=&token=` খুলুন।
- ওয়ালেট: `SelfProvider::bet/settle/refund`, `round_id = session_id + ':' + levelId + ':' + attempt`; ডোমেইন `seed = hash(session_id + round_id)`।
- ফিচার সুইচ: `xxl.eco_chain` `xxl.elephant` `xxl.skills` `xxl.entry_bet`, বন্ধ হলে শুদ্ধ একই-প্রজাতি থ্রি-ম্যাচে অবনমন।
- নিরাপত্তা: প্রথম পর্ব ক্লায়েন্ট-অথরিটি বোর্ড + সার্ভার-অথরিটি ওয়ালেট, এক round-এ শুধু একবার bet/settle; দ্বিতীয় পর্ব অপারেশন সিকোয়েন্স আপলোড করে সার্ভার পুনরায় হিসাব।

## 12. মডিউল দায়িত্ব একনজরে

| মডিউল | ইনপুট | আউটপুট | নির্ভরতা |
|------|------|------|------|
| Catalog | JSON ডেক্স | PieceDef | নেই |
| RestraintTable | কন্ট্রোল কনফিগ | isEcoRun(run) | Catalog |
| Board | কমান্ড | নতুন স্ন্যাপশট | Catalog, RNG |
| MatchDetector | স্ন্যাপশট | runs[] | RestraintTable |
| Gravity | স্ন্যাপশট | স্ন্যাপশট + Fell | Board |
| Level | মিল পরিসংখ্যান | অগ্রগতি/জয়-পরাজয় | Board ইভেন্ট |
| Score | ইভেন্ট | স্কোর | Level (মাল্টিপ্লায়ার) |
| GameStateMachine | কমান্ড/অ্যানিমেশন সম্পন্ন | স্টেট | উপরের domain |
| PieceFactory | PieceDef | Object3D | শুধু render |
| PlatformAdapter | জয়-পরাজয়/বাজি | HTTP | domain-এ সাইক্লিক নির্ভরতা নেই |
