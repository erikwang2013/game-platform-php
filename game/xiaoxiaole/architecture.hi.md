## 0. योजना के सापेक्ष आर्किटेक्चर निर्णय

योजना खेल विज़न है; निम्न निर्णय 「खेलने योग्य, परीक्षण योग्य, वॉलेट से जोड़ने योग्य」 के विरोधाभास को हल करते हैं।

| ID | निर्णय | कारण |
|----|------|------|
| D1 | **इकाइयों की सूची ≠ एक ही बोर्ड के टुकड़े**। 100+ प्रजातियाँ सूची और दिखावट हैं; एक स्तर की रीफ़िल पूल में केवल **5–8 प्रजातियाँ** आती हैं | 8×8 पर एक साथ दर्जनों प्रजातियाँ होने पर लगभग कभी मैच नहीं बनता |
| D2 | मैचिंग दो परतों में: **समान प्रजाति `speciesId` से, पारिस्थितिकी `role` + प्रतिक्रोध तालिका से** | योजना एक साथ 「तीन सेब」 और 「मुर्गी+कीट+कीट」 माँगती है |
| D3 | एक ही रेखा खंड नियम प्राथमिकता: **हाथी > पारिस्थितिकी > समान प्रजाति**; परस्पर अनन्य, दोहरी स्कोरिंग नहीं | एक पंक्ति को दो बार अंक खाने से रोकना |
| D4 | **कृषि उपकरण बोर्ड में नहीं**, केवल HUD कौशल स्लॉट में; पत्थर/पानी के गड्ढे/पेड़ बाधाएँ हैं, आदान-प्रदान योग्य नहीं | योजना का अनुभाग 5 टुकड़ा लाइब्रेरी से टकराता है, कौशल + बाधा को मानक मानें |
| D5 | **डोमेन तर्क शून्य Three.js निर्भरता**, शुद्ध फ़ंक्शन + स्नैपशॉट; प्रस्तुति परत केवल इवेंट सब्सक्राइब करती है | नियम एकाकी परीक्षण योग्य, रीप्ले योग्य, भविष्य में सर्वर-सत्यापन योग्य |
| D6 | शुरुआत `session_id` से **निर्धारणात्मक RNG seed** व्युत्पन्न; गिरना/रीफ़िल सभी इसी RNG से | एक ही seed से पुनरावलोकन संभव; एंटी-चीट के लिए अंतर छोड़ना |
| D7 | कोई भौतिकी इंजन नहीं। विस्थापन/उछाल/विलोपन के लिए सुचारु एनीमेशन, Cannon/Rapier नहीं लाया जाता | योजना में 「सिम्युलेटेड एनीमेशन」 लिखा है; ग्रिड गेम के लिए भौतिकी का कोई लाभ नहीं |
| D8 | कैमरा **ऑर्थोग्राफ़िक 2.5D निश्चित स्थिति**, ट्रैक नियंत्रण बंद | योजना के अनुरूप, गलत संचालन और चक्कर से बचाव |
| D9 | प्रजातियाँ **समान ज्यामिति टेम्पलेट + रंग/सहायक भाग** साझा करती हैं, हर फ़सल के लिए अलग मॉडल नहीं | ट्रैफ़िक और समय; दृश्य भिन्नता रंग संयोजन और एक विशिष्ट भाग से |
| D10 | स्तर प्रवेश `SelfProvider::bet` से, पास होने पर `settle`, बीच में असफल होने पर प्रवेश शुल्क वापस नहीं; पहला कदम न उठाने पर `refund` संभव | प्लेटफ़ॉर्म वॉलेट और round शक्ति-समानता से संरेखित |

## 1. सिस्टम संदर्भ

```
Flutter / HarmonyOS / PC Web
        │  POST /api/game/launch { game_id }
        ▼
service/ (webman :8788)
  GameController::launch  → session_id + seed + api_endpoint
  SelfProvider            → bet / settle / refund / getBalance
  GamePlayLog + EventBus  → game.played / उपलब्धियाँ / VIP
        │  api_endpoint?session_id=&token= खोलें
        ▼
game/xiaoxiaole/  (स्थिर संसाधन, Nginx)
  Vite + TypeScript + Three.js
  डोमेन इंजन ──इवेंट──► रेंडर / HUD
  PlatformAdapter ──HMAC/JWT──► /api/provider/*
```

गेम एक **स्थिर फ्रंटएंड** है, आधिकारिक सत्र और धन `service/` में हैं। क्लाइंट बोर्ड स्थिति रखता है; सर्वर शेष राशि और round शक्ति-समानता रखता है। पहले चरण में प्रति-कदम सर्वर सत्यापन नहीं, लेकिन डोमेन परत निर्धारणात्मक होनी चाहिए, ताकि दूसरे चरण में `seed + संचालन अनुक्रम` सर्वर पर भेजकर पुनर्गणना की जा सके।

## 2. क्लाइंट परतें

ऊपर से नीचे, क्रॉस-परत उल्टी निर्भरता निषिद्ध (`render` को `domain` द्वारा import नहीं किया जा सकता)।

```
app/          असेंबली, स्टेट मशीन, स्तर जीवनचक्र
hud/          HTML Overlay: स्कोर, कदम, लक्ष्य, कौशल, परिणाम
platform/     launch पैरामीटर, वॉलेट, play-log, फ़ीचर स्विच
render/       Three.js: दृश्य, बोर्ड, टुकड़ा ग्रिड, इनपुट, VFX
runtime/      कमांड बस, एनीमेशन कतार, रीप्ले
domain/       बोर्ड, मैचिंग, प्रतिक्रोध, गुरुत्व, स्कोर, सूची, स्तर नियम
config/       प्रतिक्रोध तालिका, रीफ़िल भार, ज्यामिति व्यंजन, स्तर JSON
```

**मुख्य लूप (rules `requestAnimationFrame` में नहीं गिने जाते)**: इनपुट → कमांड → डोमेन सिंक निपटान (एक swap में सभी श्रृंखलाएँ गणना करके इवेंट सूची उत्पन्न करता है) → रनटाइम इवेंट के अनुसार एनीमेशन कतार में बजाता है → एनीमेशन समाप्त होने पर ही अगला इनपुट स्वीकार।

इस तरह 「तर्क एक फ़्रेम, प्रस्तुति कई फ़्रेम」, combo क्लिक के साथ स्थिति छीनने की होड़ नहीं करता।

## 4. डोमेन मॉडल

### 4.1 टुकड़ा परिभाषा (इकाइयों की सूची)

```
PieceDef
  id            speciesId        जैसे wheat, hen, elephant
  faction       Faction          crop | veg | fruit | flora | insect | poultry | livestock | tree | tool | obstacle | apex
  role          Role             plant | prey | predator_mid | predator_high | apex | obstacle | skill
  tags[]                         crop, edible_by_poultry, tree_seedling, bone …
  rarity        common | rare | legendary
  template      GeometryTemplate ज्यामिति टेम्पलेट नाम
  tint          RGB              टेम्पलेट के भीतर रंग
  accessory     optional         चोंच, पंखुड़ी, सूंड आदि विभेदक भाग
```

योजना में फसल/सब्ज़ी/फल/फूल/कीट/मुर्गीपालन/पशुधन/पेड़ सभी इकाइयों की सूची में आते हैं; **tool ग्रिड में उत्पन्न नहीं होता**। हाथी `rarity = legendary`, `role = apex`।

### 4.2 सेल और बोर्ड

```
Cell
  q, r               स्तंभ, पंक्ति (0–7)
  height             भूभाग ऊँचाई (केवल रेंडर, नियमों में भाग नहीं)
  occupant           PieceInstance | null
  overlay            none | fertilizer | puddle | stone(hp) | tree(hp)
  locked             bool          हाथी उत्सव स्तर: हाथी को हटाया नहीं जा सकता

PieceInstance
  uid, speciesId, def
  special            none | fertilizer_token
```

- **पत्थर / पेड़**: ग्रिड घेरते हैं, आदान-प्रदान योग्य नहीं, गिरकर पार नहीं जा सकते। HP स्तर में देखें।
- **पानी का गड्ढा**: सेल पर रहता है, गुरुत्व को उस सेल से गुज़रने से रोकता है (ऊपर का टुकड़ा गड्ढे से एक सेल ऊपर रुकता है)।
- **उर्वरक**: पारिस्थितिकी विलोपन के बाद उसी सेल पर रहता है; अगली बार उस सेल के विलोपन में स्कोर ×2, फिर गायब।

### 4.3 रीफ़िल पूल (स्तर)

```
SpawnPool
  speciesIds[]       5–8 प्रजातियाँ
  weights[]          species के अनुरूप
  maxApex            डिफ़ॉल्ट 1
  apexUnlock         combo >= 5 पर सिस्टम उत्पन्न करता है, 「swap द्वारा उत्पन्न」 निषिद्ध
```

स्तर केवल इसी पूल से `rng` द्वारा टुकड़े खींचता है। सूची कितनी भी बड़ी हो, बोर्ड की एन्ट्रॉपी नियंत्रित रहती है।

## 5. मुख्य नियम इंजन (कार्यात्मक डिज़ाइन)

### 5.1 संचालन

1. टुकड़ा A पर क्लिक → चयन (उछाल + रूपरेखा)।
2. फिर आसन्न ऑर्थोगोनल सेल B पर क्लिक → आदान-प्रदान प्रयास (तिरछा वर्जित)।
3. फिर गैर-आसन्न / खाली पर क्लिक → फिर चयन या रद्द।
4. आदान-प्रदान के बाद **कोई वैध मैच नहीं** होने पर, वापस बजाएँ, कदम खर्च नहीं।
5. मैच होने पर 1 कदम खर्च, निपटान में प्रवेश।

बाधा सेल आदान-प्रदान लक्ष्य के रूप में चुना नहीं जा सकता। लॉक किए सेल (स्तर नियम) समान।

### 5.2 रेखा खंड स्कैन

प्रत्येक swap के बाद के बोर्ड के लिए:

- क्षैतिज, ऊर्ध्वाधर सतत सेल, लंबाई ≥ 3 एक **run** है।
- एक run केवल एक नियम लागू करता है (D3)।
- कई run प्रतिच्छेद कर सकते हैं (क्लासिक L/T आकार), प्रतिच्छेदी सेल केवल एक बार विलोपित होते हैं।

### 5.3 समान प्रजाति विलोपन

run के भीतर `speciesId` सभी समान, और बाधा नहीं, हाथी विशेषाधिकार अलग से संभाला जाता है।

- 3 विलोपन: आधार स्कोर।
- 4 विलोपन: अतिरिक्त स्कोर, और केंद्र सेल पर **उर्वरक** गिरता है (पारिस्थितिकी उर्वरक के समान overlay)।
- 5 विलोपन: अतिरिक्त स्कोर, कौशल स्लॉट +1 चार्ज (5.7 देखें)।

### 5.4 पारिस्थितिकी विलोपन (प्रतिक्रोध श्रृंखला)

निर्धारण: **ठीक 1 प्रतिक्रोधकर्ता + बाकी सभी उस प्रतिक्रोधकर्ता के शिकार** (3 सेल = 1+2)। शिकारों का समान प्रजाति होना आवश्यक नहीं।

| प्रतिक्रोधकर्ता | शिकार मिलान |
|--------|----------|
| मुर्गी, बत्तख, हंस | faction ∈ {flora, veg, fruit, insect}; **crop (अनाज) शामिल नहीं** |
| कुत्ता | faction = poultry (मुर्गी/बत्तख/हंस/कबूतर आदि) |
| सुअर | faction ∈ {tree, flora, veg, fruit, insect, crop}; **कुत्ता शामिल नहीं** |
| गाय, घोड़ा | faction ∈ {flora, crop} या tag `tree_seedling`; कीट और मांस शामिल नहीं |
| हाथी | 5.5 देखें, यह तालिका नहीं चलती |

प्रभाव:

- पूरा खंड विलोपित, शिकार एनीमेशन बजता है (प्रतिक्रोधकर्ता पहले 「खाता」 है, फिर शिकारों के साथ मैदान छोड़ता है, या प्रतिक्रोधकर्ता रहता है — **पहले चरण में पूरा खंड एक साथ मैदान छोड़ता है**, बचे हुए प्रतिक्रोधकर्ता से गिरावट संतुलन बिगड़ने से बचाव; यदि अनुभव कमज़ोर लगे, दूसरे चरण में 「प्रतिक्रोधकर्ता मैदान पर रहता है」 स्विच में बदलें)।
- आधार पारिस्थितिकी स्कोर समान प्रजाति से अधिक।
- प्रतिक्रोधकर्ता के मूल सेल पर **उर्वरक** उत्पन्न।
- `ecoChainStreak += 1`; एक ही श्रृंखला में कई पारिस्थितिकी केवल एक बार streak गिनती नोड जोड़ती है (पूरे resolve समाप्त होने पर +1, एक बार की गिरावट से कौशल भरने से बचाव)।

**मुर्गी अनाज नहीं खाती**: फसल और मुर्गी एक ही बोर्ड पर रह सकते हैं, लेकिन पारिस्थितिकी run नहीं बना सकते; फसल केवल समान प्रजाति विलोपन से।

### 5.5 हाथी

- पूरे बोर्ड पर अधिकतम 1; रीफ़िल भार अत्यंत कम; केवल `combo >= 5` का पुरस्कार उत्पादन, या स्तर `initialPieces` में डालना।
- run में 1 हाथी + कोई भी 2 गैर-कृषि-उपकरण, गैर-बाधा टुकड़े → ये 3 सेल खाली (विभिन्न फ़ैक्शन हो सकते हैं)।
- हाथी **कृषि उपकरणों को नहीं** हटा सकता (उपकरण बोर्ड पर नहीं, स्वाभाविक रूप से संतुष्ट) और बाधाओं को नहीं (बाधाएँ run में नहीं आतीं)।
- 「हाथी उत्सव」 स्तर: शुरुआत में 1, `locked = true`, मूल सेल से हटाया नहीं जा सकता; शिकार उसके पास swap करके run बनाया जाता है।

### 5.6 श्रृंखला, गुरुत्व, रीफ़िल

```
resolve:
  runs पहचानें
  कोई नहीं → idle
  स्कोर, overlays, hp आसन्न बाधाओं पर लागू करें
  Clear emit करें
  gravity: प्रत्येक स्तंभ नीचे से ऊपर संपीड़ित, stone/tree ठोस बाधाएँ छोड़ें; puddle पार होने से रोकता है
  refill: स्तंभ शीर्ष से SpawnPool के अनुसार टुकड़े भरें (maxApex बाधा के अधीन)
  combo++
  detect पर जाएँ
```

आसन्न विलोपन बाधाओं को HP काटता है: पत्थर हर बार आसन्न समान/पारिस्थितिकी से -1, HP=0 पर टूटता है; पेड़ डिफ़ॉल्ट केवल **कुदाल** या स्तर 「तीन सुअर क्षेत्रीय ढकेलना」 या सुअर पारिस्थितिकी (शिकार में पेड़) से HP कटता है। विध्वंसक स्तर में पेड़ HP=5।

पानी की बाल्टी कौशल: एक सेल का गड्ढा चुनें → overlay हटाएँ, उस स्तंभ में तुरंत एक बार gravity।

### 5.7 कौशल स्लॉट (कृषि उपकरण)

| कौशल | अनलॉक | प्रभाव |
|------|------|------|
| दरांती | लगातार 3 resolve में पारिस्थितिकी | एक पंक्ति या स्तंभ चुनें, उस रेखा के सभी **plant भूमिका** टुकड़े हटाएँ (crop/veg/fruit/flora), कदम नहीं खर्च, चार्ज खर्च |
| कुदाल | वही, या स्तर पूर्व-सेट | पत्थर/पेड़ पर क्लिक, सीधे HP=0 या -3 (स्तर कॉन्फ़िगरेशन) |
| पानी की बाल्टी | स्तर पूर्व-सेट या चार्ज | एक सेल का गड्ढा सुखाएँ |

चार्ज नियम: `ecoResolveCount` 3 पर पहुँचे → स्लॉट +1, गिनती शून्य। स्लॉट सीमा 2। दरांती/कुदाल/बाल्टी कौन से दिखें, स्तर `allowedSkills[]` निर्धारित करता है।

### 5.8 स्कोरिंग

```
same_3     = 10 * n * combo * fertilizerMul
eco        = 25 * n * combo * fertilizerMul
elephant   = 40 * n * combo
skill_clear= 8  * n
obstacle   = 20 * brokenCount
```

`combo` 1 से शुरू, हर श्रृंखला +1, खिलाड़ी के अगले मैन्युअल swap पर रीसेट। उर्वरक केवल 「उस सेल के विलोपन की उस एक बार」 पर काम करता है।

## 8. स्टेट मशीन

```
Boot → Title → Playing
Playing उप-स्थितियाँ:
  Idle → Selected → SwapAnim → ResolveLogic → ClearAnim → GravityAnim → RefillAnim
       ↺ यदि अभी भी मैच हों तो ResolveLogic पर वापस (combo)
       → Idle
  Playing → SkillTargeting → SkillAnim → ResolveLogic
  Playing → Won | Lost → Result → Title | next
  Playing → Paused → Playing
```

गैर-Idle/Selected/SkillTargeting स्थितियों में अवैध इनपुट छोड़ दिए जाते हैं।

**कमांड**: `Select` `Swap` `UseSkill` `Pause` `Quit` `AckResult`  
**इवेंट** (EventLog में लिखे): `Swapped` `RejectedSwap` `Matches` `Cleared` `Fell` `Refilled` `Combo` `SkillUsed` `Won` `Lost`

## 9. प्लेटफ़ॉर्म एकीकरण

पूर्ण इंटरफ़ेस अनुबंध (launch / balance / bet / settle / refund / play-log / फ़ीचर स्विच) के लिए **[api.hi.md](api.hi.md)** देखें। मुख्य बिंदु:

- लॉन्च: `POST /api/game/launch` `session_id, api_endpoint, type=self` लौटाता है, `api_endpoint?session_id=&token=` खोलें।
- वॉलेट: `SelfProvider::bet/settle/refund`, `round_id = session_id + ':' + levelId + ':' + attempt`; डोमेन `seed = hash(session_id + round_id)`।
- फ़ीचर स्विच: `xxl.eco_chain` `xxl.elephant` `xxl.skills` `xxl.entry_bet`, बंद होने पर शुद्ध समान प्रजाति तीन-मैच में बदल जाता है।
- सुरक्षा: पहले चरण में क्लाइंट-आधिकारिक बोर्ड + सर्वर-आधिकारिक वॉलेट, एक round केवल एक बार bet/settle; दूसरे चरण में संचालन अनुक्रम अपलोड कर सर्वर पुनर्गणना।
