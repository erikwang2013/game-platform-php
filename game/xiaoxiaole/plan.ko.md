## 2. V1 범위

**하면 출시인 것:** 네 스테이지 클리어 가능, 세 가지 소거, 스킬과 파괴왕 장애물, H5가 로비에서 열림. 지갑은 끌 수 있음（기능 스위치 `xxl.entry_bet`）.

**명확히 잘라내거나 후순위:** 100종 동시 등장, 농기구를 말로 사용, 물리 엔진, GLTF, 관전, 국내 랭킹, 웅덩이 메인 스테이지, 상성자가 먹고 잔류, 단계별 서버 검증.

## 4. 단계 구분과 의존성

```
P0 동종 3매치 ─────────┐
P1 스테이지 선택과 풍년 ─┼─ P2 생태와 쫓아내기 ─ P3 장애물 농기구 ─ P4 코끼리+지갑 ─ P5 폴리싱
렌더 사판（P0와 병행 가능）┘
```

- P0는 PHP에 의존하지 않음. `?debug=1` 로컬 플레이.
- P1은 지갑에 의존하지 않음.
- P2는 P0의 매칭 스캔 확장에 의존, 조작 방식은 변경 없음.
- P3는 칸 overlay에 의존.
- P4는 플랫폼 기존 `POST /api/game/launch`와 `SelfProvider`에 의존; 게임 측에서 ticket, bet, settle 추가.
- P5는 기능 의존성 없음, 언제든 저사양 스위치 삽입 가능.

## 5. 작업 패키지（인원별）

**A 도메인（UI 없음）**  
도감 JSON → 보드 스냅샷 → 매칭（동종/생태/코끼리）→ 중력 → 스테이지 승패 → 점수. Vitest가 화면보다 먼저.

**B 표현**  
씬, 카메라, 템플릿 10세트 중 3세트 우선 구현（이삭/과일/닭）, Raycaster, 교환과 소거 완급. HUD는 DOM 사용.

**C 스테이지 콘텐츠**  
네 스테이지 JSON: 리젠 풀, 목표, 스텝/시간 제한, 스킬 화이트리스트, 시작 장애물.

**D 플랫폼**  
launch URL 파라미터, 잔액 표시, bet/settle, 실패 환불 정책, play-log 이벤트.

권장 순서: A의 P0 테스트 레드-그린 → B가 스냅샷 연결 → C 풍년 → A 생태 테스트 → C 나머지 세 스테이지 → D.

## 6. 플랫폼 측 변경（P4에서만）

인터페이스 계약은 **[api.md](api.md)** 참조. 플랫폼 측 변경 포인트:

| 항목 | 현황 | 계획 동작 |
|----|------|----------|
| 게임 기록 | `GameController::launch`가 session 기록 | 백오피스에 type=self, api_endpoint가 본 H5를 가리키는 항목 추가 |
| 지갑 | `SelfProvider::bet/settle` 있음 | 게임이 round_id로 호출; 단일 round 보상 상한 설정 |
| 기능 스위치 | `FeatureFlag` 있음 | `xxl.eco_chain` `xxl.elephant` `xxl.skills` `xxl.entry_bet` |
| 정적 호스팅 | Nginx 분배 중 | `/games/xiaoxiaole/`가 빌드 산출물 가리키기 |
| 로비 열기 | Flutter `launchUrl` | endpoint에 `session_id` 붙이기 |

P0–P3은 **PHP 수정 불필요**.

## 7. 리스크

| 리스크 | 영향 | 대책 |
|------|------|------|
| 생태 규칙을 플레이어가 이해 못 함 | 쫓아내기 스테이지 클리어 불가 | 튜토리얼 세 번째 항목; 소거 가능 프리뷰는 P5로 |

| 저사양 기기 프레임 저하 | 체감 | dpr 상한 2; 입자 끄기 가능 |

## 8. 이미 결정（다시 묻지 않음）

- 생태 후 상성자 **함께 퇴장**.
- 쫓아내기 스테이지 **90초 제한 시간**, 스텝 미사용.
- 웅덩이는 네 스테이지 메인 라인에 안 들어감.
- V1은 기능 설계 7절의 그 표만 리젠, 나머지 종은 도감 파일에만.

이 네 가지를 바꾸려면 먼저 `functional-design.md`를 수정한 뒤 코드를 건드리세요.
