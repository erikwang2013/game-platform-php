## 0. قرارات معمارية بالنسبة للخطة

الخطة رؤية للطريقة؛ القرارات التالية تحل تناقض «قابل للعب، قابل للاختبار، قابل لربط المحفظة».

| المعرّف | القرار | السبب |
|----|------|------|
| D1 | **الدليل ≠ قطع نفس اللوحة**. أكثر من 100 نوع هي الدليل والمظهر؛ مجمع الإحياء لكل مرحلة يسحب **5–8 أنواع فقط** | ظهور عشرات الأنواع في 8×8 يكاد يجعل التطابق مستحيلًا |
| D2 | التطابق طبقتان: **من نفس النوع بـ `speciesId`، والبيئي بـ `role` + جدول القهر** | تتطلب الخطة في آنٍ «ثلاث تفاحات» و«دجاجة+حشرة+حشرة» |
| D3 | أولوية قواعد نفس الخط: **الفيل > البيئي > نفس النوع**؛ متنافية، لا نقاط مزدوجة | تجنب احتساب الخط مرتين دفعة واحدة |
| D4 | **الأدوات الزراعية لا تدخل اللوحة**، فقط في فتحات مهارات HUD؛ الحجر/المستنقع/الشجرة عوائق غير قابلة للتبديل | القسم الخامس من الخطة يتعارض مع قطع الشطرنج، نعتمد المهارات + العوائق |
| D5 | **منطق المجال صفر اعتماد على Three.js**، دوال نقية + لقطات؛ طبقة العرض تشترك في الأحداث فقط | القواعد قابلة للاختبار الفردي والتشغيل، ولاحقًا للتحقق على الخادم |
| D6 | من `session_id` في بداية الجولة يُشتق **بذرة RNG حتمية**؛ كل السقوط/الإحياء يمر عبر هذا الـ RNG | نفس البذرة تسمح بإعادة التشغيل؛ وتبقى فجوة لمكافحة الغش |
| D7 | بلا محرك فيزياء. الإزاحة/القفز/الإزالة بـ easing، دون إدخال Cannon/Rapier | الخطة كتبت «محاكاة الرسوم المتحركة»؛ الفيزياء بلا فائدة للعبة شبكية |
| D8 | الكاميرا **إسقاط متعامد 2.5D ثابتة الموضع**، إيقاف التحكم بالمدار | متسق مع الخطة، تفادي سوء التشغيل والدوخة |
| D9 | الأنواع تتشارك **قوالب هندسية للفصائل + ألوان/إكسسوارات**، دون نمذجة منفصلة لكل محصول | حجم العمل والجدول الزمني؛ الفرق البصري عبر الألوان وقطعة مميزة واحدة |
| D10 | دخول المرحلة عبر `SelfProvider::bet`، والاجتياز `settle`، والفشل في المنتصف لا يسترد رسوم الدخول؛ الخروج قبل اتخاذ أول خطوة `refund` | محاذاة محفظة المنصة وقوة idempotency للجولة |

## 1. سياق النظام

```
Flutter / HarmonyOS / PC Web
        │  POST /api/game/launch { game_id }
        ▼
service/ (webman :8788)
  GameController::launch  → session_id + seed + api_endpoint
  SelfProvider            → bet / settle / refund / getBalance
  GamePlayLog + EventBus  → game.played / 成就 / VIP
        │  打开 api_endpoint?session_id=&token=
        ▼
game/xiaoxiaole/  (静态资源，Nginx)
  Vite + TypeScript + Three.js
  领域引擎 ──事件──► 渲染 / HUD
  PlatformAdapter ──HMAC/JWT──► /api/provider/*
```

اللعبة **واجهة أمامية ثابتة**، والجلسة الموثوقة والأموال في `service/`. يحتفظ العميل بحالة اللوحة؛ ويحتفظ الخادم بالرصيد وقوة idempotency للجولة. في المرحلة الأولى لا تُجرى مصادقة كل خطوة على الخادم، لكن يجب أن تكون طبقة المجال حتمية، بحيث يمكن في المرحلة الثانية إرسال `seed + تسلسل العمليات` إلى الخادم لإعادة الحساب.

## 2. طبقات العميل

من الأعلى إلى الأسفل، يمنع الاعتماد العكسي عبر الطبقات (لا يجوز أن تستورد `render` من `domain`).

```
app/          التركيب، آلة الحالة، دورة حياة المرحلة
hud/          تراكب HTML: النقاط، الخطوات، الهدف، المهارات، النتيجة
platform/     معاملات launch، المحفظة، play-log، مفاتيح الميزات
render/       Three.js: المشهد، اللوحة، شبكة القطع، الإدخال، VFX
runtime/      ناقل الأوامر، قائمة الانتظار المتحركة، إعادة التشغيل
domain/       اللوحة، التطابق، القهر، الجاذبية، النقاط، الدليل، قواعد المراحل
config/       جدول القهر، أوزان الإحياء، وصفات الهندسة، JSON المراحل
```

**الحلقة الرئيسية (لا تُحسب القواعد داخل `requestAnimationFrame`)**: إدخال ← أمر ← تسوية متزامنة للمجال (تسوية كل السلسلة في swap واحد، وتُنتج قائمة أحداث) ← وقت التشغيل يصطف الرسوم المتحركة حسب الأحداث ← لا يُقبل إدخال جديد إلا بعد انتهاء الحركات.

هكذا «منطق إطار واحد، عرض عدة إطارات»، فلا تتنافس الـ combo مع النقر على الحالة.

## 4. نموذج المجال

### 4.1 تعريف القطع (الدليل)

```
PieceDef
  id            speciesId        مثل wheat, hen, elephant
  faction       Faction         crop | veg | fruit | flora | insect | poultry | livestock | tree | tool | obstacle | apex
  role          Role            plant | prey | predator_mid | predator_high | apex | obstacle | skill
  tags[]                        crop, edible_by_poultry, tree_seedling, bone …
  rarity        common | rare | legendary
  template      GeometryTemplate  اسم القالب الهندسي
  tint          RGB              الألوان داخل القالب
  accessory     optional        أجزاء مميزة: منقار، بتلات، خرطوم …
```

المحاصيل/الخضروات/الفواكه/الزهور/الحشرات/الدواجن/الماشية/الأشجار في الخطة كلها تدخل الدليل؛ **الأدوات لا تُولَّد في الخلايا**. الفيل `rarity = legendary` و`role = apex`.

### 4.2 الخلايا واللوحة

```
Cell
  q, r                العمود، الصف (0–7)
  height              تموج التضاريس (عرض فقط، لا يشارك في القواعد)
  occupant            PieceInstance | null
  overlay             none | fertilizer | puddle | stone(hp) | tree(hp)
  locked              bool          مرحلة جنون الفيل: الفيل لا يُنقل

PieceInstance
  uid, speciesId, def
  special            none | fertilizer_token
```

- **الحجر / الشجرة**: يشغلا خلية، غير قابلين للتبديل أو السقوط عبرهما. HP حسب المرحلة.
- **المستنقع**: يتراكب على الخلية، يقطع الجاذبية عبر تلك الخلية (تتوقف القطع فوقه بخلية واحدة).
- **السماد**: يبقى في الخلية بعد إزالة بيئية؛ النتيجة ×2 لأول إزالة تشارك فيها تلك الخلية لاحقًا، ثم يختفي.

### 4.3 مجمع الإحياء (المرحلة)

```
SpawnPool
  speciesIds[]       5–8 أنواع
  weights[]          بمحاذاة الأنواع
  maxApex            الافتراضي 1
  apexUnlock         عند combo >= 5 يولده النظام، ويمنع «التوليد بالتبديل»
```

تسحب المرحلة فقط من هذا المجمع عبر `rng`. مهما كبر الدليل، تظل إنتروبيا اللوحة قابلة للضبط.

## 5. محرك القواعد الأساسي (تصميم الوظائف)

### 5.1 العمليات

1. النقر على قطعة A ← تحديد (قفزة + إطار).
2. النقر على خلية B متعامدة مجاورة ← محاولة التبديل (التبديل القطري ممنوع).
3. النقر على خلية غير مجاورة / فارغة ← تغيير التحديد أو إلغاؤه.
4. بعد التبديل إذا **لم يوجد أي تطابق قانوني**، تُشغَّل حركة الإرجاع دون استهلاك خطوة.
5. إذا وُجد تطابق يُستهلك خطوة واحدة ويدخل التسوية.

لا يمكن اختيار الخلايا العائقية كهدف للتبديل. وكذلك الخلايا المغلقة (قواعد المرحلة).

### 5.2 مسح الخطوط

لكل لوحة بعد swap:

- الخلايا المتتالية أفقيًا وعموديًا، الطول ≥ 3 هو **run**.
- يطبَّق على الـ run الواحد قاعدة واحدة فقط (D3).
- يمكن أن تتقاطع عدة runs (شكل L/T الكلاسيكي)، والخلايا المتقاطعة تُزال مرة واحدة فقط.

### 5.3 إزالة نفس النوع

داخل الـ run كل `speciesId` متطابق، وغير عائق، وغير معاملة خاصة للفيل.

- 3 إزالة: نقاط أساسية.
- 4 إزالة: نقاط إضافية، ويسقط **سماد** في الخلية المركزية (نفس overlay سماد البيئي).
- 5 إزالة: نقاط إضافية، وشحن +1 لفتحة المهارة (انظر 5.7).

### 5.4 الإزالة البيئية (سلسلة القهر)

التحديد: **قاهر واحد بالضبط + بقية الخلايا كلها فرائس ذلك القاهر** (3 خلايا أي 1+2). لا يُشترط أن تكون الفرائس من نفس النوع.

| القاهر | تطابق الفريسة |
|--------|----------|
| الدجاج، البط، الإوز | faction ∈ {flora, veg, fruit, insect}؛ **بدون crop (الحبوب الخمس)** |
| الكلب | faction = poultry (دجاج وبط وإوز وحمام إلخ) |
| الخنزير | faction ∈ {tree, flora, veg, fruit, insect, crop}؛ **بدون الكلب** |
| البقر، الحصان | faction ∈ {flora, crop} أو tag `tree_seedling`؛ بدون حشرات ولحوم |
| الفيل | انظر 5.5، لا يسير عبر هذا الجدول |

التأثيرات:

- إزالة كامل المقطع، تشغيل حركة الافتراس (القاهر «يأكل» أولًا، ثم يغادر مع الفرائس، أو يبقى القاهر — **في المرحلة الأولى يغادر المقطع كاملًا موحدًا**، تفاديًا لاختلال توازن السقوط ببقاء القاهر؛ إذا ضعفت التجربة، تُغيَّر في المرحلة الثانية إلى مفتاح «بقاء القاهر»).
- النقاط البيئية الأساسية أعلى من نفس النوع.
- خلية القاهر الأصلية تولد **سمادًا**.
- `ecoChainStreak += 1`؛ في نفس السلسلة تُضاف الإزالات البيئية المتعددة عقدة streak واحدة فقط (تُزاد +1 عند انتهاء resolve كامل، تجنبًا لملء المهارة من سقوط واحد).

**الدجاج لا يأكل الحبوب**: يمكن للمحاصيل والدجاج التواجد في نفس اللوحة، لكن لا يشكلان run بيئيًا؛ المحاصيل تُزال فقط بنفس النوع.

### 5.5 الفيل

- في اللوحة كلها فيل واحد كحد أقصى؛ وزن إحياء منخفض جدًا؛ يتولد فقط كمكافأة عند `combo >= 5`، أو توضعه `initialPieces` في المرحلة.
- run يحتوي فيلًا واحدًا + أي قطعتين غير أدوات وغير عوائق ← مسح هذه الخلايا الثلاث (يمكن أن تشمل فصائل مختلفة).
- الفيل **لا** يزيل الأدوات (الأدوات ليست في اللوحة، متحققة طبيعيًا) ولا العوائق (العوائق لا تدخل الـ run).
- مرحلة «جنون الفيل»: فيل واحد في البداية، `locked = true`، لا يُنقل من خليته الأصلية؛ الفرائس تُنقل بجانبه لتشكيل run.

### 5.6 السلسلة والجاذبية والإحياء

```
resolve:
  detect runs
  if none → idle
  apply scores, overlays, hp  على العوائق المجاورة
  emit Clear
  gravity: كل عمود يُرص من الأسفل للأعلى، يتجاوز العوائق الصلبة stone/tree؛ المستنقع يقطع العبور
  refill: من أعلى العمود يُعوَّض حسب SpawnPool (مقيد بـ maxApex)
  combo++
  goto detect
```

الإزالة المجاورة تخصم HP من العوائق: الحجر -1 لكل إزالة مجاورة بنفس النوع/بيئية، وعند HP=0 يتفتت؛ الشجرة افتراضيًا لا يخصم HP إلا **المعزقة** أو «قوس نطح الخنازير الثلاثة» في المرحلة أو إزالة خنزير بيئية (فريسة فيها شجرة). في مرحلة مدمر السدود شجرة HP=5.

مهارة الدلو: اختيار خلية مستنقع ← مسح الـ overlay، وتنفيذ gravity فورًا لذلك العمود.

### 5.7 فتحة المهارة (الأدوات)

| المهارة | الفتح | التأثير |
|------|------|------|
| المنجل | 3 مرات resolve متتالية فيها بيئي | النقر على صف أو عمود، يمسح كل قطع **دور plant** في ذلك الخط (crop/veg/fruit/flora)، بلا استهلاك خطوة، يستهلك الشحن |
| المعزقة | نفسه، أو مرحلة معدّة مسبقًا | النقر على حجر/شجرة، HP=0 مباشرة أو -3 (إعداد المرحلة) |
| الدلو | مرحلة معدّة أو شحن | تجفيف خلية مستنقع |

قاعدة الشحن: عند بلوغ `ecoResolveCount` العدد 3 ← الفتحة +1، ويُصفَّر العداد. سقف الفتحات 2. يحدد `allowedSkills[]` في المرحلة أيٌّ من المنجل/المعزقة/الدلو يظهر.

### 5.8 التسجيل

```
same_3     = 10 * n * combo * fertilizerMul
eco        = 25 * n * combo * fertilizerMul
elephant   = 40 * n * combo
skill_clear= 8  * n
obstacle   = 20 * brokenCount
```

`combo` يبدأ من 1، +1 مع كل سلسلة، وتصفره عملية swap يدوية تالية للاعب. السماد يؤثر فقط على «الإزالة التي تشارك فيها تلك الخلية».

## 6. وظائف المراحل

| المرحلة | المجمع | الفوز | الخسارة | الميزة |
|------|----|------|------|------|
| الحصاد | crop/veg/fruit + وزن عالٍ للدواجن | إزالة 50 قطعة plant في 20 خطوة | نفاد الخطوات | الدجاج والبط والإوز تعيق إزالة النباتات بنفس النوع |
| الطرد | poultry + dog، بلا نباتات | خلال الوقت المحدد إزالة 15 دجاجة/بطّة عبر إزالة الكلب البيئية | انتهاء الوقت | إزالة الدواجن بنفس النوع لا تحسب في الهدف، يجب بيئيًا |
| مدمر السدود | نباتات + خنازير قليلة + 3 أشجار (HP5) | الخنازير تنطح الأشجار الثلاثة | نفاد الخطوات | ثلاثة خنازير على خط واحد تفعّل **نطح 3×3** (قاعدة مرحلة، ليست عامة) |
| جنون الفيل | مجمع مختلط + فيل مقفل في البداية | إزالة 30 قطعة بقاعدة الفيل | إخراج الفيل شاذًا (لا ينبغي حدوثه) أو نفاد الخطوات | حماية الفيل؛ النظام لا يُحيي فيلًا ثانيًا |

HUD عام: تقدم الهدف، الخطوات أو العد التنازلي، combo، فتحة المهارة، إيقاف مؤقت/خروج.

تُحسم نتيجة الفوز/الخسارة بعد انتهاء resolve واحد (يشمل كل حركات السلسلة)، تفاديًا للحكم الخاطئ أثناء الحركة.

## 7. طبقة عرض Three.js

| الوحدة | المسؤولية |
|------|------|
| SceneRoot | WebGLRenderer، تعيين درجة اللون، resize، حد dpr 2 |
| CameraRig | OrthographicCamera، إمالة حوالي 45°، lookAt مركز اللوحة، حظر OrbitControls |
| Lights | Directional (شمس) + Hemisphere (بيئة) + Rim ضعيف؛ بلا ظلال لحظية أو اللوحة فقط تستقبل ظلًا منخفض الدقة |
| BoardView | قطع أرضية 8×8؛ تموج Y عبر خريطة ارتفاع perlin مخبوزة مسبقًا (الخلايا المنطقية تبقى مسطحة) |
| PieceFactory | تجميع Group حسب `template`: كرة/أسطوانة/مخروط/مكعب؛ MeshPhongMaterial؛ تجمع كائنات |
| InputRaycaster | يصيب شبكات القطع في `Idle/Selected` فقط |
| VFX | إطار التحديد (حلقة توهج مرسومة ذاتيًا، المرحلة الأولى بلا OutlinePass بملء الشاشة)؛ التبديل GSAP؛ الإزالة scale + جسيمات Points؛ حبوب اللقاح/اليراعات عبر Points قليلة دورية |
| HUD | DOM، خارج WebGL، لتسهيل i18n وإمكانية الوصول |

القوالب الهندسية (D9): `grain` `produce` `fruit` `flower` `bug` `bird` `beast` `tree` `apex` `rock`. الدليل يغير فقط tint وaccessory.

ميزانية الأداء: 64 قطعة + أرضيات < 200 draw call (دمج الأرضيات قدر الإمكان)؛ جسيمات < 400؛ الأجهزة الضعيفة تعطّل الجسيمات والتموج.

## 8. آلة الحالة

```
Boot → Title → Playing
حالات Playing الفرعية:
  Idle → Selected → SwapAnim → ResolveLogic → ClearAnim → GravityAnim → RefillAnim
       ↺ إذا بقي تطابق يرجع إلى ResolveLogic (combo)
       → Idle
  Playing → SkillTargeting → SkillAnim → ResolveLogic
  Playing → Won | Lost → Result → Title | next
  Playing → Paused → Playing
```

تُهمَل الإدخالات غير القانونية خارج Idle/Selected/SkillTargeting.

**الأوامر**: `Select` `Swap` `UseSkill` `Pause` `Quit` `AckResult`
**الأحداث** (تُكتب في EventLog): `Swapped` `RejectedSwap` `Matches` `Cleared` `Fell` `Refilled` `Combo` `SkillUsed` `Won` `Lost`

## 9. ربط المنصة

عقد الواجهات الكامل (launch / balance / bet / settle / refund / play-log / مفاتيح الميزات) في **[api.md](api.md)**. النقاط الأساسية:

- الإقلاع: `POST /api/game/launch` يعيد `session_id, api_endpoint, type=self`، وفتح `api_endpoint?session_id=&token=`.
- المحفظة: `SelfProvider::bet/settle/refund`، و`round_id = session_id + ':' + levelId + ':' + attempt`؛ ومجال `seed = hash(session_id + round_id)`.
- مفاتيح الميزات: `xxl.eco_chain` `xxl.elephant` `xxl.skills` `xxl.entry_bet`، عند الإغلاق تتدهور إلى مطابقة ثلاثية نقية.
- الأمان: المرحلة الأولى لوحة موثوقة من العميل + محفظة موثوقة من الخادم، والجولة الواحدة bet/settle مرة واحدة فقط؛ المرحلة الثانية رفع تسلسل العمليات وإعادة الحساب على الخادم.

## 10. غير الوظيفية

| البند | المؤشر |
|----|------|
| الشاشة الأولى | مضلعات منخفضة + بلا GLTF، هدف التفاعل خلال 3 ثوانٍ (يشمل gzip Vite) |
| معدل الإطارات | سطح المكتب 60fps؛ البطاقات المدمجة يمكنها إيقاف VFX |
| الاختبار | `domain/**` يغطي التطابق/الجاذبية/القهر/الفوز والخسارة باختبارات فردية؛ لا يُختبر WebGL |
| i18n | مفاتيح نصوص HUD، تتبع وسيطة `Language` الخاصة بالمنصة |
| إمكانية الوصول | اختيار بلوحة المفاتيح + Enter للتبديل (المرحلة الثانية)؛ عمى الألوان: قوالب الشكل أولوية على اللون الخالص |
| الحجم | بدون FBX؛ السعي بعد gzip لـ three + gsap إلى < 250KB كود |
