## 1. 3つのドキュメントの使い分け

| ドキュメント | 答える問い | 答えないこと |
|------|------------|--------|
| `design.md` | 田園テーマ、克制幻想、3D の雰囲気 | 単关で何種リフレッシュするか、受け入れ条件 |
| `functional-design.md` | プレイヤーが何をクリックするか、どう勝ちを決めるか、V1 に誰が出るか | ディレクトリの切り方、物理エンジンを使うか |
| `architecture.md` | 層構造、モジュール、プラットフォームのウォレット、決定論的 RNG | 90 秒か 20 手か（機能設計で決定済み） |

開発は後ろの2つだけを正とします；ビジョンと後ろの2つが衝突したら、後ろの2つを優先します（決定済みの例外は機能設計の第 12 節に記載）。

## 2. V1 の範囲

**完了＝リリース：** 四关をクリア可能、3種類の消去、スキルと破壊王の障害、H5 を大厅から開ける。ウォレットはオフ可（フィーチャーフラグ `xxl.entry_bet`）。

**明確に削除または後回し：** 100 種が同時に盤上に、農具を駒として、物理エンジン、GLTF、観戦、局内ランキング、水たまりのメイン关、克制者が食べた後残る、毎手のサーバー側検証。

## 4. 分期と依存

```
P0 同種三消 ─────────┐
P1 选关と豊穣 ───────┼─ P2 生態と追い払い ─ P3 障害農具 ─ P4 象+ウォレット ─ P5 仕上げ
レンダリングサンドボックス（P0 と並行可）┘
```

- P0 は PHP に依存しない。`?debug=1` でローカル再生。
- P1 はウォレットに依存しない。
- P2 は P0 のマッチングスキャンの拡張に依存、操作方式は変えない。
- P3 は格子 overlay に依存。
- P4 はプラットフォーム既存の `POST /api/game/launch` と `SelfProvider` に依存；ゲーム側に ticket、bet、settle を追加。
- P5 は機能依存なし、いつでも低性能スイッチを挿入可能。

## 5. ワークパッケージ（担当別）

**A 領域（画面なし）**
図鑑 JSON → 盤面スナップショット → マッチング（同種/生態/象）→ 重力 → 关卡勝敗 → スコア。Vitest を画面より先に。

**B 表現**
シーン、カメラ、10 テンプレートのうち最初に 3 つ（穀穂/果物/鶏）、Raycaster、交換と消去のイージング。HUD は DOM。

**C 关卡コンテンツ**
四关 JSON：リフレッシュプール、目標、手数/制限時間、スキルホワイトリスト、開局障害。

**D プラットフォーム**
launch URL パラメータ、残高表示、bet/settle、失敗時の返金方針、play-log イベント。

推奨順序：A の P0 テストを赤→緑 → B がスナップショットに接続 → C 豊穣 → A の生態テスト → C の残り三关 → D。

## 6. プラットフォーム側の変更（P4 で実施）

インターフェース契約は **[api.md](api.md)** を参照。プラットフォーム側の変更点：

| 項目 | 現状 | 計画アクション |
|----|------|----------|
| ゲーム記録 | `GameController::launch` が session を書き込み済み | バックエンドに type=self、api_endpoint が本 H5 を指すレコードを追加 |
| ウォレット | `SelfProvider::bet/settle` は既存 | ゲームが round_id で呼び出し；単 round の賞金上限を設定 |
| フィーチャーフラグ | `FeatureFlag` は既存 | `xxl.eco_chain` `xxl.elephant` `xxl.skills` `xxl.entry_bet` |
| 静的ホスティング | Nginx が配信済み | `/games/xiaoxiaole/` をビルド成果物に向ける |
| 大厅から開く | Flutter `launchUrl` | endpoint に `session_id` を結合 |

P0–P3 は **PHP を変更する必要がない**。

## 7. リスク

| リスク | 影響 | 対策 |
|------|------|------|
| 生態ルールをプレイヤーが理解できない | 追い払い关をクリアできない | チュートリアル第3条；消去プレビューは P5 に |
| リフレッシュ種類がまだ多い | 消せる駒がない | 単关は上限 8 種に固定 |
| 象が強すぎる | 狂欢が瞬時に空になる | 目標は象ルールのみカウント；盤上は 1 体に固定 |
| クライアントがスコアを改ざんして賞を騙す | ウォレット | P4 の賞金上限；録画検証は後置 |
| 低性能端末のフレーム落ち | 体験 | dpr 上限 2；粒子はオフ可 |

## 8. 決定済み（再質問しない）

- 生態後、克制者も**一緒に退場**。
- 追い払い关は **90 秒制限時間**、手数は使わない。
- 水たまりは四关の本線に入れない。
- V1 は機能設計第 7 節の表のみリフレッシュし、その他の種は図鑑ファイルのみ。

この4つを変えたければ、先に `functional-design.md` を修正してからコードを動かす。
