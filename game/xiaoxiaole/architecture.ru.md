## 0. Архитектурные решения относительно плана

План — это концепция геймплея; нижеприведённые решения разрешают противоречие «играбельно, тестируемо, подключаемо к кошельку».

| ID | Решение | Причина |
|----|------|------|
| D1 | **Галерея ≠ фигуры на доске**. 100+ видов — это галерея и внешний вид; пул уровня берёт только **5–8 видов** | при 8×8 десятки видов одновременно почти невозможно собирать в совпадения |
| D2 | Сопоставление в два слоя: **одинаковые по `speciesId`, экологические по `role` + таблица сдержанности** | план требует одновременно «три яблока» и «курица+насекомое+насекомое» |
| D3 | Приоритет правил одной линии: **слон > экология > один вид**; взаимоисключающе, без двойного начисления очков | избежать начисления очков дважды за одну линию |
| D4 | **Инструменты не попадают на доску**, только в слот навыков HUD; камни/лужи/деревья — препятствия, не подлежат обмену | пятый раздел плана конфликтует с библиотекой фигур; приоритет — навыки + препятствия |
| D5 | **Доменная логика без зависимости от Three.js**, чистые функции + снимки; слой отображения только подписывается на события | правила можно юнит-тестировать, воспроизводить и в будущем проверять на сервере |
| D6 | На старте `session_id` порождает **детерминированный RNG-seed**; выпадение/дозаполнение идут только через этот RNG | один и тот же seed можно воспроизводить; задел против читов |
| D7 | Без физического движка. Перемещение/подскоки/удаление — на easing, без Cannon/Rapier | в плане уже написано «имитационная анимация»; физика для сеточной игры не даёт выгоды |
| D8 | Камера **ортогональная 2.5D, фиксированная**, без управления орбитой | соответствует плану, исключает случайные повороты и укачивание |
| D9 | Виды используют **общий геометрический шаблон фракции + цвет/аксессуары**, без отдельного моделирования каждой культуры | трафик и сроки; визуальные различия — цветом и одной отличительной деталью |
| D10 | Вход на уровень — через `SelfProvider::bet`, прохождение — `settle`, при провале плата не возвращается; до первого хода возможен `refund` | выравнивание с кошельком платформы и идемпотентностью раундов |

## 1. Системный контекст

```
Flutter / HarmonyOS / PC Web
        │  POST /api/game/launch { game_id }
        ▼
service/ (webman :8788)
  GameController::launch  → session_id + seed + api_endpoint
  SelfProvider            → bet / settle / refund / getBalance
  GamePlayLog + EventBus  → game.played / 成就 / VIP
        │  打开 api_endpoint?session_id=&token=
        ▼
game/xiaoxiaole/  (静态资源，Nginx)
  Vite + TypeScript + Three.js
  领域引擎 ──事件──► 渲染 / HUD
  PlatformAdapter ──HMAC/JWT──► /api/provider/*
```

Игра — это **статический фронтенд**: авторитетная сессия и деньги находятся в `service/`. Клиент хранит состояние доски; сервер хранит баланс и идемпотентность раундов. В первой фазе серверной валидации каждого хода нет, но слой домена обязан быть детерминированным, чтобы во второй фазе отправлять `seed + последовательность операций` на сервер для пересчёта.

## 2. Слои клиента

Сверху вниз, запрещены обратные зависимости между слоями (`render` не должен импортироваться из `domain`).

```
app/          组装、状态机、关卡生命周期
hud/          HTML Overlay：分数、步数、目标、技能、结果
platform/     launch 参数、钱包、play-log、特性开关
render/       Three.js：场景、棋盘、棋子网格、输入、VFX
runtime/      命令总线、动画队列、回放
domain/       棋盘、匹配、克制、重力、分数、目录、关卡规则
config/       克制表、刷新权重、几何配方、关卡 JSON
```

**Главный цикл (правила не считаются в `requestAnimationFrame`)**: ввод → команда → синхронный расчёт домена (одна swap обрабатывает все каскады, порождая список событий) → runtime ставит анимации в очередь по событиям → следующее действие принимается только после завершения анимаций.

Так «один кадр логики, много кадров отображения» — combo не конкурирует с кликами за состояние.

## 4. Доменная модель

### 4.1 Определение фигуры (галерея)

```
PieceDef
  id            speciesId        如 wheat, hen, elephant
  faction       Faction          crop | veg | fruit | flora | insect | poultry | livestock | tree | tool | obstacle | apex
  role          Role             plant | prey | predator_mid | predator_high | apex | obstacle | skill
  tags[]                         crop, edible_by_poultry, tree_seedling, bone …
  rarity        common | rare | legendary
  template      GeometryTemplate 几何模板名
  tint          RGB              模板内配色
  accessory     optional         喙、花瓣、象鼻等区分件
```

Культуры/овощи/фрукты/цветы/насекомые/птица/скот/деревья из плана — все попадают в галерею; **tool не генерируется в клетки**. У слона `rarity = legendary`, `role = apex`.

### 4.2 Клетка и доска

```
Cell
  q, r               列、行（0–7）
  height             地形起伏（仅渲染，不参与规则）
  occupant           PieceInstance | null
  overlay            none | fertilizer | puddle | stone(hp) | tree(hp)
  locked             bool          大象狂欢关：大象不可被换走

PieceInstance
  uid, speciesId, def
  special            none | fertilizer_token
```

- **Камень / дерево**: занимают клетку, не обмениваются, сквозь них не падают. HP задаётся уровнем.
- **Лужа**: лежит на клетке, блокирует прохождение гравитации через эту клетку (фигура сверху останавливается на клетку выше).
- **Удобрение**: остаётся на клетке после экологического удаления; следующее удаление с участием этой клетки даёт очки ×2, затем исчезает.

### 4.3 Пул выпадения (уровень)

```
SpawnPool
  speciesIds[]       5–8 个
  weights[]          与 species 对齐
  maxApex            默认 1
  apexUnlock         combo >= 5 时由系统生成，禁止「交换生成」
```

Уровень тянет фигуры только из своего пула через `rng`. Как бы ни была велика галерея, энтропия доски управляема.

## 5. Ядро правил (функциональный дизайн)

### 5.1 Операции

1. Клик по фигуре A → выделение (подскок + обводка).
2. Клик по соседней ортогональной клетке B → попытка обмена (диагональ запрещена).
3. Клик по несмежной/пустой клетке → смена выбора или отмена.
4. Если после обмена **нет ни одного легального совпадения** — фигуры возвращаются, шаг не тратится.
5. Есть совпадение — тратится 1 шаг, вход в расчёт.

Клетка с препятствием не может быть целью обмена. Заблокированные клетки (правила уровня) — аналогично.

### 5.2 Сканирование линий

Для каждой доски после swap:

- Горизонтальные и вертикальные непрерывные клетки длиной ≥ 3 образуют **run**.
- Один run применяет только одно правило (D3).
- Несколько run могут пересекаться (классические L/T-формы); пересекающаяся клетка удаляется только один раз.

### 5.3 Удаление одного вида

Внутри run `speciesId` полностью одинаков, не препятствие, без особого режима слона.

- 3-удаление: базовые очки.
- 4-удаление: дополнительные очки, в центральной клетке выпадает **удобрение** (тот же overlay, что у экологического).
- 5-удаление: дополнительные очки, слот навыка +1 заряд (см. 5.7).

### 5.4 Экологическое удаление (цепочка сдержанности)

Условие: **ровно 1 сдерживающий + все остальные — его добыча** (3 клетки = 1+2). Добыча не обязана быть одного вида.

| Сдерживающий | Совпадение с добычей |
|--------|----------|
| Курица, утка, гусь | faction ∈ {flora, veg, fruit, insect}；**не crop（зерновые）** |
| Собака | faction = poultry（куры/утки/гуси/голуби и т.п.） |
| Свинья | faction ∈ {tree, flora, veg, fruit, insect, crop}；**не собака** |
| Корова, лошадь | faction ∈ {flora, crop} 或 tag `tree_seedling`；без насекомых и мяса |
| Слон | см. 5.5, вне этой таблицы |

Эффект:

- Удаляется весь сегмент, проигрывается анимация охоты (сдерживающий сначала «ест», затем уходит вместе с добычей, или остаётся — **в первой фазе единообразно уходит весь сегмент**, чтобы остатки не ломали баланс выпадения; если ощущение слабое — во второй фазе включить переключатель «сдерживающий остаётся»).
- Базовая экологическая оценка выше, чем у одного вида.
- На исходной клетке сдерживающего генерируется **удобрение**.
- `ecoChainStreak += 1`; несколько экологических удалений в одном каскаде добавляют лишь один узел отсчёта streak (одно +1 по завершении всего resolve, чтобы одна серия выпадений не заполняла навык).

**Курица не ест зерновые**: культуры и куры могут быть на одной доске, но не образуют экологический run; культуры удаляются только как один вид.

### 5.5 Слон

- На доске одновременно максимум 1; вес выпадения крайне низкий; только награда при `combo >= 5` или через `initialPieces` уровня.
- Run из 1 слона + любые 2 неинструментальных, не-препятственных фигуры → очищает эти 3 клетки (допустимы разные фракции).
- Слон **не** удаляет инструменты (их нет на доске — выполняется само собой) и препятствия (препятствия не входят в run).
- Уровень «Слоновий карнавал»: на старте 1 слон, `locked = true`, его нельзя поменять с исходной клетки; добычу подводят к нему обменами, образуя run.

### 5.6 Каскад, гравитация, дозаполнение

```
resolve:
  detect runs
  if none → idle
  apply scores, overlays, hp 对相邻障碍
  emit Clear
  gravity: 每列从底向上压实，跳过 stone/tree 实心障碍；puddle 阻断穿过
  refill: 从列顶按 SpawnPool 补子（受 maxApex 约束）
  combo++
  goto detect
```

Соседние удаления наносят HP препятствиям: камень за каждое соседнее удаление одного вида/экологическое -1, при HP=0 разлетается; дерево по умолчанию получает HP-урон только от **мотыги**, «свиного 3×3 арка» уровня или свиной экологии (добыча содержит дерево). В уровне «Разрушитель» у дерева HP=5.

Навык ведра: выбор клетки с лужей → overlay очищается, в этом столбце сразу выполняется одна гравитация.

### 5.7 Слоты навыков (инструменты)

| Навык | Разблокировка | Эффект |
|------|------|------|
| Серп | 3 последовательных resolve с экологией | клик по строке или столбцу очищает все фигуры с ролью **plant** (crop/veg/fruit/flora) на этой линии, без траты шага, расход заряда |
| Мотыга | то же, или пресет уровня | клик по камню/дереву: сразу HP=0 или -3 (по конфигу уровня) |
| Ведро | пресет уровня или заряд | осушает одну лужу |

Зарядка: `ecoResolveCount` достигает 3 → слот +1, счётчик обнуляется. Максимум слотов 2. Какие из серпа/мотыги/ведра доступны, определяет `allowedSkills[]` уровня.

### 5.8 Начисление очков

```
same_3     = 10 * n * combo * fertilizerMul
eco        = 25 * n * combo * fertilizerMul
elephant   = 40 * n * combo
skill_clear= 8  * n
obstacle   = 20 * brokenCount
```

`combo` начинается с 1, +1 за каждый каскад, сбрасывается при следующем ручном swap игрока. Удобрение действует только на «то самое удаление» этой клетки.

## 6. Функции уровней

| Уровень | Пул | Победа | Поражение | Особенность |
|------|----|------|------|------|
| Урожай | crop/veg/fruit + высокий вес poultry | устранить 50 plant за 20 шагов | кончились шаги | куры/утки/гуси мешают собирать растения одного вида |
| Выгон | poultry + dog, без растений | за время убрать 15 кур/уток экологией собаки | таймаут | удаление птицы одного вида не идёт в цель, нужна только экология |
| Разрушитель | растения + немного pig + 3 дерева (HP5) | свиньи валят 3 дерева | кончились шаги | три свиньи в линию триггерят **арку 3×3** (правило уровня, не глобальное) |
| Слоновий карнавал | смешанный пул + стартовый зафиксированный слон | удалить 30 фигур правилом слона | слон аномально перемещён (не должно случаться) или кончились шаги | защищать слона; система не спавнит второго |

Общий HUD: прогресс цели, шаги или отсчёт, combo, слоты навыков, пауза/выход.

Итог победы/поражения подводится после завершения всего resolve (со всеми каскадными анимациями), чтобы не ошибаться посреди анимаций.

## 7. Слой отображения Three.js

| Модуль | Обязанности |
|------|------|
| SceneRoot | WebGLRenderer, тон-маппинг, resize, верхний предел dpr 2 |
| CameraRig | OrthographicCamera, наклон ~45°, lookAt центр доски, без OrbitControls |
| Lights | Directional (солнце) + Hemisphere (окружение) + слабый Rim; без теней в реальном времени или только низкое разрешение shadow под доской |
| BoardView | участки 8×8; Y-рельеф — предварительно запечённая карта высот perlin (логические клетки остаются плоскими) |
| PieceFactory | сборка Group по `template`: сфера/цилиндр/конус/куб; MeshPhongMaterial; пул объектов |
| InputRaycaster | попадание в меш фигуры только в состояниях `Idle/Selected` |
| VFX | обводка выделения (саморисующийся светящийся контур, в первой фазе без полноэкранного OutlinePass); обмен на GSAP; удаление scale+частицы Points; пыльца/светлячки — небольшой цикл Points |
| HUD | DOM, не в WebGL, для удобства i18n и доступности |

Шаблоны геометрии (D9): `grain` `produce` `fruit` `flower` `bug` `bird` `beast` `tree` `apex` `rock`. Галерея меняет только tint и accessory.

Бюджет производительности: 64 фигуры + участки < 200 draw call (участки по возможности merge); частицы < 400; на слабых устройствах частицы и рельеф отключаются.

## 8. Конечный автомат

```
Boot → Title → Playing
Playing 子状态:
  Idle → Selected → SwapAnim → ResolveLogic → ClearAnim → GravityAnim → RefillAnim
       ↺ 若仍有匹配则回 ResolveLogic（combo）
       → Idle
  Playing → SkillTargeting → SkillAnim → ResolveLogic
  Playing → Won | Lost → Result → Title | next
  Playing → Paused → Playing
```

Некорректный ввод вне состояний Idle/Selected/SkillTargeting отбрасывается.

**Команды**: `Select` `Swap` `UseSkill` `Pause` `Quit` `AckResult`  
**События** (пишутся в EventLog): `Swapped` `RejectedSwap` `Matches` `Cleared` `Fell` `Refilled` `Combo` `SkillUsed` `Won` `Lost`

## 9. Подключение к платформе

Полный контракт интерфейсов (launch / balance / bet / settle / refund / play-log / функциональные переключатели) — в **[api.ru.md](api.ru.md)**. Ключевое:

- Запуск: `POST /api/game/launch` возвращает `session_id, api_endpoint, type=self`, открывается `api_endpoint?session_id=&token=`.
- Кошелёк: `SelfProvider::bet/settle/refund`, `round_id = session_id + ':' + levelId + ':' + attempt`; доменный `seed = hash(session_id + round_id)`.
- Функциональные переключатели: `xxl.eco_chain` `xxl.elephant` `xxl.skills` `xxl.entry_bet`; при выключении — вырождение в чистый три-в-ряд одного вида.
- Безопасность: в первой фазе клиентская авторитетная доска + серверный авторитетный кошелёк, один раунд — один bet/settle; во второй фазе — загрузка последовательности операций и пересчёт на сервере.

## 10. Нефункциональные требования

| Пункт | Показатель |
|----|------|
| Первый экран | low-poly без GLTF, цель — интерактивность за 3 с (включая gzip через Vite) |
| Частота кадров | 60fps на десктопе; на интегрированной графике можно отключить VFX |
| Тесты | `domain/**` юнит-тесты покрывают совпадения/гравитацию/сдержанность/победу и поражение; WebGL не тестируется |
| i18n | ключи текстов HUD следуют за middleware `Language` платформы |
| Доступность | выбор клавиатурой + Enter для обмена (вторая фаза); дальтонизм: приоритет форм над чистым цветом |
| Объём | без FBX; three + gsap после gzip — постараться < 250KB кода |

## 11. Этапы

| Этап | Объём | Приёмка |
|----|------|------|
| P0 | три-в-ряд одного вида, 8×8, обмен/гравитация/дозаполнение, ортогональная сцена, 3 шаблонных фигуры | можно сыграть партию без цели |
| P1 | галерея + SpawnPool + цели/шаги четырёх уровней, HUD | уровень «Урожай» проходим |
| P2 | таблица сдержанности + экологическое удаление + удобрение + combo | «курица + два насекомых» удаляются; зерновые курицей не удаляются |
| P3 | камень/дерево/лужа + серп/мотыга/ведро | в «Разрушителе» можно сломать дерево |
| P4 | слон + зафиксированные клетки + bet/settle платформы | карнавальный уровень; сверка баланса |
| P5 | частицы, звук, пул объектов, режим слабых устройств, запись | бюджет производительности выполнен |

P0 не подключает кошелёк — достаточно локального `?debug=1`. Только P4 подключает `SelfProvider`.

## 12. Обзор обязанностей модулей
