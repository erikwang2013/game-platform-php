## 1. Дизайн системы валют

### 1.1 Трёхуровневая модель валют

```
第1层: 法币 (USD / CNY / EUR / JPY ...)
       ↕ 充值/提现（按汇率兑换）
第2层: 平台币（统一，精度 decimal(18,4)）
       ↕ 兑换（含汇率 + 平台抽成差价）
第3层: 游戏币（每种游戏独立，独立汇率）
```

### 1.2 Платформенная валюта

- Единая расчётная единица платформы
- Точность: `DECIMAL(18,4)`, минимальная единица 0.0001
- Получается пополнением через фиатную валюту, обменивается на любую игровую валюту
- Игровая валюта также может обмениваться обратно на платформенную, затем выводиться в фиат
- Платформа получает доход с разницы обмена (спреда)

### 1.3 Игровая валюта

- У каждой игры может быть несколько игровых валют (например, монеты, алмазы, очки)
- Для каждой валюты отдельно задаётся курс обмена на платформенную (`exchange_rate`)
- Для каждой валюты отдельно задаётся доля комиссии платформы (`spread_pct`)
- Поддерживается установка минимального/максимального лимита обмена (`min_exchange` / `max_exchange`)

### 1.4 Формулы обмена

**Покупка игровой валюты (платформенная → игровая):**
```
游戏币到账 = 平台币数量 × exchange_rate × (1 - spread_pct / 100)
```

**Продажа игровой валюты (игровая → платформенная):**
```
平台币到账 = 游戏币数量 ÷ exchange_rate × (1 - spread_pct / 100)
```

**Пример:**
- exchange_rate = 100 (1 платформенная = 100 игровых)
- spread_pct = 5% (комиссия платформы 5%)
- Пользователь покупает на 10 платформенных: (10 × 100 × 0.95) = 950 игровых
- Пользователь продаёт 950 игровых: (950 ÷ 100 × 0.95) = 9.025 платформенных
- Доход платформы: 10 - 9.025 = 0.975 платформенных

## 2. Дизайн кошелька

### 2.1 Кошелёк платформенной валюты (game_user_wallet)

Автоматически создаётся при регистрации пользователя, начальный баланс 0.

| Поле | Описание |
|------|------|
| balance | доступный баланс (пополнение/вывод/обмен) |
| frozen_balance | замороженный баланс (зарезервирован, например, при выводе) |
| total_earned | совокупный доход |
| total_spent | совокупные расходы |
| version | номер версии оптимистичной блокировки (+1 при каждом обновлении) |

### 2.2 Кошелёк игровой валюты (game_user_game_wallet)

Уникален по трём измерениям: пользователь + игра + валюта. Автоматически создаётся при первом обмене.

### 2.3 Безопасность параллелизма

Для защиты от проблем конкурентного доступа используется оптимистичная блокировка:

```php
// 更新时检查版本号
$updated = Wallet::where('id', $wallet->id)
    ->where('version', $wallet->version)
    ->update([
        'balance' => bcadd($wallet->balance, $amount, 4),
        'version' => $wallet->version + 1,
    ]);

// 更新失败（版本号已变）→ 重试，最多5次
```

## 3. Дизайн системы вывода средств

### 3.1 Многоуровневый контроль

```
第1层: 全局提现开关
       ├─ 关闭 → 所有提现拒绝，用于紧急风控
       └─ 开启 → 进入第2层检查

第2层: 限额检查
       ├─ 单笔最低金额 (min_amount)
       ├─ 单笔最高金额 (max_amount)
       └─ 每日累计限额 (daily_limit)

第3层: 审核流程
       ├─ 金额 < 自动审核阈值 → 自动通过
       └─ 金额 >= 自动审核阈值 → 人工审核 → 通过/拒绝
```

### 3.2 Конечный автомат вывода

```
pending (待审核)
  ├─→ approved (已通过) → completed (已完成)
  └─→ rejected (已拒绝) → 余额退回 + 退款流水
```

### 3.3 Управление в админ-панели

- **Кнопка глобального переключателя**: одним кликом включить/выключить вывод для всех пользователей
- **Очередь проверки**: отсортированный по времени список ожидающих проверки, кнопки одобрить/отклонить
- **Настройка лимитов**: визуальная настройка параметров лимитов

## 4. Дизайн пополнения

### 4.1 Процесс пополнения

```
1. 用户选择支付方式和金额
2. 平台创建充值订单 (status=pending, 生成唯一 order_no)
3. 跳转第三方支付页面
4. 用户完成支付
5. 第三方回调通知平台 (POST /api/payment/callback)
6. 平台验签 → 更新订单 (status=confirmed)
7. 平台币到账 → 记录流水
```

### 4.2 Платёжные методы

| Тип | Провайдер | Описание |
|------|--------|------|
| Фиат | Stripe | международные кредитные карты |
| Фиат | PayPal | глобальный электронный кошелёк |
| Фиат | Alipay | Alipay (международная версия, через Stripe Checkout APM) |
| Фиат | WeChat Pay | WeChat Pay (международная версия, через Stripe Checkout APM) |
| Криптовалюта | USDT-TRC20 | USDT в сети Tron |

Базовая версия сначала подключает один платёжный метод (например, Stripe), стандартная версия расширяет до всех каналов.

## 5. Дизайн интеграции игр

### 5.1 Саморазработанные игры

Саморазработанные игры интегрируются в платформу напрямую, разделяя систему пользователей и кошельки:

- Игра запрашивает баланс игровой валюты через внутренний API
- Расчёт игры списывает/начисляет игровую валюту через внутренний API
- Дополнительная проверка подписи не требуется

### 5.2 Сторонние игры

Сторонние игры подключаются через SDK/API:

```
平台侧:
  1. 用户点击"进入游戏"
  2. 平台生成签名（user_id + timestamp + api_secret → HMAC-SHA256）
  3. 302跳转或iframe加载游戏URL（携带签名参数）

游戏侧:
  4. 验签 → 建立游戏会话
  5. 查询余额：GET /api/game/balance?user_id=...&sign=...
  6. 结算回调：POST /api/game/callback {user_id, amount, type, sign}
  7. 平台验签 → 更新余额 → 记录流水 → 返回结果
```

### 5.3 Алгоритм подписи

```
signature = HMAC-SHA256(
    secret = api_secret,
    message = user_id + "|" + timestamp + "|" + amount + "|" + nonce,
)
```

Условия проверки:
- Подпись корректна
- Таймстамп в пределах ±60s (защита от replay attack)
- nonce не использовался ранее (записывается в Redis, истекает через 60s)
- IP запроса в белом списке

## Дополнительно. Новый дизайн стандартной версии

### 8.1 Движок риск-контроля

Четыре типа правил:
- `ip_blacklist` — сопоставление с чёрным списком IP, при совпадении — немедленная блокировка
- `amount_anomaly` — детекция крупных сумм, предупреждение при превышении порога
- `frequency` — детекция частоты операций в окне времени
- `velocity` — детекция связей множества аккаунтов за короткое время

Правила выполняются по убыванию priority, результат определяет первое совпавшее правило (block > warn > log).

### 8.2 OAuth-вход через третьи стороны

Поддерживаемые провайдеры: Google, Facebook, Apple

Процесс:
1. Фронтенд запрашивает `GET /api/auth/oauth/{provider}` и получает URL авторизации
2. Пользователь переходит к третьей стороне и завершает авторизацию
3. Колбэк `POST /api/auth/oauth/{provider}/callback` с кодом авторизации
4. Бэкенд находит существующую привязку → вход; привязки нет → автоматическая регистрация + привязка + создание кошелька

### 8.3 Система лимитов KYC

| Уровень | Способ получения | Лимит одной операции | Дневной лимит | Комиссия |
|------|---------|---------|--------|--------|
| default | по умолчанию при регистрации | 1,000 | 10,000 | 1.00% |
| verified | после прохождения KYC | 5,000 | 50,000 | 0.50% |
| vip | присваивается оператором | 20,000 | 200,000 | 0.00% |

### 8.4 Игровые серверы

Для каждой игры можно настроить несколько серверов (region: global/asia/eu/na), статусы сервера: техническое обслуживание / работает / горячий / новый.

### 8.5 Ежедневный статистический снимок

Каждую ночь crontab выполняет `ComputeDailyStats::run()`, рассчитывающий пять показателей:
- Статистика пользователей (новые/активные/всего)
- Статистика пополнений (число операций/общая сумма)
- Статистика выводов (число операций/общая сумма)
- Статистика обменов (число операций/общая сумма комиссий)
- Статистика игр (число игроков/число сессий)

## 9. Функции производственного уровня

### 9.1 Система уведомлений

Типы уведомлений: system/deposit/withdraw/kyc/coupon/announcement

Автоматические сценарии срабатывания:
- Пополнение зачислено → NotificationService::send()
- Проверка вывода одобрена/отклонена → автоматическое уведомление
- Проверка KYC одобрена/отклонена → автоматическое уведомление
- Получение купона → автоматическое уведомление
- Зачисление реферальной награды → автоматическое уведомление

Поддерживаются два канала: внутренние сообщения + email (для email требуется переменная окружения MAIL_HOST).

### 9.2 Реферальные вознаграждения

```
用户A 生成推荐码 → 分享给用户B
用户B 注册时填写推荐码 → 双方各得注册奖励(signup_reward)
用户B 充值 → A 获得充值返佣(deposit_commission_pct%)
```

### 9.3 2FA — двухфакторная аутентификация

- Стандартный протокол TOTP (RFC 6238), совместим с Google Authenticator
- Процесс включения: получение ключа → сканирование QR → проверка TOTP → генерация 8 резервных кодов восстановления
- Вторая проверка при входе: POST /api/2fa/verify
- Поддерживается допуск ±1 временного окна (30 секунд)

### 9.4 Реальное подключение OAuth

| Провайдер | Эндпоинт токена | Эндпоинт данных пользователя |
|--------|----------|------------|
| Google | oauth2.googleapis.com/token | www.googleapis.com/oauth2/v3/userinfo |
| Facebook | graph.facebook.com/v18.0/oauth/access_token | graph.facebook.com/me |
| Apple | appleid.apple.com/auth/token | декодирование JWT id_token |

Конфигурация через PlatformConfig или переменные окружения, при сбое запроса автоматический откат в mock-режим.

### 9.5 Проверка подписи платёжных Webhook

- Stripe: проверка подписи HMAC-SHA256 (заголовок Stripe-Signature)
- PayPal: POST-запрос обратно на проверочный эндпоинт PayPal
- При не настроенном ключе проверка пропускается автоматически (режим разработки)

### 9.6 WebSocket-рейтинг в реальном времени

- Протокол: WebSocket (ws://host:8789)
- Подписка: {action: "subscribe", leaderboard_id: 123}
- Пуш: {type: "ranking_update", rankings: [...]}
- Поддерживается keep-alive через ping/pong

## 7. Дизайн интернационализации

### 7.1 Поддерживаемые языки

| Код | Название | Локальное название | Иконка |
|------|------|--------|------|
| en-US | English | English | us |
| zh-CN | Chinese (Simplified) | 简体中文 | cn |
| ja-JP | Japanese | 日本語 | jp |
| ko-KR | Korean | 한국어 | kr |

### 7.2 Управление переводами

- Переводы организованы в формате `group.key` (например, `auth.login_success`)
- Хранятся в таблице `game_translation`, кэшируются в Redis (TTL 1 час)
- API: `GET /api/language/list` для получения доступных языков, `POST /api/language/switch` для переключения языка
- Фронтенд автоматически определяет язык по заголовку `X-Language` или `Accept-Language`
- При отсутствии перевода — откат на en-US, если нет и в en-US — возврат исходного key

### 7.3 Языковые предпочтения пользователя

- При регистрации язык автоматически задаётся по `Accept-Language` браузера
- После входа можно изменить поле `language` через `PUT /api/user/profile`
- При переключении языка запись пользователя синхронно обновляется

## 8. Модель дохода платформы

| Источник дохода | Способ расчёта | Описание |
|---------|---------|------|
| Разница обмена | spread_fee за каждый обмен | взимается в обе стороны (покупка и продажа) |
| Комиссия за вывод | сумма вывода × fee_pct | реализована в стандартной версии |
| Доля от игр | доход от сторонних игр | по условиям контракта |
| Валютная разница пополнений | разница курсов фиат→платформенная | разница между курсом платформы и рыночным |
