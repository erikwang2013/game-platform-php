## 1. মুদ্রা সিস্টেম ডিজাইন

### 1.1 তিন-স্তরের মুদ্রা মডেল

```
第1层: 法币 (USD / CNY / EUR / JPY ...)
       ↕ 充值/提现（按汇率兑换）
第2层: 平台币（统一，精度 decimal(18,4)）
       ↕ 兑换（含汇率 + 平台抽成差价）
第3层: 游戏币（每种游戏独立，独立汇率）
```

### 1.2 প্ল্যাটফর্ম কয়েন

- প্ল্যাটফর্মের মধ্যে ইউনিফাইড মূল্যায়ন একক
- নির্ভুলতা: `DECIMAL(18,4)`, সর্বনিম্ন একক 0.0001
- ফিয়াট কারেন্সি টপ-আপে অর্জিত হয়, যেকোনো গেম কয়েনে বিনিময় করা যায়
- গেম কয়েনও প্ল্যাটফর্ম কয়েনে ফেরত বিনিময় করে, তারপর ফিয়াটে উত্তোলন করা যায়
- প্ল্যাটফর্ম বিনিময় স্প্রেড আয়ের উৎস হিসেবে আদায় করে

### 1.3 গেম কয়েন

- প্রতিটি গেমে একাধিক গেম কয়েন থাকতে পারে (যেমন সোনার মুদ্রা, ডায়মন্ড, পয়েন্ট)
- প্রতিটি কয়েনের প্ল্যাটফর্ম কয়েনের সাপেক্ষে আলাদা বিনিময় হার (`exchange_rate`) সেট করা যায়
- প্রতিটি কয়েনের আলাদা প্ল্যাটফর্ম কমিশন অনুপাত (`spread_pct`) সেট করা যায়
- ন্যূনতম/সর্বোচ্চ বিনিময় সীমা (`min_exchange` / `max_exchange`) সেট করা যায়

### 1.4 বিনিময় সূত্র

**গেম কয়েন বাই (প্ল্যাটফর্ম কয়েন → গেম কয়েন):**
```
游戏币到账 = 平台币数量 × exchange_rate × (1 - spread_pct / 100)
```

**গেম কয়েন সেল (গেম কয়েন → প্ল্যাটফর্ম কয়েন):**
```
平台币到账 = 游戏币数量 ÷ exchange_rate × (1 - spread_pct / 100)
```

**উদাহরণ:**
- exchange_rate = 100 (১ প্ল্যাটফর্ম কয়েন = ১০০ গেম কয়েন)
- spread_pct = 5% (প্ল্যাটফর্ম ৫% স্প্রেড নেয়)
- ব্যবহারকারী ১০ প্ল্যাটফর্ম কয়েনে বাই করে: (10 × 100 × 0.95) = 950 গেম কয়েন
- ব্যবহারকারী ৯৫০ গেম কয়েন সেল করে: (950 ÷ 100 × 0.95) = 9.025 প্ল্যাটফর্ম কয়েন
- প্ল্যাটফর্ম আয়: 10 - 9.025 = 0.975 প্ল্যাটফর্ম কয়েন

## 2. ওয়ালেট ডিজাইন

### 2.1 প্ল্যাটফর্ম কয়েন ওয়ালেট (erik_user_wallet)

ইউজার রেজিস্ট্রেশনের সময় স্বয়ংক্রিয়ভাবে তৈরি হয়, প্রাথমিক ব্যালেন্স 0।

| ফিল্ড | বিবরণ |
|------|------|
| balance | উপলব্ধ ব্যালেন্স (টপ-আপ/উত্তোলন/বিনিময় সম্ভব) |
| frozen_balance | ফ্রোজেন ব্যালেন্স (রিজার্ভ, যেমন উত্তোলন চলমান) |
| total_earned | মোট আয় |
| total_spent | মোট ব্যয় |
| version | অপটিমিস্টিক লক ভার্সন নম্বর (প্রতিটি আপডেটে +1) |

### 2.2 গেম কয়েন ওয়ালেট (erik_user_game_wallet)

ব্যবহারকারী+গেম+কয়েন তিন মাত্রায় ইউনিক। প্রথম বিনিময়ে স্বয়ংক্রিয়ভাবে তৈরি হয়।

### 2.3 কনকারেন্সি নিরাপত্তা

কনকারেন্সি সমস্যা প্রতিরোধে অপটিমিস্টিক লক ব্যবহার:

```php
// 更新时检查版本号
$updated = Wallet::where('id', $wallet->id)
    ->where('version', $wallet->version)
    ->update([
        'balance' => bcadd($wallet->balance, $amount, 4),
        'version' => $wallet->version + 1,
    ]);

// 更新失败（版本号已变）→ 重试，最多5次
```

## 3. উত্তোলন সিস্টেম ডিজাইন

### 3.1 মাল্টি-লেয়ার কন্ট্রোল

```
第1层: 全局提现开关
       ├─ 关闭 → 所有提现拒绝，用于紧急风控
       └─ 开启 → 进入第2层检查

第2层: 限额检查
       ├─ 单笔最低金额 (min_amount)
       ├─ 单笔最高金额 (max_amount)
       └─ 每日累计限额 (daily_limit)

第3层: 审核流程
       ├─ 金额 < 自动审核阈值 → 自动通过
       └─ 金额 >= 自动审核阈值 → 人工审核 → 通过/拒绝
```

### 3.2 উত্তোলন স্টেট মেশিন

```
pending (待审核)
  ├─→ approved (已通过) → completed (已完成)
  └─→ rejected (已拒绝) → 余额退回 + 退款流水
```

### 3.3 অ্যাডমিন প্যানেল কন্ট্রোল

- **গ্লোবাল সুইচ বাটন**: এক ক্লিকে সব ইউজারের উত্তোলন চালু/বন্ধ
- **রিভিউ কিউ**: সময় অনুযায়ী সাজানো অপেক্ষমাণ রিভিউ তালিকা, পাস/রিজেক্ট বাটন
- **সীমা কনফিগ**: ভিজ্যুয়ালি বিভিন্ন সীমা প্যারামিটার সেট করা

## 4. টপ-আপ ডিজাইন

### 4.1 টপ-আপ প্রক্রিয়া

```
1. 用户选择支付方式和金额
2. 平台创建充值订单 (status=pending, 生成唯一 order_no)
```

## 5. গেম ইন্টিগ্রেশন ডিজাইন

### 5.1 নিজস্ব গেম

নিজস্ব গেম সরাসরি প্ল্যাটফর্মে ইন্টিগ্রেটেড, ইউজার সিস্টেম ও ওয়ালেট শেয়ার করে:

- গেম অভ্যন্তরীণ API দিয়ে ইউজারের গেম কয়েন ব্যালেন্স কুয়েরি করে
- গেম সেটেলমেন্ট অভ্যন্তরীণ API দিয়ে গেম কয়েন ডেবিট/ক্রেডিট করে
- অতিরিক্ত সিগনেচার ভেরিফিকেশন প্রয়োজন নেই

### 5.2 থার্ড-পার্টি গেম

থার্ড-পার্টি গেম SDK/API দিয়ে সংযুক্ত:

```
平台侧:
  1. 用户点击"进入游戏"
  2. 平台生成签名（user_id + timestamp + api_secret → HMAC-SHA256）
  3. 302跳转或iframe加载游戏URL（携带签名参数）

游戏侧:
  4. 验签 → 建立游戏会话
  5. 查询余额：GET /api/game/balance?user_id=...&sign=...
  6. 结算回调：POST /api/game/callback {user_id, amount, type, sign}
  7. 平台验签 → 更新余额 → 记录流水 → 返回结果
```

### 5.3 সিগনেচার অ্যালগরিদম

```
signature = HMAC-SHA256(
    secret = api_secret,
    message = user_id + "|" + timestamp + "|" + amount + "|" + nonce,
)
```

ভেরিফিকেশন শর্ত:
- সিগনেচার সঠিক
- টাইমস্ট্যাম্প ±60s-এর মধ্যে (রিপ্লে অ্যাটাক প্রতিরোধ)
- nonce পূর্বে ব্যবহৃত হয়নি (Redis-এ রেকর্ড, 60s মেয়াদ)
- রিকোয়েস্ট IP হোয়াইটলিস্টে আছে

## ৮. স্ট্যান্ডার্ড সংস্করণে নতুন ডিজাইন

### 8.1 রিস্ক কন্ট্রোল ইঞ্জিন

চার ধরনের নিয়ম:
- `ip_blacklist` — IP ব্ল্যাকলিস্ট ম্যাচ, ম্যাচ হলেই সরাসরি ব্লক
- `amount_anomaly` — একক লেনদেন বড় অঙ্ক ডিটেকশন, থ্রেশহোল্ড ছাড়ালে সতর্কতা
- `frequency` — সময় উইন্ডোর মধ্যে অপারেশন ফ্রিকোয়েন্সি ডিটেকশন
- `velocity` — অল্প সময়ে একাধিক অ্যাকাউন্টের সম্পর্ক ডিটেকশন

নিয়ম priority অবরোহী ক্রমে চলে, প্রথম ম্যাচ হওয়া নিয়ম ফলাফল নির্ধারণ করে (block > warn > log)।

### 8.2 OAuth থার্ড-পার্টি লগইন

সমর্থিত প্রদানকারী: Google, Facebook, Apple

প্রক্রিয়া:
1. ফ্রন্টএন্ড `GET /api/auth/oauth/{provider}` দিয়ে অথোরাইজেশন URL পায়
2. ইউজার থার্ড-পার্টিতে গিয়ে অথোরাইজেশন সম্পন্ন করে
3. কলব্যাক `POST /api/auth/oauth/{provider}/callback` অথোরাইজেশন কোড সহ
4. ব্যাকএন্ড বিদ্যমান বাইন্ডিং খোঁজে → সরাসরি লগইন; বাইন্ডিং না থাকলে → অটো রেজিস্ট্রেশন+বাইন্ডিং+ওয়ালেট তৈরি

### 8.4 গেম সার্ভার/অঞ্চল

প্রতিটি গেমে একাধিক সার্ভার/অঞ্চল কনফিগ করা যায় (region: global/asia/eu/na), সার্ভার অবস্থা: রক্ষণাবেক্ষণ/সাধারণ/হট/নতুন সার্ভার।

## 9. প্রোডাকশন-লেভেল ফিচার

### 9.1 নোটিফিকেশন সিস্টেম

নোটিফিকেশন ধরন: system/deposit/withdraw/kyc/coupon/announcement

অটো ট্রিগার পরিস্থিতি:
- টপ-আপ ক্রেডিট → NotificationService::send()
- উত্তোলন রিভিউ পাস/রিজেক্ট → অটো নোটিফিকেশন
- KYC রিভিউ পাস/রিজেক্ট → অটো নোটিফিকেশন
- কুপন গ্রহণ → অটো নোটিফিকেশন
- রেফারেল বোনাস ক্রেডিট → অটো নোটিফিকেশন

ইন-অ্যাপ মেসেজ + ইমেইল দ্বৈত চ্যানেল সাপোর্ট (ইমেইলে MAIL_HOST এনভায়রনমেন্ট ভেরিয়েবল প্রয়োজন)।

### 9.2 রেফারেল কমিশন

```
用户A 生成推荐码 → 分享给用户B
用户B 注册时填写推荐码 → 双方各得注册奖励(signup_reward)
用户B 充值 → A 获得充值返佣(deposit_commission_pct%)
```

### 9.3 2FA দ্বি-ফ্যাক্টর অথেনটিকেশন

- TOTP স্ট্যান্ডার্ড প্রোটোকল (RFC 6238), Google Authenticator সামঞ্জস্যপূর্ণ
- সক্রিয়করণ প্রক্রিয়া: সিক্রেট পাওয়া → QR স্ক্যান বাইন্ডিং → TOTP ভেরিফিকেশন → ৮টি ব্যাকআপ রিকভারি কোড
- লগইন সেকেন্ডারি ভেরিফিকেশন: POST /api/2fa/verify
- ±1 টাইম উইন্ডো টলারেন্স সাপোর্ট (৩০ সেকেন্ড)

### 9.4 প্রকৃত OAuth ইন্টিগ্রেশন

| প্রদানকারী | Token এন্ডপয়েন্ট | ইউজার ইনফো এন্ডপয়েন্ট |
|--------|----------|------------|
| Google | oauth2.googleapis.com/token | www.googleapis.com/oauth2/v3/userinfo |
| Facebook | graph.facebook.com/v18.0/oauth/access_token | graph.facebook.com/me |
| Apple | appleid.apple.com/auth/token | JWT id_token ডিকোড |

কনফিগ PlatformConfig বা এনভায়রনমেন্ট ভেরিয়েবলের মাধ্যমে; রিকোয়েস্ট ব্যর্থ হলে অটো mock মোডে ফলব্যাক।

### 9.5 পেমেন্ট Webhook ভেরিফিকেশন

- Stripe: HMAC-SHA256 সিগনেচার ভেরিফিকেশন (Stripe-Signature হেডার)
- PayPal: ভেরিফিকেশন এন্ডপয়েন্টে POST করে ফিরে যায়
- সিক্রেট কনফিগ না থাকলে ভেরিফিকেশন স্কিপ (ডেভেলপমেন্ট মোড)

### 9.6 WebSocket রিয়েল-টাইম লিডারবোর্ড

- প্রোটোকল: WebSocket (ws://host:8789)
- সাবস্ক্রাইব: {action: "subscribe", leaderboard_id: 123}
- পুশ: {type: "ranking_update", rankings: [...]}
- ping/pong হার্টবিট কিপ-অ্যালাইভ সাপোর্ট

## 7. ইন্টারন্যাশনালাইজেশন ডিজাইন

### 7.1 সমর্থিত ভাষা

| কোড | নাম | স্থানীয় ভাষা | আইকন |
|------|------|--------|------|
| en-US | English | English | us |
| zh-CN | Chinese (Simplified) | 简体中文 | cn |
| ja-JP | Japanese | 日本語 | jp |
| ko-KR | Korean | 한국어 | kr |

### 7.2 অনুবাদ ম্যানেজমেন্ট

- অনুবাদ `group.key` ফরম্যাটে সংগঠিত (যেমন `auth.login_success`)
- ডেটাবেস টেবিল `erik_translation`-এ সংরক্ষিত, Redis ক্যাশ (TTL ১ ঘণ্টা)
- API: `GET /api/language/list` উপলব্ধ ভাষা পায়, `POST /api/language/switch` ভাষা পরিবর্তন করে
- ফ্রন্টএন্ড `X-Language` রিকোয়েস্ট হেডার বা `Accept-Language` দিয়ে অটো ডিটেক্ট করে
- অনুবাদ না থাকলে en-US-এ ফলব্যাক, en-US-ও না থাকলে মূল key রিটার্ন

### 7.3 ইউজার ভাষা পছন্দ

- রেজিস্ট্রেশনের সময় ব্রাউজারের `Accept-Language` অনুযায়ী অটো সেট
- লগইনের পর `PUT /api/user/profile` দিয়ে `language` ফিল্ড পরিবর্তন করা যায়
- ভাষা পরিবর্তনে ইউজার রেকর্ড সিঙ্ক আপডেট
