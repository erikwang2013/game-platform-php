## 1. मुद्रा प्रणाली डिज़ाइन

### 1.1 तीन-परत मुद्रा मॉडल

```
परत 1: फ़िएट मुद्रा (USD / CNY / EUR / JPY ...)
       ↕ रिचार्ज/निकासी (विनिमय दर के अनुसार)
परत 2: प्लेटफ़ॉर्म कॉइन (एकीकृत, सटीकता decimal(18,4))
       ↕ विनिमय (विनिमय दर + प्लेटफ़ॉर्म कमीशन अंतर सहित)
परत 3: गेम कॉइन (प्रत्येक गेम के लिए स्वतंत्र, स्वतंत्र विनिमय दर)
```

### 1.2 प्लेटफ़ॉर्म कॉइन

- प्लेटफ़ॉर्म के भीतर एकीकृत मूल्य निर्धारण इकाई
- सटीकता: `DECIMAL(18,4)`, न्यूनतम इकाई 0.0001
- फ़िएट मुद्रा रिचार्ज से प्राप्त होता है, किसी भी गेम कॉइन में बदला जा सकता है
- गेम कॉइन भी वापस प्लेटफ़ॉर्म कॉइन में बदल सकता है, फिर फ़िएट में निकाला जा सकता है
- प्लेटफ़ॉर्म विनिमय अंतर को आय स्रोत के रूप में वसूलता है

### 1.3 गेम कॉइन

- प्रत्येक गेम में कई गेम मुद्राएँ हो सकती हैं (जैसे सोने के सिक्के, हीरे, अंक)
- प्रत्येक मुद्रा स्वतंत्र रूप से प्लेटफ़ॉर्म कॉइन के साथ विनिमय दर (`exchange_rate`) निर्धारित करती है
- प्रत्येक मुद्रा स्वतंत्र रूप से प्लेटफ़ॉर्म कमीशन प्रतिशत (`spread_pct`) निर्धारित करती है
- न्यूनतम/अधिकतम विनिमय सीमाएँ (`min_exchange` / `max_exchange`) सेट करने का समर्थन

### 1.4 विनिमय सूत्र

**गेम कॉइन खरीदना (प्लेटफ़ॉर्म कॉइन → गेम कॉइन):**
```
गेम कॉइन जमा = प्लेटफ़ॉर्म कॉइन संख्या × exchange_rate × (1 - spread_pct / 100)
```

**गेम कॉइन बेचना (गेम कॉइन → प्लेटफ़ॉर्म कॉइन):**
```
प्लेटफ़ॉर्म कॉइन जमा = गेम कॉइन संख्या ÷ exchange_rate × (1 - spread_pct / 100)
```

**उदाहरण:**
- exchange_rate = 100 (1 प्लेटफ़ॉर्म कॉइन = 100 गेम कॉइन)
- spread_pct = 5% (प्लेटफ़ॉर्म 5% अंतर वसूलता है)
- उपयोगकर्ता 10 प्लेटफ़ॉर्म कॉइन से खरीदता है: (10 × 100 × 0.95) = 950 गेम कॉइन
- उपयोगकर्ता 950 गेम कॉइन बेचता है: (950 ÷ 100 × 0.95) = 9.025 प्लेटफ़ॉर्म कॉइन
- प्लेटफ़ॉर्म आय: 10 - 9.025 = 0.975 प्लेटफ़ॉर्म कॉइन

## 2. वॉलेट डिज़ाइन

### 2.1 प्लेटफ़ॉर्म कॉइन वॉलेट (erik_user_wallet)

उपयोगकर्ता पंजीकरण पर स्वचालित रूप से बनता है, प्रारंभिक शेष 0।

| फ़ील्ड | विवरण |
|------|------|
| balance | उपलब्ध शेष (रिचार्ज/निकासी/विनिमय योग्य) |
| frozen_balance | जमा शेष (आरक्षित, जैसे निकासी प्रक्रिया में) |
| total_earned | संचयी आय |
| total_spent | संचयी व्यय |
| version | ऑप्टिमिस्टिक लॉक संस्करण संख्या (प्रत्येक अपडेट पर +1) |

### 2.2 गेम कॉइन वॉलेट (erik_user_game_wallet)

उपयोगकर्ता + गेम + मुद्रा तीन आयामों में अद्वितीय। पहले विनिमय पर स्वचालित रूप से बनता है।

### 2.3 समवर्ती सुरक्षा

समवर्ती समस्याओं को रोकने के लिए ऑप्टिमिस्टिक लॉक:

```php
// अपडेट करते समय संस्करण संख्या जाँचें
$updated = Wallet::where('id', $wallet->id)
    ->where('version', $wallet->version)
    ->update([
        'balance' => bcadd($wallet->balance, $amount, 4),
        'version' => $wallet->version + 1,
    ]);

// अपडेट विफल (संस्करण बदल चुका) → पुनः प्रयास, अधिकतम 5 बार
```

## 3. निकासी प्रणाली डिज़ाइन

### 3.1 बहु-परत नियंत्रण

```
परत 1: वैश्विक निकासी स्विच
       ├─ बंद → सभी निकासी अस्वीकार, आपातकालीन जोखिम नियंत्रण के लिए
       └─ चालू → परत 2 जाँच में प्रवेश

परत 2: सीमा जाँच
       ├─ एकल लेनदेन न्यूनतम राशि (min_amount)
       ├─ एकल लेनदेन अधिकतम राशि (max_amount)
       └─ दैनिक संचयी सीमा (daily_limit)

परत 3: समीक्षा प्रक्रिया
       ├─ राशि < स्वचालित समीक्षा सीमा → स्वचालित स्वीकृति
       └─ राशि >= स्वचालित समीक्षा सीमा → मैन्युअल समीक्षा → स्वीकृति/अस्वीकृति
```

### 3.2 निकासी स्थिति मशीन

```
pending (समीक्षा लंबित)
  ├─→ approved (स्वीकृत) → completed (पूर्ण)
  └─→ rejected (अस्वीकृत) → शेष वापस + रिफंड लेनदेन
```

### 3.3 प्रशासन कंसोल नियंत्रण

- **वैश्विक स्विच बटन**: एक क्लिक से सभी उपयोगकर्ताओं की निकासी चालू/बंद
- **समीक्षा कतार**: समय के अनुसार क्रमबद्ध लंबित सूची, स्वीकृति/अस्वीकृति बटन
- **सीमा कॉन्फ़िग**: प्रत्येक सीमा पैरामीटर दृश्य रूप से सेट करें

## 4. रिचार्ज डिज़ाइन

### 4.1 रिचार्ज प्रक्रिया

```
1. उपयोगकर्ता भुगतान विधि और राशि चुनता है
2. प्लेटफ़ॉर्म रिचार्ज ऑर्डर बनाता है (status=pending, अद्वितीय order_no उत्पन्न)
3. तृतीय-पक्ष भुगतान पृष्ठ पर जाएं
4. उपयोगकर्ता भुगतान पूरा करता है
5. तृतीय-पक्ष कॉलबैक प्लेटफ़ॉर्म को सूचित करता है (POST /api/payment/callback)
6. प्लेटफ़ॉर्म हस्ताक्षर सत्यापन → ऑर्डर अपडेट (status=confirmed)
7. प्लेटफ़ॉर्म कॉइन जमा → लेनदेन रिकॉर्ड
```

### 4.2 भुगतान विधियाँ

| प्रकार | प्रदाता | विवरण |
|------|--------|------|
| फ़िएट | Stripe | अंतर्राष्ट्रीय क्रेडिट कार्ड भुगतान |
| फ़िएट | PayPal | वैश्विक इलेक्ट्रॉनिक वॉलेट |
| फ़िएट | Alipay | अलीपे (मुख्य भूमि चीन) |
| फ़िएट | WeChat Pay | वीचैट भुगतान (मुख्य भूमि चीन) |
| क्रिप्टोकरेंसी | USDT-TRC20 | ट्रॉन चेन USDT |

मूल संस्करण पहले एकल भुगतान विधि (जैसे Stripe) से जोड़ता है, मानक संस्करण सभी चैनलों का विस्तार करता है।

## 5. गेम एकीकरण डिज़ाइन

### 5.1 स्वयं विकसित गेम

स्वयं विकसित गेम सीधे प्लेटफ़ॉर्म में एकीकृत होते हैं, उपयोगकर्ता प्रणाली और वॉलेट साझा करते हैं:

- गेम आंतरिक API के माध्यम से उपयोगकर्ता के गेम कॉइन शेष क्वेरी करता है
- गेम निपटान आंतरिक API के माध्यम से गेम कॉइन घटाता/बढ़ाता है
- अतिरिक्त हस्ताक्षर सत्यापन की आवश्यकता नहीं

### 5.2 तृतीय-पक्ष गेम

तृतीय-पक्ष गेम SDK/API के माध्यम से जुड़ते हैं:

```
प्लेटफ़ॉर्म पक्ष:
  1. उपयोगकर्ता "गेम में प्रवेश" क्लिक करता है
  2. प्लेटफ़ॉर्म हस्ताक्षर उत्पन्न करता है (user_id + timestamp + api_secret → HMAC-SHA256)
  3. 302 रीडायरेक्ट या iframe में गेम URL लोड (हस्ताक्षर पैरामीटर सहित)

गेम पक्ष:
  4. हस्ताक्षर सत्यापन → गेम सत्र स्थापित
  5. शेष क्वेरी: GET /api/game/balance?user_id=...&sign=...
  6. निपटान कॉलबैक: POST /api/game/callback {user_id, amount, type, sign}
  7. प्लेटफ़ॉर्म हस्ताक्षर सत्यापन → शेष अपडेट → लेनदेन रिकॉर्ड → परिणाम लौटाएं
```

### 5.3 हस्ताक्षर एल्गोरिदम

```
signature = HMAC-SHA256(
    secret = api_secret,
    message = user_id + "|" + timestamp + "|" + amount + "|" + nonce,
)
```

सत्यापन शर्तें:
- हस्ताक्षर सही
- टाइमस्टैम्प ±60s के भीतर (replay attack सुरक्षा)
- nonce पहले उपयोग नहीं हुआ (Redis में रिकॉर्ड, 60s समाप्ति)
- अनुरोध IP श्वेतसूची में है

## 呼. मानक संस्करण नए डिज़ाइन

### 8.1 जोखिम नियंत्रण इंजन

चार नियम प्रकार:
- `ip_blacklist` — IP ब्लैकलिस्ट मिलान, हिट पर सीधे अवरोधन
- `amount_anomaly` — एकल लेनदेन बड़ी राशि पहचान, सीमा पार करने पर चेतावनी
- `frequency` — समय विंडो में संचालन आवृत्ति पहचान
- `velocity` — अल्प समय में बहु-खाता संबंध पहचान

नियम priority के अवरोही क्रम में निष्पादित होते हैं, पहला मिलान नियम परिणाम निर्धारित करता है (block > warn > log)।

### 8.2 OAuth तृतीय-पक्ष लॉगिन

समर्थित प्रदाता: Google, Facebook, Apple

प्रक्रिया:
1. फ्रंटएंड `GET /api/auth/oauth/{provider}` से प्राधिकरण URL प्राप्त करता है
2. उपयोगकर्ता तृतीय-पक्ष पर प्राधिकरण पूरा करता है
3. कॉलबैक `POST /api/auth/oauth/{provider}/callback` प्राधिकरण कोड सहित
4. बैकएंड मौजूदा बाइंडिंग ढूँढता है → सीधे लॉगिन; कोई बाइंडिंग नहीं → स्वचालित पंजीकरण + बाइंडिंग + वॉलेट निर्माण

### 8.3 KYC सीमा प्रणाली

| स्तर | प्राप्ति विधि | एकल लेनदेन सीमा | दैनिक सीमा | शुल्क |
|------|---------|---------|--------|--------|
| default | पंजीकरण डिफ़ॉल्ट | 1,000 | 10,000 | 1.00% |
| verified | KYC समीक्षा स्वीकृत | 5,000 | 50,000 | 0.50% |
| vip | संचालन द्वारा प्रदान | 20,000 | 200,000 | 0.00% |

### 8.4 गेम क्षेत्र/सर्वर

प्रत्येक गेम में कई क्षेत्र/सर्वर कॉन्फ़िगर किए जा सकते हैं (region: global/asia/eu/na), क्षेत्र स्थितियाँ: रखरखाव/सामान्य/व्यस्त/नया।

### 8.5 दैनिक सांख्यिकी स्नैपशॉट

प्रतिदिन सुबह crontab `ComputeDailyStats::run()` निष्पादित करता है, पाँच मीट्रिक्स की गणना:
- उपयोगकर्ता सांख्यिकी (नए/सक्रिय/संचयी)
- रिचार्ज सांख्यिकी (संख्या/कुल राशि)
- निकासी सांख्यिकी (संख्या/कुल राशि)
- विनिमय सांख्यिकी (संख्या/कुल शुल्क)
- गेम सांख्यिकी (खिलाड़ी संख्या/सत्र संख्या)

## 9. उत्पादन-स्तरीय सुविधाएँ

### 9.1 अधिसूचना प्रणाली

अधिसूचना प्रकार: system/deposit/withdraw/kyc/coupon/announcement

स्वचालित ट्रिगर परिदृश्य:
- रिचार्ज जमा → NotificationService::send()
- निकासी समीक्षा स्वीकृति/अस्वीकृति → स्वचालित अधिसूचना
- KYC समीक्षा स्वीकृति/अस्वीकृति → स्वचालित अधिसूचना
- कूपन प्राप्ति → स्वचालित अधिसूचना
- रेफरल पुरस्कार जमा → स्वचालित अधिसूचना

साइट-आंतरिक संदेश + ईमेल दोहरा चैनल समर्थित (ईमेल के लिए MAIL_HOST पर्यावरण चर कॉन्फ़िगर करना आवश्यक)।

### 9.2 रेफरल कमीशन

```
उपयोगकर्ता A रेफरल कोड उत्पन्न करता है → उपयोगकर्ता B को साझा करता है
उपयोगकर्ता B पंजीकरण पर रेफरल कोड भरता है → दोनों को पंजीकरण पुरस्कार (signup_reward) मिलता है
उपयोगकर्ता B रिचार्ज करता है → A को रिचार्ज कमीशन (deposit_commission_pct%) मिलता है
```

### 9.3 2FA दो-कारक प्रमाणीकरण

- TOTP मानक प्रोटोकॉल (RFC 6238), Google Authenticator के साथ संगत
- सक्षम प्रक्रिया: कुंजी प्राप्त करें → QR स्कैन बाइंडिंग → TOTP सत्यापन → 8 बैकअप रिकवरी कोड उत्पन्न
- लॉगिन दोहरा सत्यापन: POST /api/2fa/verify
- ±1 समय विंडो सहनशीलता समर्थित (30 सेकंड)

| Google | oauth2.googleapis.com/token | www.googleapis.com/oauth2/v3/userinfo |
| Facebook | graph.facebook.com/v18.0/oauth/access_token | graph.facebook.com/me |
| Apple | appleid.apple.com/auth/token | JWT id_token डिकोड |

कॉन्फ़िग PlatformConfig या पर्यावरण चरों के माध्यम से, अनुरोध विफलता पर स्वचालित रूप से mock मोड में रोलबैक।

### 9.5 भुगतान Webhook हस्ताक्षर सत्यापन

- Stripe: HMAC-SHA256 हस्ताक्षर सत्यापन (Stripe-Signature हेडर)
- PayPal: सत्यापन एंडपॉइंट पर POST री-वेरिफिकेशन
- कुंजी कॉन्फ़िगर न होने पर स्वचालित रूप से सत्यापन छोड़ें (विकास मोड)

### 9.6 WebSocket वास्तविक समय लीडरबोर्ड

- प्रोटोकॉल: WebSocket (ws://host:8789)
- सदस्यता: {action: "subscribe", leaderboard_id: 123}
- पुश: {type: "ranking_update", rankings: [...]}
- ping/pong हार्टबीट जीवनरक्षा समर्थित

## 7. अंतर्राष्ट्रीयकरण डिज़ाइन

### 7.1 समर्थित भाषाएँ

### 7.2 अनुवाद प्रबंधन

- अनुवाद `group.key` प्रारूप में व्यवस्थित (जैसे `auth.login_success`)
- डेटाबेस तालिका `erik_translation` में संग्रहीत, Redis कैश (TTL 1 घंटा)
- API: `GET /api/language/list` उपलब्ध भाषाएँ प्राप्त करता है, `POST /api/language/switch` भाषा बदलता है
- फ्रंटएंड `X-Language` अनुरोध हेडर या `Accept-Language` से स्वचालित पहचान
- अनुवाद अनुपलब्ध होने पर en-US में रोलबैक, en-US में भी न हो तो मूल key लौटाएं

### 7.3 उपयोगकर्ता भाषा प्राथमिकता

- पंजीकरण पर ब्राउज़र `Accept-Language` के अनुसार स्वचालित रूप से सेट होती है
- लॉगिन के बाद `PUT /api/user/profile` से `language` फ़ील्ड संशोधित किया जा सकता है
- भाषा बदलते समय उपयोगकर्ता रिकॉर्ड समकालिक रूप से अपडेट होता है
